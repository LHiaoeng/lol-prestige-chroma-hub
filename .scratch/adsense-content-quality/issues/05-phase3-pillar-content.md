# 阶段三：构建双语支柱内容体系

> 本地实施规格：按用户指示发布于仓库本地 Issue 目录。

**Status:** ready-for-agent

## Problem Statement

站点已经完成索引边界、广告范围与编辑可信度整改，也已有六篇双语常青指南，但围绕臻彩核心搜索意图的内容深度仍然不足。现有璀璨臻彩召唤文章主要服务单期活动查询，读者缺少一篇不依赖某一期活动、能够完整解释玩法、成本、奖池、概率、领取与历史变化的长期参考内容。若直接批量扩展支柱页，又容易复制模板、重复目录字段或产出缺乏独立价值的页面，无法可靠改善 AdSense 所关注的内容质量。

## Solution

先发布中英双语的“璀璨臻彩召唤完全指南”，用真实的第一方资料与既有活动数据验证一套可复用但不制造同质内容的支柱页标准。指南应把跨期稳定规则与单期可变信息分开，解释完整用户旅程，并连接相关活动文章、臻彩图鉴和基础指南。模板经发布构建验证后，再用同一质量门槛生产已经批准的后续支柱选题；每个页面都必须回答不同的核心问题、具备独立叙事与第一方证据。全部支柱内容上线后进入约 90 天的收录观察期，待 Google Search Console 显示相关页面已收录，再由人工决定并提交 AdSense 复审。

## User Stories

1. 作为第一次接触璀璨臻彩召唤的国服玩家，我希望先理解活动的定位与适用范围，以便判断这项玩法是否与我有关。
2. 作为准备参与召唤的玩家，我希望看到从进入活动、绑定大区、选择奖池、召唤到领取奖励的完整流程，以便避免遗漏关键步骤。
3. 作为控制预算的玩家，我希望理解各次召唤的计价方式和完整一轮的成本构成，以便在付费前做出知情决定。
4. 作为比较奖池的玩家，我希望理解不同奖励层级、自选项与随机项的区别，以便选择符合收藏目标的奖池。
5. 作为关注概率的玩家，我希望理解不放回抽取以及剩余奖项概率变化的含义，以便正确阅读官方概率而不被误导。
6. 作为已有部分奖励的玩家，我希望了解重复内容、已抽取内容和奖池锁定规则，以便预估后续召唤的实际价值。
7. 作为跨大区玩家，我希望明确账号、游戏大区绑定与领奖限制，以便避免把奖励发往错误的大区。
8. 作为限时活动参与者，我希望知道活动开放、支付、召唤和领奖期限应以哪项官方信息为准，以便不错过截止时间。
9. 作为臻彩收藏者，我希望从完全指南进入对应臻彩图鉴和单期活动记录，以便核对原画、基础皮肤与历史获取渠道。
10. 作为只想查询当前一期活动的读者，我希望完全指南能把我引向最新的单期文章，以便快速查看当期奖池、日期、价格和主推奖励。
11. 作为研究往期活动的读者，我希望看到可核验的历史场次入口，以便比较规则、奖池与成本如何变化。
12. 作为非中国大陆服玩家，我希望清楚看到 China Server、Global Server、Server Region 与 LPL 电竞赛区的区别，以便不把国服活动误认为全球服活动。
13. 作为英文读者，我希望英文指南准确解释中国大陆服专有概念，而不是生硬直译中文营销用语，以便理解活动的真实语境。
14. 作为中文读者，我希望文章使用“臻彩”“璀璨臻彩召唤”等项目既定术语，以便与国服官方页面和站内其他内容保持一致。
15. 作为谨慎消费的玩家，我希望页面区分官方事实、基于历史场次的归纳和编辑建议，以便判断每类信息的可信程度。
16. 作为核验内容的读者，我希望看到第一方来源、最后核验日期、编辑团队署名与纠错入口，以便复查规则并报告过期信息。
17. 作为使用手机阅读的玩家，我希望长篇指南的目录、表格、图片和链接在窄屏下仍然易读易操作，以便在活动期间随时查阅。
18. 作为使用辅助技术的读者，我希望标题层级、链接文字、表格语义和图片替代文本清晰，以便完整理解指南。
19. 作为从搜索引擎进入站点的访客，我希望落地页直接回答搜索问题并提供原创解释，以便无需拼凑多个单期公告。
20. 作为持续阅读站点内容的访客，我希望每篇支柱页都有相关基础指南、图鉴或活动文章入口，以便沿主题继续探索。
21. 作为站点编辑，我希望先用一篇完全指南验证支柱页标准，以便在扩大产量前发现内容结构与维护方式的问题。
22. 作为站点编辑，我希望后续支柱选题各自服务不同的核心搜索意图，以便避免批量生成重复或低价值页面。
23. 作为站点维护者，我希望可变的活动数据与长期解释保持清晰边界，以便更新新一期信息时不必重写整篇支柱内容。
24. 作为站点维护者，我希望构建过程能发现缺失的双语路由、元数据、来源、署名或站内关系，以便阻止不完整页面发布。
25. 作为广告审核方，我希望看到成体系、可核验且具有独立阅读价值的原创内容，以便判断站点不是由大量薄弱目录页构成。
26. 作为复审负责人，我希望记录首批支柱内容的上线日期和 Search Console 收录状态，以便在约 90 天观察期后有依据地提交复审。

## Implementation Decisions

- 第一篇模板支柱内容固定为中英双语“璀璨臻彩召唤完全指南”，它是长期解释页，不替代任何单期活动新闻。
- 完全指南覆盖活动定位、适用服务器、参与前提、点券或活动积分关系、奖池与奖励层级、自选机制、召唤顺序与成本、不放回概率、大区绑定、领奖、有效期、历史场次、消费提醒和常见问题。
- 跨期稳定规则写入完全指南；日期、主推奖励、具体奖池、当期概率和价格等可变信息保留在单期活动文章中。完全指南只展示有来源支持的示例或历史归纳，并明确其时效性。
- 中英文版本服务同一信息需求并保持事实一致，但允许针对读者背景调整解释，不采用逐句机械翻译。
- 英文统一使用 `Brilliant Prestige Chroma Summoning`、`China Server`、`Global Server`、`Server Region` 和 `Prestige Chroma`；中文使用“璀璨臻彩召唤”“国服”“游戏大区”和“臻彩”。游戏服务器、大区与 LPL 电竞赛区不得混用。
- 页面只陈述第一方来源可以支持的事实。对多个历史场次的总结必须标明这是编辑归纳，不得把过去规则承诺为未来固定规则。
- 支柱页沿用现有博客的统一元数据、团队署名、来源、最后核验日期、纠错入口、相关文章和广告资格机制，不另建平行内容系统。
- 完全指南与最新单期文章、往期场次、臻彩基础指南及相关图鉴建立双向、语义明确的站内链接，避免孤立页面和仅为 SEO 设置的链接堆叠。
- 结构化数据与页面可见内容保持一致；文章、面包屑与 FAQ 仅在页面确实呈现对应内容时输出。
- 图片必须帮助解释流程、奖池或历史内容，提供有意义的替代文本；不得为了拉长页面而堆叠宣传素材。
- 长表格在移动端可以横向查看或转化为等价的窄屏结构，但不得隐藏概率、成本或限制条件。
- “内容深度”由完整回答用户任务、原创解释、可核验来源和主题独立性判断，不设置机械字数目标。
- 模板验收后，后续支柱页只从已经批准的选题清单生产。每个选题必须先声明独立的核心问题、目标读者、第一方来源与现有内容差异；不满足条件的选题不得进入批量生产。
- 后续支柱页复用的是质量契约、维护元数据和可访问布局，不复用整段正文或固定标题骨架。批量生产不得成为程序化生成薄内容的入口。
- 支柱页发布属于代码与内容交付；Google Search Console 检查、等待约 90 天和提交 AdSense 复审由人工执行并记录。
- 阶段三完成的技术门槛是全部批准的支柱页通过发布构建；业务复审门槛是首批页面上线约 90 天且 Search Console 显示相关页面已收录。

## Testing Decisions

- 使用一个最高层测试缝：发布构建后的静态产物审计。它验证读者、搜索引擎和广告审核方实际获得的 HTML，不绑定 Astro 组件或页面内部实现。
- 对每篇已批准支柱内容，审计确认中英文规范路由均已生成、页面可索引、canonical 与语言替代关系正确、博客列表可发现该文章，并且 sitemap 包含应收录的 URL。
- 审计确认最终页面存在标题层级、摘要、编辑团队署名、最后核验日期、第一方来源、纠错入口、至少必要的站内关联和与可见内容一致的结构化数据。
- 审计确认支柱页遵循既有博客广告边界，且不会改变图鉴详情页的 `noindex` 与无广告规则。
- 审计确认双语页面没有占位文案、空白成功页面、断开的内部链接或缺失的图片替代文本；移动端表格和长内容沿用既有响应式与无障碍约束。
- 既有静态站构建测试、SEO sitemap 测试、博客元数据测试和产物广告审计是本功能的测试先例。必要的新断言应并入这些高层测试，而不是为文案内部结构新增低层重复测试。
- 自动化测试不判断文章是否“足够原创”或官方事实是否仍然有效；这些由编辑审阅来源、区分事实与归纳并核对中英文事实一致性来验收。
- 完整验收命令为 `pnpm release:build`，一次覆盖测试、类型检查、数据校验、站点构建与最终产物审计。
- Google Search Console 的“已收录”状态和约 90 天观察期属于发布后的人工验收证据，不伪装成自动化测试结果。

## Out of Scope

- 重新实现阶段一已完成的 About 页面、团队署名、编辑原则、来源说明、纠错机制、首页导览或旧编辑政策路由合并。
- 重新处理图鉴详情页的索引与广告边界。
- 把现有六篇常青指南改写为本阶段的新增数量，除非某篇需要为新支柱内容补充真实的上下文链接。
- 将单期璀璨臻彩召唤文章合并进完全指南，或停止继续发布新的单期活动文章。
- 为了达到固定篇数、字数或发布日期而发布来源不足、主题重复或由模板批量填充的页面。
- 自动部署、自动请求 Google 抓取、自动查询或操纵收录状态、自动提交 AdSense 复审。
- 承诺 Google 收录时点、AdSense 审核结果或广告收益。
- 更改图鉴数据契约、Cloudflare 部署流程、生产域名或广告投放范围。

## Further Notes

- 阶段一已于 2026-09-15 完成，类型检查为 0 errors、0 warnings，测试为 179/179 通过；这些结果是阶段三的实施基线，不代表阶段三已经验收。
- 当前已有六篇中英双语常青指南，并具备统一的维护信息。阶段三的价值在于建立更深的主题支柱与内容集群，而不是重复计算或包装这六篇文章。
- “璀璨臻彩召唤完全指南”应先单独上线并接受人工内容审阅。模板验证通过后，才扩展已批准的后续选题。
- 发布时记录首批支柱页面的实际生产上线日期。约 90 天从该日期计算，而不是从规格、开发或合并日期计算。
- 观察期结束前，在 Google Search Console 中逐页确认支柱内容显示“已收录”，并保留检查日期与结果。只有技术构建和人工收录前置条件都满足后，才提交 AdSense 复审。
