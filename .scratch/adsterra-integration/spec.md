# 规格：默认广告展示与 Adsterra / AdSense 切换

## 问题与目标

AdSense 再次以低价值内容拒绝站点，当前先使用 Adsterra 快速接通广告，同时保留 AdSense 以供后续继续申请和切换。新页面默认具备广告展示能力，通过一个全站开关选择广告平台，任一页面只投放一种平台的广告。本站商业目标是尝试广告收入，本次开发交付仅验证真实广告能否正常展示；广告平台后台记录、收益及实际到账由用户自行查看，不属于本次验收条件。不将切换广告平台视为已解决 AdSense 内容审核问题。

产品选择已于 2026-11-17 确认，本文按用户修订定稿。广告代码及审查修复已在本地实现；真实广告素材展示尚未验证，部署按独立授权执行。

## 已确认的要求与输入

- 首期平台为 Adsterra；账号已注册。
- Adsterra 与 AdSense 的集成同时保留，通过全站统一开关互斥投放，初始选择 Adsterra。
- 后续新增页面默认展示所选平台的广告，无需逐页声明开启；特殊页面显式排除。
- 用户确认中英文臻彩、英雄、皮肤、皮肤系列和皮肤宇宙详情均可投放广告。
- 已提供一个 300×250、`iframe` 格式的 Banner 广告单元。公开广告位 key 为 `77357bee0c4371d3773095ac4d08de0b`，脚本地址为 `https://bauval.org/22/77357bee0c4371d3773095ac4d08de0b`，`params` 为空对象。
- 对话中转义的反斜线和 HTML 空格实体不属于实际接入代码，实施时还原为有效脚本。
- 用户先要求出规格，随后授权审查修复、提交和推送；不因这些授权自动执行手动部署。
- 用户明确要求默认展示广告，不增加接受、拒绝、广告设置或其他额外交互。
- 用户明确要求验收仅看广告正常展示，后台统计和实际到账由用户自行查看；隐私政策按指定参考文章的第三方服务披露建议调整。
- 不索取账号密码、验证码、付款凭据或 API token。

## 代码现状与约束

- Astro 静态构建，部署至 Cloudflare Workers Static Assets；本次不引入服务端、数据库、广告统计 API 或新依赖。
- `src/components/AdSlot.astro` 当前仅输出空的 `data-ad-boundary` 容器；`src/layouts/BaseLayout.astro` 根据显式 `adPlacement` 在正文后渲染它，并在 head 加载 AdSense 脚本。
- 当前广告范围覆盖首页及显式标记的博客列表和文章；`src/domain/ad-policy.ts`、`scripts/audit-build.ts`、相关测试和 README 仍限制详情页广告，实施时需改为默认开启、显式排除，不能保留要求新路由逐个登记的允许名单。
- 当前仅发现 AdSense 发布商脚本及公开 client ID `ca-pub-1090619659930920`，`AdSlot` 中没有真实广告单元代码或 `data-ad-slot`。保留这一身份与后续接入能力，不编造广告单元 ID，也不把保留脚本视为已通过审核或能展示真实 AdSense 广告。
- 详情页包括静态臻彩详情与英雄、皮肤、皮肤系列、皮肤宇宙的运行时详情壳；后者存在加载、错误、无效参数和缺失实体状态，不能把空壳当成成功内容。
- 隐私页承诺在适用地区先提供广告同意选择，当前尚无对应广告同意机制。全站 Google 访问衡量独立存在，不应将广告开关描述为关闭全部跟踪。
- 原 ADR 0001 排除臻彩详情广告，与用户新要求冲突；本次规格同步修订该文档，保留内容类型区分。代码和 README 等消费者在实施阶段同步。
- 已有导航、图标、详情和样式的未提交改动必须保留。实施时仅编辑广告相关部分。

## 用户故事

- 作为站长，我希望真实访客能够看到一个克制的 Banner，后台记录和实际到账由我自行查看。
- 作为访客，我希望广告不遮挡原画、操作和正文，广告失败或被拦截时仍可正常浏览。
- 作为访客，我希望通过清晰的广告标识区分广告与站点内容，无需额外点击即可继续浏览。
- 作为站长，我希望出现异常广告行为时能停用投放。
- 作为站长，我希望新增普通页面自动带上广告，并通过一个统一开关在 Adsterra、AdSense 和关闭广告之间切换。

## 已确认的产品决策

### Q1：默认开启与显式排除

中英文首页、博客列表和文章、臻彩详情以及英雄、皮肤、皮肤系列和皮肤宇宙详情投放广告。后续新增页面通过共享布局默认启用，无需传入开启参数、注册广告路由或修改审核脚本的允许名单；忘记填写 `adPlacement` 不应导致新页面没有广告。

既有排除范围维持不变：当前其他目录页、PBE 新增页、About、Privacy、Editorial Policy 和错误页显式关闭广告。它们是既有页面的例外，不构成“所有未来目录页都关闭”的规则；以后新增的说明页或错误页若需要免广告，也必须显式关闭。

运行时详情仅在主资料成功加载并确有实体时允许广告，首次加载失败或无实体时不请求广告。`noindex` 不等于免广告，不能用索引状态代替页面投放设置。

状态：按用户新增页面默认展示的修订确认。

### Q2：广告位置与数量

所有可投放页面每页最多一个广告位，置于主内容后、页脚前。首期 Adsterra 使用已提供的 300×250 Banner；AdSense 后续使用其有效广告单元配置消费同一位置，不增加第二个区域。预留尺寸、居中显示、中英文广告标识；320 CSS px 不产生页面级横向溢出。不做正文插入、浮动、吸底、轮播或自动刷新。

状态：已确认。运行时详情的内部资料切换不重复初始化同一个广告。

### Q3：默认展示，无额外交互

可投放的静态页面默认加载广告；运行时详情在真实主资料首次成功后加载广告。不等待接受操作，不新增同意条、拒绝按钮、广告设置入口、偏好存储、地域判断或 CMP，不用弹窗或遮罩打断浏览。

状态：用户明确选择默认展示，取代初稿中的同意交互建议。

隐私页按下方“隐私政策调整”执行，不再承诺本站存在尚未实现的同意提示。现有 Google 访问衡量保持原状，广告开关不代表全站跟踪开关。

### Q4：仅以正常展示验收

仅以广告能否正常展示作为本次功能验收条件。不登录、读取、抓取或追踪 Adsterra 后台展示统计、收入、付款状态及实际到账，也不等待后台入账或达到付款门槛。上述记录由用户自行查看，不作为开发交付阻塞项。

状态：按用户最终修订确认。不承诺收入金额或到账时间。

### Q5：一个全站平台开关，互斥投放

使用单一构建期配置 `AD_PROVIDER`，取值仅为 `adsterra`、`adsense` 或 `none`，初始值为 `adsterra`。不使用两个可以同时开启的布尔开关，不提供访客切换控件或运行时远程配置。非法值必须报错，不能默默回退。

- `adsterra`：仅加载 Adsterra 投放代码，不加载 AdSense 投放脚本或初始化广告。
- `adsense`：仅加载 AdSense 投放代码，不加载 Adsterra 脚本或初始化广告。
- `none`：所有页面停止投放，不输出广告容器、广告平台请求或初始化；与广告无关的 Google 访问衡量保持不变。

页面显式关闭广告时优先于平台选择；运行时详情还须满足内容就绪条件。不因无填充、拦截或请求失败自动切换另一平台。开关变更须重新构建并部署后生效。

保留已有 AdSense 发布商身份与申请用途的配置，不将 AdSense 从项目删除；申请验证标记与实际投放代码区分，不因停用投放擅自删除已有验证标记。正式切到 AdSense 前需具备平台要求的有效投放配置；缺少必要配置时明确报错，不能假称已展示或改为混投。当前尚未获批或尚无真实广告单元不阻塞首期 Adsterra 展示验收；AdSense 实际展示待其具备投放条件后单独验证。

状态：按用户要求保留两种广告、单开关控制的修订确认。

## 隐私政策调整

依据用户指定的 [Adsterra 接入完整指南](https://bryantchen.cc/zh/posts/adsterra-integration-guide) 中“别忘了更新隐私政策”一节，采用最小第三方服务披露，不新增同意管理功能：

- 在中英文隐私页的第三方服务或广告小节说明本站支持 Adsterra 与 Google AdSense，通过配置选择其中一家投放，并分别提供两家平台的隐私信息链接；当前实际启用的平台须如实显示，不描述为两家同时投放。
- 初始 Adsterra 披露采用文章建议的简短表述，并说明它在本站启用广告的页面提供展示广告，链接至 [Adsterra 隐私政策](https://adsterra.com/privacy-policy/)。英文提供对应表述，投放范围以本规格为准，不照搬参考文章自身的网站范围。
- 保留 AdSense 的未来使用说明，但不误述为已获批或当前已投放；切换平台时使用同一个配置同步实际广告披露，关闭广告时不继续声称正在投放。移除并未实现的同意提示承诺；保留与现有 Google 访问衡量、Cloudflare 托管和其他服务实际行为相符的说明。
- 更新中英文生效日期；实际关闭或更换广告服务时同步复核披露，避免文案与行为不一致。
- 参考文章提供披露建议，不作为已满足所有地区法律要求的保证；本次不扩展法律审查或额外交互。

## 行为边界

- 静态投放页随页面加载初始化广告，不增加滚动触发条件或新的懒加载产品选项。异步加载不得阻塞主内容或替换整个页面。
- 运行时详情首次加载、无效参数、主资料错误或不存在时不初始化广告；辅助资料失败不取消已经成功的主资料资格。保留旧主资料的刷新可保留已有广告，不发起第二次初始化；若旧主资料被移除，广告区域也随之移除，不在同一文档内自动刷新广告。
- 广告请求失败、无填充或被拦截时不重试轰炸、不显示错误弹窗、不回退其他广告格式；保留固定广告空间避免正文跳动。页面其余功能继续可用。
- 无脚本时不展示广告，静态正文、导航与原有无脚本提示继续可用。不为广告再加启用脚本的弹窗或操作。
- 使用中英文静态广告标识，广告容器与广告内嵌框架提供可访问名称；广告区域不与站点下载、预览或导航控件混在一起。

## 实现决策

- 共用配置、广告容器和加载入口，实现 `adsterra / adsense / none` 三种互斥状态，不增加通用广告插件系统。当前选中 Adsterra 时不执行原有 AdSense 投放脚本，AdSense 分支和发布商身份仍保留。关闭广告后的真实产物不得请求广告平台。
- 将共享布局改为默认启用广告，免广告页面显式关闭；`adPlacement` 等分类标记仅描述页面或广告位置，不再承担“必须传入才能开启”的隐式门槛。现有页面调用、`BlogIndexView` 等中间组件、领域策略、测试夹具和构建审计须同步，新增普通页面无需修改它们。
- 使用提供的完整 HTTPS 地址和配置，不擅自换域名、补写路径或修改广告 key。加载方式需适配供应商代码的执行时序；若依赖 `document.write`，不可直接在已加载页面执行而覆盖整页。
- 不创建 Popunder、Social Bar、Smartlink 或 Native Banner 接入，不启用 Anti-AdBlock。后台 Adult ads 保持关闭；后台设置仍需在实际账户中复核，前端不能保证所有广告素材和跳转行为。
- 共用组件及其纯逻辑与相邻测试放在 `src/components/`；页面资格等跨页面规则放在领域层。页面仅显式声明资格或传递内容就绪状态。
- 审计使用实际脚本来源与广告初始化标记，不仅匹配 `adsterra` 字样；检查默认开启、显式排除、数量、平台互斥、运行时详情就绪条件和全局关闭状态，不再依靠固定的可投放路由允许名单。申请验证标记不能被误判为双平台投放。
- 更新中英文隐私说明、生效日期、README 和 ADR 0001；保持现有 canonical、hreflang、noindex 与 sitemap 边界不变。
- 本地验证避免向广告平台制造重复展示；自动测试使用隔离的固定响应。真实投放测试只检查正常展示和异常行为，不自点广告、不诱导点击。

## 验证与验收

- 页面资格测试覆盖默认允许和显式排除，并检查运行时详情加载、成功、失败、无效参数、实体缺失和资料切换；新增一个未登记广告路由、未显式开启的普通页面夹具，验证其自动获得广告位。
- 默认展示测试覆盖静态页面加载和运行时资料首次成功后加载，验证重复通知、资料切换和重新渲染不会重复初始化；广告组件不新增同意按钮、偏好存储或设置交互。
- 产物测试分别覆盖三种开关值：Adsterra 只执行 Adsterra、AdSense 只执行 AdSense、none 不执行任一平台；校验无效值或所选平台必要配置缺失时报错。AdSense 分支可以使用固定有效配置夹具测试，不伪造生产广告单元或宣称真实展示通过。
- 产物测试覆盖单一广告边界、脚本实际域名、关闭广告无容器、排除页面无广告请求入口、新增页面默认开启、中英文一致和隐私页与当前平台配置一致。
- 桌面和手机检查中英文真实页面，包含 320 CSS px、断点两侧、键盘焦点、无脚本、广告拦截或请求失败状态；广告异常不影响主内容。
- 实施完成运行相关测试和 `pnpm release:build`，检查 `git diff --check`；本次仅写规格时只做文档检查。
- 正常展示须在浏览器中看到第三方返回的实际广告素材；仅有空容器、脚本加载成功或测试占位图不能判定真实广告展示通过。检查中英文代表页面的桌面与手机布局，确保广告不遮挡内容或产生横向溢出。广告拦截器或无填充导致不可见时如实记录，不能用模拟素材冒充实际展示；生产环境验证需获得部署授权。
- 后台记录、收入、付款和到账由用户自行查看，不纳入验收，不增加相关统计权限、观察窗口或收款方式核验要求。既有代码测试、类型检查与产物审计用于保证改动未破坏站点，不扩展为收入验收。
- 出现自动跳转、非预期弹窗、移动端遮挡等异常时停止试运行。首期停用方式为关闭构建期广告配置后重建并部署；明确它不是即时远程停用，不额外搭建远程配置服务。停用后新加载页面不请求广告，不承诺撤销已打开页面的第三方行为。

## 范围外

- AdSense 内容整改、重新申请、收益承诺、流量采购、广告平台统计抓取及自动收款。
- 后台展示记录、收益、付款与到账的读取、核实、监控、追踪和验收；用户自行处理这些事项。
- 多广告位优化、设备尺寸分流、A/B 测试、广告刷新和各页面独立收益归因。
- 同意条、广告设置、偏好持久化、地域识别和 CMP。
- 双平台同时投放、无填充时自动换平台、AdSense 自动广告扩展出的额外广告位；AdSense 重新申请及当前不具备条件的真实展示验收。
- 未经要求修改全站 Google 访问衡量或部署流程。

## 下一步

规格已按用户修订定稿：新增页面默认启用、特殊页面显式关闭，Adsterra 与 AdSense 共存但互斥投放，通过一个构建期开关选择，保留全局关闭选项。后台收入或到账验收、同意交互均不在范围内。后续按本规格实施；实施授权与部署授权分别判断，不因规格定稿而自动部署。
