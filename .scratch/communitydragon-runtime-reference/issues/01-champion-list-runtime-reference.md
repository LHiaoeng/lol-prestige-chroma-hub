# 01: 修复英雄列表与运行时页面基础

**What to build:** 让中英文英雄目录成为职责单一、真实可用的独立列表页，同时建立后续详情页面复用的运行时页面模式、数据通道、区域数据视图和普通跨页面链接规则。

**Blocked by:** None (can start immediately).

**Status:** completed

- [x] 英文英雄列表只读取 `default`，中文英雄列表只读取 `zh_cn`；默认通道为 `pbe`，显式选择 `latest` 时读取 `latest`。
- [x] 英雄列表页始终渲染列表，不再根据 `id` 查询参数切换成英雄详情或保留隐藏的详情模式。
- [x] 英雄列表支持名称搜索、职业筛选、稳定排序和分页，并为加载、空结果、失败与重试提供可访问状态。
- [x] 每个英雄卡片都是可复制、可在新标签页打开的普通链接，指向相同语言下的独立英雄详情页，并保留当前数据通道。
- [x] 中文和英文页面的按钮、当前来源、状态反馈及无障碍文本只显示小写 `pbe` / `latest`，不显示通道别名。
- [x] 运行时资料边界继续通过 `list`/`get` 行为封装安全 URL、Schema 校验、区域隔离、页面内去重、取消和结构化错误，列表/详情页面模式不会泄漏到数据层。
- [x] 在真实浏览器中，中英文列表能够加载、搜索、筛选、排序、分页、切换通道并打开详情链接；失败恢复由固定夹具自动化测试覆盖，验收过程中没有阻止使用的控制台异常或资源错误。
- [x] 自动化测试使用固定夹具和假请求覆盖列表行为、页面模式、卡片链接、语言与通道状态、竞争响应及失败恢复，常规测试不访问真实 CommunityDragon。

## Implementation result

- `/champions/` 和 `/zh-cn/champions/` 现在是独立列表页，使用显式 `list` 页面模式；旧列表 URL 携带 `id` 时仍保持列表模式。
- 新增 `/champions/detail/?id={id}` 和 `/zh-cn/champions/detail/?id={id}` 详情壳，初始 HTML 使用 `noindex`，并提供返回列表的普通链接。
- 英雄卡片、静态臻彩页面和资源指南统一指向独立英雄详情路径；`latest` 通道在列表、详情及中英文导航中保持不变。
