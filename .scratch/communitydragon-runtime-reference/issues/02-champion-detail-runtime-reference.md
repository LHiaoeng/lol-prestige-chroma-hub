# 02: 建立独立英雄详情页

**What to build:** 让访客通过独立中英文详情页面查看指定英雄及其皮肤集合，使详情的标题、导航、加载状态和 SEO 策略不再与英雄列表混合。

**Blocked by:** 01/修复英雄列表与运行时页面基础。

**Status:** completed

- [x] 英文和中文分别生成独立英雄详情壳，详情通过正安全整数 `id` 加载英雄，不生成逐英雄静态 HTML。
- [x] 缺少或提供非法 `id` 时显示可访问的无效链接状态，并且不发出 CommunityDragon 请求。
- [x] 详情展示当前区域数据视图中的英雄名称、称号、简介、媒体和皮肤正向集合，不跨区域或跨通道补值。
- [x] 详情页初始 HTML 已声明 `noindex`，具有独立标题、说明、面包屑和返回英雄列表的普通链接。
- [x] 从列表进入详情、详情返回列表、语言切换和 `pbe` / `latest` 切换均保留合法的英雄 ID 与数据通道；通道切换失败时保留旧内容和旧 URL。
- [x] 皮肤入口携带皮肤 ID、英雄定位提示和当前数据通道，并指向独立皮肤详情路径。
- [x] 在真实浏览器中，中英文详情可以从列表打开、刷新、分享、切换通道、返回列表和恢复失败，且没有阻止使用的控制台异常或资源错误。
- [x] 自动化测试覆盖详情参数、英雄身份校验、初始 `noindex`、普通跨页面导航、皮肤链接、语言与通道状态，以及不存在、网络失败和 Schema 失败。

## Implementation result

- `/champions/detail/?id={championId}` 和 `/zh-cn/champions/detail/?id={championId}` 是独立的固定详情壳，使用 `detail` 页面模式，不为每个英雄生成静态 HTML。
- 详情控制器只接受正安全整数英雄 ID，使用当前页面语言对应的 `default` 或 `zh_cn` 数据视图和当前 `pbe` / `latest` 通道；返回记录的英雄 ID 必须再次匹配请求 ID。
- 详情视图展示英雄名称、称号、简介、头像媒体和由英雄详情正向记录提供的皮肤集合；皮肤入口统一指向 `/skins/detail/` 并携带皮肤 ID、英雄定位提示和数据通道。
- 初始详情壳带 `noindex`、独立标题、说明和面包屑；返回列表、语言切换和通道切换均保留合法 URL 状态，失败时保留原内容与原 URL。
