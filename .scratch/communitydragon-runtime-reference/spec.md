# CommunityDragon 运行时资料架构规格

## Problem Statement

LoL Chroma Art 当前在 Astro 构建期间读取 CommunityDragon PBE 的 `default` 与 `zh_cn` 数据，合并成一份完整图谱，再为英雄、普通皮肤、皮肤系列和皮肤宇宙生成大量静态页面。这使发布依赖外部源站可用性，扩大静态产物和 sitemap，并把具有不同区域事实的数据视图压进同一个模型。站点还无法在构建后于 PBE 与正式服数据之间切换。

站点需要继续把首页、臻彩详情、博客和固定说明作为稳定、可索引的静态图鉴内容，同时将 CommunityDragon 内容降为可失败的运行时资料。动态资料需要支持 PBE 与正式服、英文与简体中文，但不能重新引入完整皮肤 JSON、运行时代理、区域事实混用或全量实体静态页面。

## Solution

保留静态图鉴内容的现有 Astro 构建链路，并建立一个浏览器端 CommunityDragon 运行时资料模块。该模块通过小型 `list` 与 `get` 接口隐藏 URL 生成、请求、校验、资源路径转换、页面内缓存、取消和错误分类。英文页面只读取 `default`，中文页面只读取 `zh_cn`；默认数据通道为 PBE，URL 中显式的 `channel=latest` 切换到正式服。

Astro 只输出英雄、皮肤、皮肤系列和皮肤宇宙所需的少量双语页面壳。英雄、皮肤系列和皮肤宇宙提供列表与详情；不提供全量皮肤列表，用户从英雄详情进入皮肤详情。运行时详情不承担 SEO，统一 `noindex` 且不进入 sitemap。静态臻彩页可以在正文完成后渐进加载少量关联资料，但其完整性、SEO 和构建成功均不依赖 CommunityDragon。

## User Stories

1. 作为英文访客，我希望英雄资料只读取 CommunityDragon `default` 数据，以便看到 Global Server 区域视图中的事实。
2. 作为中文访客，我希望英雄资料只读取 CommunityDragon `zh_cn` 数据，以便看到 China Server 区域视图中的事实。
3. 作为访客，我希望默认浏览 PBE 数据，以便优先查看当前测试内容。
4. 作为访客，我希望在同一页面壳中切换到正式服数据，以便比较 PBE 与正式服状态。
5. 作为访客，我希望分享的 URL 完整表达实体、语言和数据通道，以便接收方看到相同资料。
6. 作为访客，我希望浏览器前进和后退能够恢复之前的数据通道，以便切换行为符合网页导航习惯。
7. 作为访客，我希望通道切换失败时继续看到原有数据，以便源站短暂故障不会清空页面。
8. 作为访客，我希望目标通道不存在当前实体时看到明确的不存在状态，以便不会把 PBE 数据误认为正式服数据。
9. 作为访客，我希望非法或损坏的详情链接显示链接无效，以便页面不会猜测错误实体。
10. 作为访客，我希望英雄列表支持搜索、排序和分页，以便在不渲染全部节点的情况下找到英雄。
11. 作为访客，我希望从英雄详情浏览该英雄的普通皮肤，以便无需下载完整皮肤目录。
12. 作为访客，我希望皮肤详情链接同时携带皮肤 ID 和英雄定位提示，以便客户端能精确读取单英雄文件并校验皮肤身份。
13. 作为访客，我希望皮肤详情先显示核心资料，再逐步显示系列和宇宙关联，以便关联请求不会阻塞主要内容。
14. 作为访客，我希望皮肤系列拥有独立列表和详情，以便浏览系列名称、描述和所属宇宙。
15. 作为访客，我希望系列详情不冒充完整皮肤目录，以便页面不会承诺无法低成本取得的反向集合。
16. 作为访客，我希望皮肤宇宙拥有独立列表和详情，以便浏览宇宙资料和所属皮肤系列。
17. 作为访客，我希望宇宙详情不冒充完整皮肤或英雄目录，以便页面准确表达数据覆盖范围。
18. 作为访客，我希望区域字段缺失时看到真实缺失状态，以便另一地区的数据不会被静默混入当前页面。
19. 作为访客，我希望区域记录引用的共享图片、视频和图标仍可正常显示，以便物理资源共享不会被误判为区域字段回退。
20. 作为访客，我希望主媒体失败时仍能阅读文字资料，以便单个静态资源 404 不会破坏整个详情。
21. 作为访客，我希望加载期间看到稳定的页面壳、骨架和状态说明，以便页面不会空白或剧烈跳动。
22. 作为键盘和屏幕阅读器用户，我希望加载、失败、重试和切换状态可被感知，以便能够完整操作运行时资料。
23. 作为禁用 JavaScript 的访客，我希望看到页面标题、来源说明、导航和启用脚本提示，以便理解页面用途并返回其他内容。
24. 作为臻彩详情访客，我希望静态正文先完整显示，再自动补充关联英雄和基础皮肤资料，以便 CommunityDragon 故障不影响核心图鉴。
25. 作为臻彩详情访客，我希望 `channel=latest` 只改变 CommunityDragon 补充区，以便静态臻彩事实不会随数据通道变化。
26. 作为博客读者，我希望英雄覆盖率文章始终有完整静态正文，以便发布和阅读不依赖 CommunityDragon 在线状态。
27. 作为博客读者，我希望浏览器可以尝试刷新英雄覆盖率，以便源站可用时获得较新的辅助数据。
28. 作为隐私敏感的访客，我希望站点说明浏览器会连接 CommunityDragon，并尽量减少请求附带信息，以便了解第三方数据请求。
29. 作为站点维护者，我希望断网时仍能完成静态构建，以便外部源站故障不会阻止发布。
30. 作为站点维护者，我希望 CommunityDragon URL、Schema、缓存和错误策略集中在一个模块中，以便源站变化只需在一个位置处理。
31. 作为站点维护者，我希望常规测试不访问真实 CommunityDragon，以便测试快速、稳定且可重复。
32. 作为站点维护者，我希望能够通过显式维护流程更新英雄覆盖率仓库快照，以便快照来源和时间可审计。
33. 作为搜索引擎，我希望 sitemap 只包含站点希望索引的静态内容，以便不会抓取大量动态辅助详情。
34. 作为通过旧 CommunityDragon 静态详情链接访问的用户，我接受页面永久 404，以便站点不必为兼容历史辅助资料继续生成大量文件。

## Implementation Decisions

- 遵循“将 CommunityDragon 资料移至浏览器运行时”ADR；静态图鉴内容与运行时资料是两条独立链路。
- 运行时资料模块是主要数据 seam，只公开 `list` 与 `get` 两类行为。调用方提供实体种类、数字 ID、数据通道、区域数据视图、取消信号，以及皮肤请求需要的英雄定位提示；模块返回经过校验和规范化的区域记录或结构化错误。
- `list` 只支持英雄、皮肤系列和皮肤宇宙，不支持全量皮肤列表。`get` 支持英雄、皮肤、皮肤系列和皮肤宇宙。
- 数字 ID 是 CommunityDragon 实体跨数据通道和区域数据视图的共享身份。名称、描述和 slug 都属于可变化的区域事实，不能用作实体身份。
- 页面语言决定区域数据视图：英文映射 `default`，简体中文映射 `zh_cn`。页面只请求当前区域数据视图，不预取另一语言。
- URL 缺少 `channel` 时表示 PBE；只有 `channel=latest` 表示正式服。实体 ID、皮肤英雄定位提示和数据通道必须在语言切换、内部导航及分享链接中保留。
- `id` 与皮肤的英雄定位提示必须是正安全整数。显式 `channel` 只能是 `pbe` 或 `latest`。非法参数显示链接无效，且不能发出 CommunityDragon 请求。
- 皮肤详情使用英雄定位提示读取对应英雄详情，再按皮肤 ID 查找并验证目标皮肤。缺失提示时允许回退读取必要索引，但不得依据皮肤 ID 的数字格式猜测英雄 ID。
- 不读取完整 `skins.json` 作为皮肤目录、详情默认依赖、系列反向索引或宇宙反向索引。不提供独立皮肤列表入口；用户从英雄详情进入皮肤详情。
- 皮肤系列列表与详情读取系列资源。系列详情展示自身资料和所属宇宙，但不反向列出或承诺全部皮肤。
- 皮肤宇宙列表与详情读取宇宙资源。宇宙详情展示自身资料和所属皮肤系列，但不反向列出或承诺全部皮肤与英雄。
- 英雄详情提供该英雄的皮肤正向集合。皮肤可以链接到系列和宇宙；允许这种有意的单向导航。
- 区域字段缺失时保留缺失状态，不读取另一数据视图补值。由当前区域记录引用的共享静态资源仍按 CommunityDragon 资源路径规则解析，不构成区域事实回退。
- 运行时资料模块只允许访问批准的 HTTPS CommunityDragon RAW 源站和白名单路径。查询参数不能控制域名或任意相对路径。
- 请求使用省略凭据和 Referer 的浏览器设置。页面初次进入、显式重试和数据通道切换会加载数据；不轮询、不预取详情、不在页面获得焦点时自动刷新。
- 页面内以数据通道、区域数据视图和资源键缓存进行中的 Promise 和已完成响应，避免重复请求。不使用 `localStorage`、`sessionStorage`、IndexedDB 或 Service Worker 保存 CommunityDragon 响应；浏览器 HTTP 缓存和验证器负责跨导航缓存。
- 核心实体请求优先。核心数据成功后，关联资源最多三个并发请求；通道切换、重新加载或页面销毁时取消旧请求，旧响应不得覆盖新状态。
- 页面运行时控制器是主要交互 seam。它负责解析 URL、调用运行时资料模块、维护 History API、渲染加载/成功/空状态/失败，以及协调重试和数据通道切换。
- 数据通道只影响运行时资料。PBE/正式服切换器出现在动态资料来源区；静态臻彩页只在 CommunityDragon 补充区显示该控件，不放入全站 Header。
- 通道切换先加载目标数据，成功后再提交新内容与 URL。失败时保留旧内容和旧 URL，并显示可访问的失败反馈。
- 核心实体先渲染，系列、宇宙等关联区独立加载。关联失败不移除核心详情。
- 动态页面保留可读的静态标题、资料来源、导航和无脚本提示。内容区使用接近最终布局的骨架，暴露忙碌状态和状态消息，避免全屏遮罩。
- 动态详情统一 `noindex`，不进入 sitemap，也不为每个实体生成静态 HTML。旧的 CommunityDragon 实体静态详情 URL 不生成兼容页或跳转，永久返回 404。
- 动态目录页面可以保留静态说明和自身 canonical，但其运行时实体不成为静态 SEO 页面。
- 静态臻彩正文、图片、主要操作和 SEO 不依赖 CommunityDragon。正文完成后可以自动加载精确的英雄和基础皮肤补充资料；补充失败只影响其自身区域。
- 静态臻彩页上的当前 `channel` 参数会传递给补充资料及指向其他运行时资料的链接，但不会改变静态臻彩事实。
- 英雄覆盖率文章从仓库快照生成完整静态正文。快照通过显式维护命令更新并记录来源 URL、数据通道、区域数据视图、抓取时间和内容版本；普通发布构建不联网更新。浏览器刷新是可失败的渐进增强。
- 隐私说明披露浏览器会向 CommunityDragon 发起资料与媒体请求。第一版不增加外部错误监控；用户可见错误、重试和开发环境日志承担反馈职责。
- 不引入客户端框架。页面沿用 Astro 静态壳与 TypeScript DOM 控制器模式。
- 迁移按垂直切片进行，新旧实现不长期并存。完成迁移后移除完整 PBE 图谱、构建时 CommunityDragon 实体抓取、实体静态路由、动态实体 sitemap 条目和仅适用于旧图谱的 PBE 命名。

## Testing Decisions

- 测试只验证调用者和用户可观察到的行为，不绑定内部函数拆分、缓存容器或 DOM 构建步骤。
- 第一主要 seam 是 CommunityDragon 运行时资料模块的 `list` 与 `get` 行为。测试注入假 `fetch`，覆盖 PBE/Latest、`default`/`zh_cn`、安全 URL、Schema 校验、共享静态资源解析、页面内请求去重、取消、HTTP 失败、非法响应、实体不存在和结构化错误。
- 运行时资料模块测试必须证明英文请求不会读取 `zh_cn`，中文请求不会读取 `default`，字段缺失不会跨区域或跨通道补值。
- 皮肤详情测试必须证明英雄定位提示用于选择资源、返回的皮肤 ID 会再次校验、定位提示与响应不一致时失败，并且正常路径不请求完整 `skins.json`。
- 第二主要 seam 是页面运行时控制器。DOM 测试通过注入假的运行时资料模块和 History Adapter，覆盖参数解析、加载、成功、空状态、失败、重试、切换、取消、旧响应竞争、前进后退、语言链接和可访问状态。
- 通道切换测试必须证明目标加载成功前 URL 不变化，失败时旧内容和旧 URL 保留，实体在目标通道不存在时显示明确空状态。
- 静态臻彩渐进增强测试必须证明正文先存在，补充成功时追加资料，失败时正文和主要操作保持不变，且 `channel` 只影响补充资料。
- 英雄覆盖率测试使用提交的仓库快照生成正文，并证明浏览器刷新失败时保留快照。快照维护流程需要验证元数据和两个区域数据视图。
- 构建产物是系统级验收面。测试应证明断网时静态构建成功、首页/博客/臻彩正文完整、动态详情带 `noindex`、sitemap 不含 CommunityDragon 实体、旧实体详情没有产物、完整目录 JSON 未公开。
- 常规测试使用小型固定 JSON 夹具，不访问真实 CommunityDragon。真实 PBE/Latest 探测仅用于人工维护和诊断，不阻塞日常测试。
- 沿用现有 URL 转换测试、可注入加载/应用/降级测试、DOM 初始化器测试、SEO/sitemap 测试和构建产物测试模式；迁移后删除只验证旧静态图谱行为的测试。

## Out of Scope

- 为 CommunityDragon 动态实体提供可索引的静态详情或服务端渲染。
- 生成 PBE 与 Latest 双静态版本树。
- 提供全量皮肤列表或读取完整 `skins.json` 作为默认页面依赖。
- 在系列或宇宙页面维护完整的皮肤反向索引。
- 为旧 CommunityDragon 静态详情 URL 提供跳转或兼容页面。
- 建立本站 CommunityDragon 代理、Worker 数据接口、远程镜像或运行时数据库。
- 使用 `localStorage`、`sessionStorage`、IndexedDB 或 Service Worker 持久缓存外部资料。
- 引入 React、Vue 或其他客户端 UI 框架。
- 自动轮询、焦点刷新或列表详情预取。
- 支持任意固定补丁目录；本规格只覆盖滚动的 `pbe` 与 `latest`。
- 自动部署、提交 Pull Request 或改变 Cloudflare Worker 名称、域名及生产分支。

## Further Notes

- 2026-09-20 的只读探测确认目标 PBE/Latest、`default`/`zh_cn` JSON 支持浏览器跨域读取。Latest 明确缓存一小时；PBE 未提供 `Cache-Control`，但两者都有 `ETag` 与 `Last-Modified`，条件请求可返回 `304`。
- 同次探测中，英雄摘要未压缩约 54–56 KB，单英雄详情示例约 75 KB，完整皮肤 JSON 未压缩约 5.9–6.2 MB。该体积是取消全量皮肤目录和禁止默认读取完整皮肤 JSON的直接依据。
- CommunityDragon 日后若取消跨域、限制访问或重组路径，运行时资料应明确失败。代理或仓库级运行时后备源需要新的架构决策，不能作为本规格的隐藏回退。
- 规格实现完成的判断以 ADR 中的静态/动态边界和本规格的构建产物验收为准。
