# CommunityDragon 运行时资料架构规格

## Problem Statement

LoL Chroma Art 原先在 Astro 构建期间读取 CommunityDragon `pbe` 的 `default` 与 `zh_cn` 数据，合并成一份完整图谱，再为英雄、皮肤、皮肤系列和皮肤宇宙生成大量静态页面。这使发布依赖外部源站可用性，扩大静态产物和 sitemap，并把不同本地化视图的事实压进同一个模型。站点还无法在构建后于 `pbe` 与 `latest` 之间切换。

站点需要继续把首页、臻彩详情、博客和固定说明作为稳定、可索引的静态图鉴内容，同时将 CommunityDragon 内容降为可失败的运行时资料。动态资料需要支持 `pbe` 与 `latest`、英文与简体中文，但不能重新引入完整皮肤 JSON、运行时代理、本地化事实混用或全量实体静态页面。

当前仓库已经存在一轮运行时页面实现，但实际页面不可用。英雄列表和英雄详情目前共用同一个页面壳，通过 `id` 查询参数在客户端切换模式，使列表路由同时承担目录与详情职责。通过单元测试、类型检查或静态构建不能单独代表本规格完成；英雄、皮肤、皮肤系列和皮肤宇宙页面必须在真实浏览器中能够加载、导航、切换和恢复失败，才可视为交付。

## Solution

保留静态图鉴内容的现有 Astro 构建链路，并建立一个浏览器端 CommunityDragon 运行时资料模块。该模块通过小型 `list` 与 `get` 接口隐藏 URL 生成、请求、校验、资源路径转换、页面内缓存、取消和错误分类。英文页面只读取 `default`，中文页面只读取 `zh_cn`；默认数据通道为 `pbe`，URL 中显式的 `channel=latest` 切换到 `latest`。

Astro 只输出英雄、皮肤、皮肤系列和皮肤宇宙所需的少量双语页面壳。英雄、皮肤系列和皮肤宇宙分别拥有独立的列表页与详情页；皮肤不提供全量列表，但拥有独立详情页。中文页面使用对应的 `/zh-cn/` 前缀。该结构参考两个 Skin Explorer 项目将集合与实体详情分成独立页面的做法，同时使用固定详情壳而不是为每个实体生成静态 HTML。

英雄、皮肤系列和皮肤宇宙提供列表与详情；不提供全量皮肤列表，用户从英雄详情进入皮肤详情。运行时详情不承担 SEO，统一 `noindex` 且不进入 sitemap。首页、臻彩详情、博客、覆盖率文章和其他原有静态页面保持现状，不属于本轮修改范围。

CommunityDragon 数据源和 URL 使用精确的小写 token `pbe` 与 `latest`。玩家界面将 `pbe` 显示为 `PBE`，将 `latest` 显示为中文“正式服”或英文 `Live`；本地化视图 token `default` 与 `zh_cn` 不作为服务器名称展示。

## User Stories

1. 作为英文访客，我希望英雄资料只读取 CommunityDragon `default` 本地化视图，以便看到该视图中的事实，而不会被误导为某个游戏服务器。
2. 作为中文访客，我希望英雄资料只读取 CommunityDragon `zh_cn` 本地化视图，以便看到简体中文资料，而不会把 `zh_cn` 当成国服服务器标识。
3. 作为访客，我希望默认浏览 `pbe` 数据，以便优先查看当前测试内容。
4. 作为访客，我希望在同一页面壳中切换到 `latest` 数据，以便比较两个滚动数据通道。
5. 作为访客，我希望分享的 URL 完整表达实体、语言和数据通道，以便接收方看到相同资料。
6. 作为访客，我希望浏览器前进和后退能够恢复之前的数据通道，以便切换行为符合网页导航习惯。
7. 作为访客，我希望通道切换失败时继续看到原有数据，以便源站短暂故障不会清空页面。
8. 作为访客，我希望目标通道不存在当前实体时看到明确的不存在状态，以便不会把一个通道的数据误认为另一个通道的数据。
9. 作为访客，我希望非法或损坏的详情链接显示链接无效，以便页面不会猜测错误实体。
10. 作为访客，我希望英雄列表支持搜索、排序和分页，以便在不渲染全部节点的情况下找到英雄。
11. 作为访客，我希望从英雄详情浏览该英雄的皮肤，以便无需下载完整皮肤目录。
12. 作为访客，我希望皮肤详情链接同时携带皮肤 ID 和英雄定位提示，以便客户端能精确读取单英雄文件并校验皮肤身份。
13. 作为访客，我希望皮肤详情先显示核心资料，再逐步显示皮肤系列和皮肤宇宙关联，以便关联请求不会阻塞主要内容。
14. 作为访客，我希望皮肤系列拥有独立列表和详情，以便浏览系列名称、描述和所属宇宙。
15. 作为访客，我希望系列详情不冒充完整皮肤目录，以便页面不会承诺无法低成本取得的反向集合。
16. 作为访客，我希望皮肤宇宙拥有独立列表和详情，以便浏览宇宙资料和所属皮肤系列。
17. 作为访客，我希望皮肤宇宙详情不冒充完整皮肤或英雄目录，以便页面准确表达数据覆盖范围。
18. 作为访客，我希望本地化字段缺失时看到真实缺失状态，以便另一视图的数据不会被静默混入当前页面。
19. 作为访客，我希望本地化记录引用的共享图片、视频和图标仍可正常显示，以便物理资源共享不会被误判为跨视图字段回退。
20. 作为访客，我希望主媒体失败时仍能阅读文字资料，以便单个静态资源 404 不会破坏整个详情。
21. 作为访客，我希望加载期间看到稳定的页面壳、骨架和状态说明，以便页面不会空白或剧烈跳动。
22. 作为键盘和屏幕阅读器用户，我希望加载、失败、重试和切换状态可被感知，以便能够完整操作运行时资料。
23. 作为禁用 JavaScript 的访客，我希望看到页面标题、来源说明、导航和启用脚本提示，以便理解页面用途并返回其他内容。
24. 作为隐私敏感的访客，我希望站点说明浏览器会连接 CommunityDragon，并尽量减少请求附带信息，以便了解第三方数据请求。
25. 作为站点维护者，我希望断网时仍能完成静态构建，以便外部源站故障不会阻止发布。
26. 作为站点维护者，我希望 CommunityDragon URL、Schema、缓存和错误策略集中在一个模块中，以便源站变化只需在一个位置处理。
27. 作为站点维护者，我希望常规测试不访问真实 CommunityDragon，以便测试快速、稳定且可重复。
28. 作为搜索引擎，我希望 sitemap 只包含站点希望索引的静态内容，以便不会抓取大量动态辅助详情。
29. 作为通过旧 CommunityDragon 静态详情链接访问的用户，我接受页面永久 404，以便站点不必为兼容历史辅助资料继续生成大量文件。
30. 作为中文访客，我希望通道按钮和当前来源显示 `PBE` 与“正式服”，以便使用游戏圈熟悉的名称。
31. 作为英文访客，我希望通道按钮和当前来源显示 `PBE` 与 `Live`，以便使用英文玩家熟悉的名称。
32. 作为屏幕阅读器用户，我希望通道控件和状态反馈朗读与视觉界面相同的玩家名称，以便不用理解 CommunityDragon 路径 token。
33. 作为维护者，我希望 URL、请求和领域模型保留 `pbe` / `latest`，玩家界面通过集中映射显示 `PBE` / “正式服” / `Live`，以便技术身份与展示文案不会混为一层。
34. 作为访客，我希望运行时页面在真实浏览器中能够加载内容、进入详情、切换通道和重试失败，以便页面不是只能通过构建和单元测试的静态壳。
35. 作为维护者，我希望浏览器验收覆盖中英文和所有运行时实体入口，以便脚本装载、DOM 绑定、跨域请求或路由问题能够在交付前暴露。
36. 作为访客，我希望英雄列表拥有独立 URL，以便打开列表时始终看到目录而不是由查询参数决定的详情状态。
37. 作为访客，我希望英雄详情拥有独立页面壳，以便详情的标题、导航、加载状态和 SEO 策略不与列表混合。
38. 作为访客，我希望点击英雄卡片执行正常的跨页面导航，以便刷新、复制链接、在新标签页打开和浏览器返回都符合普通网页行为。
39. 作为中文访客，我希望中文英雄列表与详情保持同样的页面划分，以便中英文信息架构一致。
40. 作为访客，我希望英雄详情链接保留数字 ID 和当前数据通道，以便目标页面加载与列表中相同的数据视图。
41. 作为访客，我希望从详情返回列表时仍保留当前数据通道，以便无需重复选择 `pbe` 或 `latest`。
42. 作为访客，我希望旧的列表页 `?id=` 地址不再呈现详情，以便列表页职责保持单一且没有隐藏兼容模式。
43. 作为搜索引擎，我希望英雄列表可以保持目录页面语义，而英雄详情壳明确 `noindex`，以便两个页面的抓取策略不相互污染。
44. 作为访客，我希望皮肤系列列表与系列详情使用不同页面，以便浏览目录和查看单个系列不会共享隐藏状态。
45. 作为访客，我希望皮肤宇宙列表与皮肤宇宙详情使用不同页面，以便每个页面拥有清晰的导航、标题和失败状态。
46. 作为访客，我希望皮肤拥有独立详情页，以便从英雄、皮肤系列或皮肤宇宙进入皮肤时得到稳定且可分享的页面地址。
47. 作为访客，我希望皮肤详情继续要求英雄定位提示，以便客户端读取单英雄资源并复核皮肤身份，而不是下载完整皮肤目录。
48. 作为访客，我希望皮肤系列详情到皮肤宇宙详情、皮肤宇宙详情到皮肤系列详情以及英雄详情到皮肤详情都执行普通跨页面导航，以便刷新与返回行为一致。
49. 作为维护者，我希望每种详情壳在初始 HTML 中具有明确 `noindex`，以便 SEO 规则不依赖客户端数据加载成功。
50. 作为维护者，我希望列表页永远只解析列表状态、详情页永远只解析详情状态，以便控制器无需根据同一路径上的查询参数切换页面职责。

## Implementation Decisions

- 遵循“将 CommunityDragon 资料移至浏览器运行时”ADR；静态图鉴内容与运行时资料是两条独立链路。
- 运行时资料模块是主要数据 seam，只公开 `list` 与 `get` 两类行为。调用方提供实体种类、数字 ID、数据通道、本地化视图、取消信号，以及皮肤请求需要的英雄定位提示；模块返回经过校验和规范化的本地化记录或结构化错误。
- `list` 只支持英雄、皮肤系列和皮肤宇宙，不支持全量皮肤列表。`get` 支持英雄、皮肤、皮肤系列和皮肤宇宙。
- 数字 ID 是 CommunityDragon 实体跨数据通道和本地化视图的共享身份。名称、描述和 slug 都属于可变化的本地化事实，不能用作实体身份。
- 页面语言决定本地化视图：英文映射 `default`，简体中文映射 `zh_cn`。页面只请求当前本地化视图，不预取另一语言，也不把视图 token 当成服务器名称。
- 英雄列表和英雄详情是两个独立的 Astro 页面壳。英文列表使用 `/champions/`，英文详情使用 `/champions/detail/?id={championId}`；中文版本在路径前增加 `/zh-cn/`。
- 皮肤系列列表和详情是两个独立页面壳。英文列表使用 `/skinlines/`，英文详情使用 `/skinlines/detail/?id={skinlineId}`；中文版本使用对应前缀。
- 宇宙列表和详情是两个独立页面壳。英文列表使用 `/universes/`，英文详情使用 `/universes/detail/?id={universeId}`；中文版本使用对应前缀。
- 皮肤只提供独立详情壳 `/skins/detail/?id={skinId}&champion={championId}` 及中文等价地址，不提供 `/skins/` 全量列表。`champion` 定位提示仍是必需参数。
- 列表页只解析列表状态，不因存在 `id` 参数而渲染详情。详情页只解析对应实体详情状态，缺少或提供非法参数时显示无效链接且不发出 CommunityDragon 请求。
- 列表卡片和实体关联使用普通可复制链接导航到对应详情页，不在列表页内用 History API 替换为详情内容。详情页内的数据通道切换可以继续使用当前页面的运行时控制器。
- 列表与详情之间保留 `channel`。页面语言切换同时映射到另一语言的同类页面，并保留合法实体 ID、皮肤英雄定位提示和数据通道。
- 旧的 `/champions/?id=...`、`/skinlines/?id=...`、`/universes/?id=...`、`/skins/?id=...` 及中文等价地址不再作为详情入口，不增加重定向或客户端兼容模式；列表页始终保持列表职责。
- 不采用 `/{entity}/{entityId}/` 形式，因为纯静态部署无法在不生成逐实体 HTML 或增加服务器重写的情况下提供任意动态路径。固定详情壳保留少量静态页面的架构边界。
- URL 缺少 `channel` 时表示 `pbe`；显式 `channel=pbe` 与 `channel=latest` 都是有效值。实体 ID、皮肤英雄定位提示和数据通道必须在语言切换、内部导航及分享链接中保留。
- `id` 与皮肤的英雄定位提示必须是正安全整数。显式 `channel` 只能是 `pbe` 或 `latest`。非法参数显示链接无效，且不能发出 CommunityDragon 请求。
- 皮肤详情使用英雄定位提示读取对应英雄详情，再按皮肤 ID 查找并验证目标皮肤。缺失提示时允许回退读取必要索引，但不得依据皮肤 ID 的数字格式猜测英雄 ID。
- 不读取完整 `skins.json` 作为皮肤目录、详情默认依赖、系列反向索引或宇宙反向索引。不提供独立皮肤列表入口；用户从英雄详情进入皮肤详情。
- 皮肤系列列表与详情读取系列资源。系列详情展示自身资料和所属宇宙，但不反向列出或承诺全部皮肤。
- 皮肤宇宙列表与详情读取皮肤宇宙资源。皮肤宇宙详情展示自身资料和所属皮肤系列，但不反向列出或承诺全部皮肤与英雄。
- 英雄详情提供该英雄的皮肤正向集合。皮肤可以链接到皮肤系列和皮肤宇宙；允许这种有意的单向导航。
- 本地化字段缺失时保留缺失状态，不读取另一视图补值。由当前本地化记录引用的共享静态资源仍按 CommunityDragon 资源路径规则解析，不构成跨视图事实回退。
- 运行时资料模块只允许访问批准的 HTTPS CommunityDragon RAW 源站和白名单路径。查询参数不能控制域名或任意相对路径。
- 请求使用省略凭据和 Referer 的浏览器设置。页面初次进入、显式重试和数据通道切换会加载数据；不轮询、不预取详情、不在页面获得焦点时自动刷新。
- 页面内以数据通道、本地化视图和资源键缓存进行中的 Promise 和已完成响应，避免重复请求。不使用 `localStorage`、`sessionStorage`、IndexedDB 或 Service Worker 保存 CommunityDragon 响应；浏览器 HTTP 缓存和验证器负责跨导航缓存。
- 核心实体请求优先。核心数据成功后，关联资源最多三个并发请求；通道切换、重新加载或页面销毁时取消旧请求，旧响应不得覆盖新状态。
- 页面运行时控制器是主要交互 seam。它负责解析 URL、调用运行时资料模块、维护 History API、渲染加载/成功/空状态/失败，以及协调重试和数据通道切换。
- 数据通道只影响运行时资料。`pbe` / `latest` 切换器出现在动态资料来源区，不放入全站 Header。
- 数据通道 token 是大小写敏感的技术名称。URL、请求、缓存键和领域值使用 `pbe` 或 `latest`；玩家界面通过集中映射显示中文 `PBE` / “正式服”和英文 `PBE` / `Live`。
- `default` 与 `zh_cn` 是本地化视图 token，不映射为“直营服”或“国服”。页面通常不显示这些 token；需要说明语言时使用 `English` 或“简体中文”。
- 通道切换先加载目标数据，成功后再提交新内容与 URL。失败时保留旧内容和旧 URL，并显示可访问的失败反馈。
- 核心实体先渲染，系列、宇宙等关联区独立加载。关联失败不移除核心详情。
- 动态页面保留可读的静态标题、资料来源、导航和无脚本提示。内容区使用接近最终布局的骨架，暴露忙碌状态和状态消息，避免全屏遮罩。
- 动态详情统一 `noindex`，不进入 sitemap，也不为每个实体生成静态 HTML。旧的 CommunityDragon 实体静态详情 URL 不生成兼容页或跳转，永久返回 404。
- 英雄、皮肤系列和皮肤宇宙列表等动态目录页面可以保留静态说明、自身 canonical 和目录页面语义；英雄、皮肤、皮肤系列和皮肤宇宙详情壳具有独立标题与导航，并在初始 HTML 中声明 `noindex`，不能只依赖数据加载后的客户端注入。
- 首页、臻彩详情、博客、覆盖率文章及其他原有静态页面保持当前实现，本轮不修改其内容、数据链路、交互、SEO 或测试。
- 隐私说明披露浏览器会向 CommunityDragon 发起资料与媒体请求。第一版不增加外部错误监控；用户可见错误、重试和开发环境日志承担反馈职责。
- 不引入客户端框架。页面沿用 Astro 静态壳与 TypeScript DOM 控制器模式。
- 迁移按垂直切片进行，新旧实现不长期并存。完成迁移后移除完整 `pbe` 图谱、构建时 CommunityDragon 实体抓取、实体静态路由、动态实体 sitemap 条目和仅适用于旧图谱的命名。
- CommunityDragon 资源指南持续作为数据通道、本地化视图、资源路径和展示规则的项目权威指南；实现发现稳定新事实时在同一任务中更新指南。
- 任务完成必须以真实浏览器中的用户路径可用为准。存在页面壳、单元测试通过或构建成功都不能替代列表渲染、详情导航、通道切换、错误重试和无阻断脚本异常的浏览器验收。

## Testing Decisions

- 测试只验证调用者和用户可观察到的行为，不绑定内部函数拆分、缓存容器或 DOM 构建步骤。
- 第一主要 seam 是 CommunityDragon 运行时资料模块的 `list` 与 `get` 行为。测试注入假 `fetch`，覆盖 `pbe` / `latest`、`default` / `zh_cn`、安全 URL、Schema 校验、共享静态资源解析、页面内请求去重、取消、HTTP 失败、非法响应、实体不存在和结构化错误。
- 运行时资料模块测试必须证明英文请求不会读取 `zh_cn`，中文请求不会读取 `default`，字段缺失不会跨本地化视图或跨通道补值。
- 皮肤详情测试必须证明英雄定位提示用于选择资源、返回的皮肤 ID 会再次校验、定位提示与响应不一致时失败，并且正常路径不请求完整 `skins.json`。
- 第二主要 seam 是页面运行时控制器。DOM 测试通过注入假的运行时资料模块和 History Adapter，覆盖参数解析、加载、成功、空状态、失败、重试、切换、取消、旧响应竞争、前进后退、语言链接和可访问状态。
- 通道切换测试必须证明目标加载成功前 URL 不变化，失败时旧内容和旧 URL 保留，实体在目标通道不存在时显示明确空状态。
- 构建产物是系统级验收面。测试应证明断网时静态构建成功、动态详情带 `noindex`、sitemap 不含 CommunityDragon 实体、旧实体详情没有产物、完整目录 JSON 未公开。
- 浏览器可用性是系统级验收面。至少覆盖中英文英雄列表和详情、英雄到皮肤、皮肤系列与皮肤宇宙、`pbe` / `latest` 切换、失败重试和浏览器前进后退；验收必须检查阻断性控制台异常和失败网络请求。
- 构建路由测试必须证明中英文各自生成英雄、皮肤系列和皮肤宇宙的独立列表壳与详情壳，以及独立皮肤详情壳。列表壳保持目录 canonical 且不承担详情状态；所有详情壳初始 HTML 带 `noindex`，缺少合法参数时不会请求 CommunityDragon。
- 真实浏览器导航测试从英雄列表开始，覆盖数据加载、筛选与分页、普通链接进入英雄详情、英雄进入皮肤详情、皮肤系列与皮肤宇宙互相导航、返回列表、刷新、新标签页可复制 URL、语言切换和 `pbe` / `latest` 保留。
- 浏览器测试必须证明所有列表卡片和实体关联指向独立详情路径，旧列表页 `?id=` 形式不会在当前页面渲染详情，详情页非法 ID 或皮肤缺少英雄提示时显示可访问的无效状态。
- 用户可见 DOM 测试必须断言中文界面显示 `PBE` / “正式服”、英文界面显示 `PBE` / `Live`，同时 URL 与请求继续使用精确 token `pbe` / `latest`。
- 仓库与构建产物进行分层术语审计，覆盖 CommunityDragon 通道相关 UI、无障碍文案、测试、资源指南、ADR、规格和最终 HTML；技术 token 与玩家显示名分别按所在层级判断。
- 常规测试使用小型固定 JSON 夹具，不访问真实 CommunityDragon。真实 `pbe` / `latest` 探测仅用于人工维护、浏览器验收和诊断，不阻塞日常单元测试。
- 沿用现有 URL 转换测试、可注入加载/应用/降级测试、DOM 初始化器测试、SEO/sitemap 测试和构建产物测试模式；迁移后删除只验证旧静态图谱行为的测试。

## Out of Scope

- 为 CommunityDragon 动态实体提供可索引的静态详情或服务端渲染。
- 为每个英雄、皮肤、皮肤系列或皮肤宇宙生成逐实体静态页面，或为动态路径增加 Cloudflare Worker 重写。
- 为旧的列表页 `?id=` 详情形式提供重定向或兼容渲染。
- 提供皮肤全量列表页。
- 生成 `pbe` 与 `latest` 双静态版本树。
- 提供全量皮肤列表或读取完整 `skins.json` 作为默认页面依赖。
- 在皮肤系列或皮肤宇宙页面维护完整的皮肤反向索引。
- 为旧 CommunityDragon 静态详情 URL 提供跳转或兼容页面。
- 建立本站 CommunityDragon 代理、Worker 数据接口、远程镜像或运行时数据库。
- 使用 `localStorage`、`sessionStorage`、IndexedDB 或 Service Worker 持久缓存外部资料。
- 引入 React、Vue 或其他客户端 UI 框架。
- 自动轮询、焦点刷新或列表详情预取。
- 支持任意固定补丁目录；本规格只覆盖滚动的 `pbe` 与 `latest`。
- 修改首页、臻彩详情、博客、覆盖率文章或其他原有静态页面。
- 自动部署、提交 Pull Request 或改变 Cloudflare Worker 名称、域名及生产分支。

## Further Notes

- 2026-09-20 的只读探测确认目标 `pbe` / `latest`、`default` / `zh_cn` JSON 支持浏览器跨域读取。`latest` 明确缓存一小时；`pbe` 未提供 `Cache-Control`，但两者都有 `ETag` 与 `Last-Modified`，条件请求可返回 `304`。
- 同次探测中，英雄摘要未压缩约 54–56 KB，单英雄详情示例约 75 KB，完整皮肤 JSON 未压缩约 5.9–6.2 MB。该体积是取消全量皮肤目录和禁止默认读取完整皮肤 JSON的直接依据。
- CommunityDragon 日后若取消跨域、限制访问或重组路径，运行时资料应明确失败。代理或仓库级运行时后备源需要新的架构决策，不能作为本规格的隐藏回退。
- 规格实现完成的判断以 ADR 中的静态/动态边界和本规格的构建产物验收为准。
- 本规格中的反引号用于标识规范 token；实际用户界面显示不带反引号的纯文本 `pbe` / `latest`。
- 页面划分参考 BuguoguoLoLCreator/lol-skin-explorer 与 BennyExtreme00/lol-skin-explorer 的集合到独立实体详情导航，但不复制其 Next.js 静态生成和阻塞回退机制。
