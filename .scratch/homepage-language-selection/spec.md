# 首页自动语言选择

## 目标

直接打开站点首页或从外站进入时，访客能优先看到自己选过或浏览器偏好的语言。选择简体中文时，在发送首页 HTML 前完成跳转，避免先显示英文首屏。

## 浏览规则

| 场景 | 结果 |
| --- | --- |
| 从站内导航到 `/`，请求有同站导航信号 | 显示英文首页，沿用站内链接指向的语言 |
| 直接或从外站访问 `/`，已保存站点语言偏好 | 按保存的英文或简体中文选择首页 |
| 直接或从外站访问 `/`，没有有效站点语言偏好 | 按请求中的 `Accept-Language` 选择首页 |
| 请求来源无法识别 | 按直接访问处理 |
| 直接打开 `/zh-cn/`、博客、图鉴或其他内页 | 按 URL 显示相应语言 |

- `Accept-Language` 按权重从高到低匹配，同权重按请求头顺序，跳过明确排除或不支持的语言。`en` 及英文地区变体匹配英文。`zh`、`zh-CN`、`zh-SG` 和明确标注 `Hans` 的中文标签匹配简体中文。明确标注 `Hant` 或默认使用繁体中文的 `zh-TW`、`zh-HK`、`zh-MO` 继续检查后续偏好。缺少有效匹配时显示英文。
- 自动进入简体中文首页时返回 `302` 到 `/zh-cn/`，保留原查询参数。浏览或自动跳转不会写入站点语言偏好。
- 保留页头语言切换入口，内页仅使用该入口。手动切换打开同一页面的对应语言，保存站点语言偏好一年，再次切换重新计时。禁用 JavaScript 时仍可切换并保存。清除站点数据后恢复浏览器判断。

## 实现和 SEO

- 保留 Astro 双语静态构建。在 `wrangler.jsonc` 配置 Worker 入口、`ASSETS` 绑定和选择性 `run_worker_first`。首页语言判断及手动切换请求由 Worker 处理，其余页面和资源使用静态资源路由。
- 从请求的同源导航信号识别站内访问。手动切换使用浏览器原生表单提交，由 Worker 校验站内目标路径和语言，写入站点 Cookie，再跳转。正常启用 JavaScript 的详情页切换时保留影响内容的查询参数和锚点。
- 个性化首页响应和写入 Cookie 的响应使用 `Cache-Control: private, no-store`。两种首页各自维持固定的 HTML、canonical、`hreflang` 与 sitemap URL。没有语言偏好的请求可直接取得英文首页。
- 实施时更新《国际化与多语言 SEO》，说明首页例外、手动切换机制、Cookie 与验收规则。

## 验收

- 覆盖 Cookie 优先级、浏览器语言顺序、简繁体匹配、缺失或无效语言、站内导航及来源未知的请求。
- 使用本地 Wrangler 验证根路径的 `200` 和 `302`、查询参数、缓存头、手动切换的偏好写入、普通内页及静态资源、两种首页的 SEO。验证英文内页回首页时仍为英文。
- 核对桌面和移动页头的键盘操作及无 JavaScript 切换。运行相关测试和 `pnpm release:build`。

## 实施结果

- 本地 Wrangler 已验证首页响应、缓存头、Cookie、查询参数、内页与 404。双语首页构建测试覆盖原生切换表单与 SEO 元数据。
- 已在现有 Edge 验证桌面切到中文，并在 440px 移动预览禁用 JavaScript 后切回英文。键盘激活未完成实测。
- 全量测试通过 721 项，失败的 19 项均在改动前的 `c00b956` 干净工作树复现。当前发布构建被这些失败拦住，尚未部署。
