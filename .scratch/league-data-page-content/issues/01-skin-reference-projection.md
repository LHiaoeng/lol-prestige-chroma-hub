# 01: 建立皮肤资料项投影与阶段定位

**What to build:** 在现有 CommunityDragon 运行时边界上建立统一的皮肤资料项投影，使所属皮肤和有效皮肤阶段都具有可验证、可导航的资料身份，并为后续页面提供一致的本地化稀有度、媒体、继承和排序结果。

**Blocked by:** None (can start immediately).

**Status:** completed

- [x] 保留现有安全 URL、数据通道、本地化视图、结构化错误、内存去重和取消行为，现有英雄、系列、宇宙及皮肤页面继续可用。
- [x] 运行时契约能够校验并规范化页面所需的本地化稀有度、完整皮肤媒体、历史版本原画和炫彩颜色，缺失值不跨本地化视图或数据通道补齐。
- [x] 所属皮肤投影为皮肤资料项；只有来源提供有效正整数 ID 和名称的阶段才投影为独立皮肤资料项，不补造名称或顶层实体身份。
- [x] 阶段优先使用自己的名称、媒体和炫彩；描述、稀有度、皮肤系列和皮肤宇宙只从同一响应中的所属皮肤继承。
- [x] 阶段目标由英雄 ID、所属皮肤 ID 和阶段 ID 共同定位；无效、重复或不属于所属皮肤的阶段 ID 被拒绝且不发出额外猜测请求。
- [x] 所有皮肤资料项提供稳定身份、稳定排序和可供现有页面消费的名称、缩略图与本地化稀有度。
- [x] 普通皮肤详情继续通过英雄定位提示读取单英雄资源，不请求完整皮肤资源，也不根据皮肤 ID 数字结构猜测英雄。
- [x] 自动化测试覆盖两种本地化稀有度、媒体、历史原画、颜色、有效与无效阶段、允许与禁止的继承、稳定排序、URL 状态和现有行为无回归。

## Comments

- 已补充本地化稀有度、完整媒体、历史原画、炫彩颜色和阶段定位测试。
- 已核对国服与直营服稀有度事实：`default` 使用 `rarity` 和直营服图标，`zh_cn` 使用 `regionRarityId` 和 `cn-gem-{id}.png` 国服图标，两套映射不互相替代。
- 验证通过：`pnpm test`、`pnpm typecheck`、`pnpm data:validate`、`pnpm build`、`pnpm audit:build`。
