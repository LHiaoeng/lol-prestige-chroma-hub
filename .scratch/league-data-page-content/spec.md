# 英雄联盟资料页面内容扩展规格

## Problem Statement

项目已经能展示臻彩数据和部分 CommunityDragon 运行时资料，但缺少一套明确、统一的内容契约来扩展英雄、皮肤、皮肤系列、皮肤宇宙和 PBE 新增资料页。若直接实施，容易出现本地化视图混用、把皮肤本体项误计为炫彩、皮肤阶段丢失或重复，以及 PBE“新增”口径不统一等问题。

本规格只定义各页面展示哪些英雄联盟数据及其业务规则，不借鉴参考项目的架构、组件结构或视觉样式。

参考内容来源：

- 国服：BuguoguoLoLCreator/lol-skin-explorer
- 直营服：BennyExtreme00/lol-skin-explorer

## Solution

以 `codex/communitydragon-runtime-reference` 已完成的运行时页面、独立详情壳、`pbe` / `latest` 切换、区域隔离、错误状态和浏览器验收为基线。本轮不重建这些能力，只补齐以下内容差距：

1. 扩充英雄目录与英雄详情展示字段。
2. 为皮肤系列详情补充完整皮肤集合。
3. 为皮肤宇宙详情补充完整皮肤集合。
4. 扩充皮肤详情、阶段、炫彩及分区第三方入口，但不新增独立的皮肤目录页。
5. 新增独立的 PBE 新增页，统一展示新增英雄、皮肤、皮肤系列和皮肤宇宙。

页面字段以参考项目实际展示的信息为基线，并由本项目统一领域规则约束：

- 简体中文页面只使用 `zh_cn` 本地化视图，并采用国服参考项目的第三方入口。
- 英文页面只使用 `default` 本地化视图，并采用直营服参考项目的第三方入口。
- 多阶段皮肤的每个有效阶段都生成独立可查看的皮肤资料项，但不成为新的 CommunityDragon 实体。
- 炫彩数量只统计真正的炫彩，不包含皮肤本体项。
- 炫彩区域仍展示皮肤本体项，但必须明确标记为“非炫彩”。
- PBE 新增只表示同一本地化视图中 ID 存在于 `pbe`、不存在于 `latest`；已有实体的字段或媒体变化不算新增。

实施按与基线分支相同的纵向颗粒度拆分为 7 个工单；每个工单拥有单一用户结果、约 8 条可验收完成条件及明确依赖。权威拆分位于本规格同目录的 `issues/`：

1. 统一资料投影与阶段规则。
2. 补齐英雄目录与详情内容。
3. 补齐皮肤系列详情的皮肤集合。
4. 补齐皮肤宇宙详情的皮肤集合。
5. 补齐皮肤详情、炫彩与第三方入口。
6. 建立 PBE 新增页。
7. 完成跨页面收口、文档和整体验收。

## User Stories

### 导航与页面边界

1. 作为访客，我可以进入英雄目录并浏览英雄，而不需要经过臻彩页面。
2. 作为访客，我可以进入皮肤系列目录并浏览系列。
3. 作为访客，我可以进入皮肤宇宙目录并浏览皮肤宇宙。
4. 作为访客，我可以进入独立的 PBE 新增页查看本轮新增资料。
5. 作为访客，我可以从相关实体进入皮肤详情。
6. 作为访客，我不会看到一个独立的皮肤目录页。
7. 作为现有用户，我看到的首页、臻彩详情页和博客内容保持不变。

### 英雄目录与详情

8. 作为访客，我可以在英雄目录看到英雄名称、称号、头像或方形图标。
9. 作为访客，我可以按参考项目已有字段识别英雄的定位、资源类型和基础资料。
10. 作为访客，我可以在英雄详情看到名称、称号、简介、背景故事和主要图片。
11. 作为访客，我可以在英雄详情看到角色、难度、资源类型、攻击类型等结构化资料。
12. 作为访客，我可以在英雄详情看到基础属性及成长属性。
13. 作为访客，我可以在英雄详情看到技能图标、名称、说明和必要的数值信息。
14. 作为访客，我可以在英雄详情看到该英雄的皮肤，并进入对应详情。
15. 作为访客，我在英文页面只看到 `default`、在简体中文页面只看到 `zh_cn` 本地化视图中的事实，但不会把这些 token 误认为服务器名称。

### 皮肤系列目录与详情

16. 作为访客，我可以在皮肤系列目录看到系列名称、说明和代表图片等参考项目展示的信息。
17. 作为访客，我可以在系列详情看到名称、说明、图片及其关联信息。
18. 作为访客，我可以在系列详情看到属于该系列的完整皮肤集合。
19. 作为访客，我可以从系列详情进入皮肤详情。
20. 作为访客，我看到的关联皮肤按稳定规则排序，刷新后顺序不变。

### 皮肤宇宙目录与详情

21. 作为访客，我可以在皮肤宇宙目录看到皮肤宇宙名称、说明和代表图片等参考项目展示的信息。
22. 作为访客，我可以在皮肤宇宙详情看到名称、说明、图片及其关联信息。
23. 作为访客，我可以在宇宙详情看到属于该皮肤宇宙的完整皮肤集合。
24. 作为访客，我可以从皮肤宇宙详情进入皮肤详情。
25. 作为访客，我看到的关联皮肤按稳定规则排序，刷新后顺序不变。

### 皮肤详情

26. 作为访客，我可以看到皮肤名称、所属英雄、说明、稀有度、价格或可获得性等参考项目已有信息。
27. 作为访客，我可以看到皮肤的主视觉、载入图、图标及参考项目展示的其他媒体。
28. 作为访客，我可以看到皮肤所属的皮肤系列与皮肤宇宙，并跳转到对应详情。
29. 作为访客，我可以看到该皮肤的炫彩区域。
30. 作为访客，我看到的炫彩计数不包含皮肤本体项。
31. 作为访客，我仍能在炫彩区域看到皮肤本体项；中文显示“默认配色”，英文显示 `Base`，并能清楚识别它不是炫彩。
32. 作为访客，我看到的真正炫彩保留其颜色信息。
33. 作为访客，我可以区分皮肤本体项与真正炫彩，不会因相同组件外观产生误解。
34. 作为访客，我会把多阶段皮肤的每个有效阶段视为一项可查看的皮肤资料项，同时不会把它误认为新的 CommunityDragon 实体。
35. 作为访客，我在阶段详情优先看到该阶段自己的名称与媒体。
36. 作为访客，当阶段缺少说明、稀有度、皮肤系列或皮肤宇宙时，会看到同一本地化视图、同一数据通道所属皮肤的对应值。
37. 作为访客，我不会看到跨语言或跨渠道继承产生的混合资料。
38. 作为英文页面访客，我可以使用 SkinSpotlights 的对应搜索入口。
39. 作为英文页面访客，我可以使用 Teemo.GG 的对应模型入口。
40. 作为简体中文页面访客，我可以进入不够够语音站的对应英雄语音页。
41. 作为简体中文页面访客，我可以进入哔哩哔哩的对应皮肤视频搜索。
42. 作为简体中文页面访客，我可以进入不够够 3D 模型站的对应模型页。
43. 作为访客，我看到的第三方入口会随页面语言与本地化视图变化，不会混用两组链接。

### PBE 新增

44. 作为访客，我可以在一个页面统一查看 PBE 新增英雄、皮肤、皮肤系列和皮肤宇宙。
45. 作为访客，我可以清楚区分四类新增实体。
46. 作为访客，我只看到同一本地化视图中存在于 `pbe`、不存在于 `latest` 的 ID。
47. 作为访客，我不会把已有实体的名称、说明、数值或媒体调整误认为新增。
48. 作为访客，我可以从新增实体进入其详情页。
49. 作为访客，我在 PBE 新增皮肤中看到按阶段展开后的有效皮肤资料项。
50. 作为访客，我看到的 PBE 新增结果使用稳定排序。
51. 作为访客，当某一分类没有新增内容时，会看到明确的空状态。
52. 作为访客，当全部分类都没有新增内容时，会看到页面级空状态，而不是错误。

### 质量与可访问性

53. 作为键盘用户，我可以访问新增页面的链接、切换项和第三方入口。
54. 作为屏幕阅读器用户，我可以理解图片、皮肤本体项的非炫彩状态和各数据分区。
55. 作为移动端用户，我可以完整读取所有新增字段与操作，不发生关键内容截断。

## Implementation Decisions

1. 建立一个高层、纯函数式的资料投影边界：输入为已校验的数据通道与本地化视图记录，输出为页面直接消费的视图模型。页面只负责组装与展示。
2. 字段选择、缺失值处理、稳定排序、阶段展开与继承、关联索引和 `pbe` 差集计算必须集中在领域层，不能分散到页面组件。
3. 英雄、皮肤、皮肤系列和皮肤宇宙必须使用稳定 ID 建立关系；展示名只用于显示，不作为关联主键。
4. 阶段展开规则：
   - 每个有效阶段生成一个独立皮肤资料项视图模型，但不把阶段提升为 CommunityDragon 实体。
   - 阶段自己的名称与媒体优先。
   - 说明、稀有度、皮肤系列和皮肤宇宙缺失时，才从同一本地化视图、同一数据通道的所属皮肤继承。
   - 无法满足同语言、同渠道继承时保持缺失并进入明确的空值展示，不跨边界补值。
5. 炫彩规则：
   - 炫彩计数只包含真正的炫彩记录。
   - 皮肤本体作为炫彩区域中的独立展示项，其领域状态为 `skin-self`，不是炫彩；可见文案使用中文“默认配色”和英文 `Base`。
   - 现有颜色圆点组件增加可识别的非炫彩状态；原有炫彩默认行为保持不变。
6. PBE 新增差集以实体类型加稳定 ID 为键，在同一本地化视图内比较 `pbe` 与 `latest`；不得根据名称、媒体 URL 或字段内容判断新增。
7. 皮肤详情的第三方操作由页面语言与本地化视图策略统一生成：
   - 英文 / `default`：SkinSpotlights 搜索、Teemo.GG 模型。
   - 简体中文 / `zh_cn`：不够够语音站英雄页、哔哩哔哩皮肤视频搜索、不够够 3D 模型。
8. 允许对现有“避免完整皮肤集合”决策做窄范围例外：
   - 仅皮肤系列详情、皮肤宇宙详情和 PBE 新增页可以显式请求完整皮肤数据。
   - 首页、臻彩详情、博客、英雄目录、英雄详情和皮肤详情不得因此默认加载完整皮肤数据。
   - PBE 新增页只加载同一本地化视图的 `pbe` 与 `latest` 完整皮肤数据。
   - 皮肤系列和皮肤宇宙详情只加载当前选定数据通道与本地化视图所需的完整皮肤数据。
9. 运行时读取保持浏览器直连 CommunityDragon，不增加数据库、代理 API、持久缓存或构建时在线依赖。
10. 实施时必须更新与上述窄范围例外冲突的既有架构决策记录，并清楚说明适用页面，避免把例外扩散为全站默认行为。
11. 新页面需同时提供英文和简体中文路由、标题、说明、空状态、错误状态、SEO 元数据和结构化数据。
12. 运行时错误应按现有错误模型区分网络、HTTP、解析和数据契约错误；不得用静默默认值掩盖非法数据。
13. 技术层保留 `pbe`、`latest`、`default` 和 `zh_cn`；玩家界面将 `pbe` 显示为 `PBE`，将 `latest` 显示为中文“正式服”或英文 `Live`。`default` 与 `zh_cn` 不作为服务器名称展示；需要说明页面语言时使用 `English` 或“简体中文”。
14. “英雄默认外观”“炫彩所属皮肤”“皮肤本体项”和“皮肤阶段”属于领域词。玩家界面分别使用“原皮/默认皮肤”“所属皮肤或具体皮肤名”“默认配色/`Base`”以及来源提供的“阶段/形态”名称。

## Testing Decisions

1. 以资料投影边界作为主要单元测试 seam，覆盖字段映射、缺失值、稳定排序和语言/渠道隔离。
2. 为阶段展开建立表驱动测试，至少覆盖：
   - 阶段字段完整；
   - 阶段缺少可继承字段；
   - 阶段媒体覆盖所属皮肤；
   - 禁止跨语言或跨渠道继承；
   - 无效或重复阶段。
3. 为炫彩规则测试“计数不含皮肤本体项”“皮肤本体项仍显示”“皮肤本体项状态不是炫彩”“真正炫彩保留颜色”。
4. 为 PBE 新增差集测试四类实体，覆盖新增 ID、已有 ID 字段变化、空分类、全部为空和稳定排序。
5. 为关联索引测试英雄、皮肤系列、皮肤宇宙到包含阶段资料项的皮肤集合之完整反向关系。
6. 为第三方操作测试英文 / `default` 与简体中文 / `zh_cn` URL、查询编码、缺失 ID，以及两组入口不互相泄漏。
7. 为运行时数据访问测试请求范围，确保完整皮肤数据只在获准页面加载。
8. 为客户端控制器与 DOM 绑定测试加载、成功、空状态、错误、切换、键盘操作和重复初始化。
9. 为构建产物测试新增中英文路由、canonical、alternate、robots 和 sitemap。
10. 使用浏览器验收桌面端与移动端，重点检查长文本、图片替代文本、焦点状态、皮肤本体项非炫彩标识和第三方链接。
11. 最终验证至少运行相关 Vitest、类型检查和发布构建；如修改静态目录数据，再运行数据校验。
12. 用户可见 DOM 测试必须区分技术 token 与显示名：URL 和数据请求继续使用 `pbe` / `latest`，中文界面显示 `PBE` / “正式服”，英文界面显示 `PBE` / `Live`。

## Out of Scope

- 不修改首页。
- 不修改现有臻彩详情页的内容与行为。
- 不修改博客系统或既有文章。
- 不新增独立皮肤目录页。
- 不复制参考项目的架构、组件组织、样式或视觉布局。
- 不把已有实体的 PBE 字段变化做成变更日志。
- 不增加运行时数据库、服务端代理或自建数据 API。
- 不保存 CommunityDragon 的完整 JSON 到 `public/`。
- 不抓取或托管第三方网站的视频、语音或 3D 模型。
