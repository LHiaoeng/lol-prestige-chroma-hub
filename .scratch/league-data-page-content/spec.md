# 英雄联盟资料页面内容补齐规格

## Problem Statement

项目当前已经完成 CommunityDragon 运行时资料的基础链路：英雄、皮肤系列和皮肤宇宙具有独立目录与详情壳，皮肤具有独立详情壳；浏览器按 `pbe` / `latest` 数据通道和 `default` / `zh_cn` 本地化视图读取资料，并具备参数校验、普通链接导航、加载、失败、重试、取消和详情 `noindex` 行为。

现有实现仍只是基础资料浏览器，与已确认的页面信息范围存在以下差距：

1. 英雄目录未在卡片中展示英雄定位；英雄详情展示的是头像、称号、简介和皮肤名称链接，尚未按目标展示全部皮肤的缩略图和稀有度，也需要移除不属于页面契约的默认外观展示和完成状态文案。
2. 皮肤系列详情只展示所属皮肤宇宙，皮肤宇宙详情只展示所属皮肤系列；两者都没有目标要求的关联皮肤集合。
3. 皮肤详情已有名称、部分媒体、描述、阶段、炫彩和系列/宇宙关系，但缺少本地化稀有度、完整媒体、历史版本原画、皮肤本体项、炫彩颜色、阶段独立目标和分语言第三方入口。
4. 当前皮肤阶段只嵌套显示在所属皮肤详情中，且会为缺少来源名称的阶段生成名称；这不符合“只有有效 ID 才形成资料项、不补造来源事实”的确认规则。
5. 尚无 PBE 新增页面，也没有在同一本地化视图内比较 `pbe` 与 `latest` 实体 ID 的能力。
6. 当前 ADR 禁止在皮肤系列和皮肤宇宙详情读取完整皮肤集合，也未允许 PBE 新增页比较完整皮肤集合；目标信息范围需要对该约束作明确、有限的修订。

本规格以当前代码为实施基线，只补齐页面展示信息及其必要领域能力，不复制两个 Skin Explorer 参考项目的架构、组件组织或视觉设计。

## Solution

保留现有 Astro 静态页面壳、浏览器运行时 CommunityDragon 数据边界、独立目录/详情路由、数据通道切换、本地化视图隔离和错误模型。扩展当前运行时领域投影，使各页面严格展示《英雄联盟资料页面信息规范》确认的字段：

1. 英雄目录展示名称、头像和定位；英雄详情展示名称，以及该英雄全部皮肤的名称、数据源正方形缩略图和本地化稀有度，默认按发布顺序并可按稀有度排序，成功后不显示完成状态文案。
2. 皮肤系列目录只展示系列名称；系列详情展示系列名称、所属皮肤宇宙，以及系列内皮肤的名称、缩略图和本地化稀有度。
3. 皮肤宇宙目录展示宇宙名称及其包含的皮肤系列名称；宇宙详情展示名称、描述、所属皮肤系列，以及按系列归类的皮肤名称、缩略图和本地化稀有度。
4. 皮肤详情展示名称、稀有度、描述、所属英雄、皮肤系列、皮肤宇宙、完整媒体、历史版本原画、阶段、皮肤本体项、真正的炫彩及对应第三方入口。
5. 新增独立 PBE 新增页面，展示 PBE 与正式服版本信息、总数与分类数量，以及新增英雄、皮肤、皮肤系列和皮肤宇宙。

关联、差集和阶段身份只使用来源提供的稳定数字 ID。英文页面只使用 `default`，简体中文页面只使用 `zh_cn`；缺失事实不跨本地化视图或数据通道补值。首页、臻彩详情和博客保持不变。

实施拆分为 8 个本地工单；第一项建立其余页面共同使用的运行时资料投影与查询 seam，后续工单按当前页面边界补齐用户结果，最后一项负责文档、公开产物和真实浏览器验收收口。

## User Stories

### 现有行为与页面边界

1. 作为访客，我希望现有英雄、皮肤系列和皮肤宇宙目录继续拥有独立页面，以便目录与详情职责保持清晰。
2. 作为访客，我希望皮肤继续只有详情入口而没有全量皮肤目录，以便站点不新增未确认的页面。
3. 作为访客，我希望目录与详情之间继续使用可复制、可刷新、可在新标签打开的普通链接，以便符合网页导航预期。
4. 作为访客，我希望从列表进入详情、切换数据通道和切换语言时保留合法实体参数，以便查看同一目标。
5. 作为访客，我希望运行时资料失败时仍看到稳定页面壳、错误说明和重试入口，以便静态站其他内容不受影响。
6. 作为禁用 JavaScript 的访客，我希望继续看到页面用途、导航和启用脚本说明，以便理解为何动态资料不可用。
7. 作为现有用户，我希望首页、臻彩详情和博客的信息、交互及 SEO 保持不变，以便本次扩展不改变图鉴主体。

### 英雄目录与详情

8. 作为访客，我希望英雄目录展示英雄名称，以便快速识别英雄。
9. 作为访客，我希望英雄目录展示英雄头像，以便通过视觉识别英雄。
10. 作为访客，我希望英雄目录直接展示英雄定位，以便无需进入详情即可了解其主要职责。
11. 作为访客，我希望继续按名称搜索、按定位筛选并使用稳定排序和分页，以便在大量英雄中查找目标。
12. 作为访客，我希望英雄详情展示英雄名称，以便确认当前实体。
13. 作为访客，我希望英雄详情不额外展示标记为 `isBase: true` 的英雄默认外观，以便页面聚焦可浏览的皮肤资料列表。
14. 作为访客，我希望英雄详情列出该英雄全部皮肤的名称，以便浏览皮肤集合。
15. 作为访客，我希望英雄详情中的每款皮肤显示缩略图，以便快速辨认外观。
16. 作为访客，我希望英雄详情中的每款皮肤显示当前本地化视图的稀有度，以便看到适用于该页面语言的数据事实。
17. 作为访客，我希望从英雄详情进入所属皮肤或有效阶段的独立详情目标，以便继续查看完整资料。
18. 作为访客，我希望缺失头像、缩略图或稀有度时看到诚实的缺失状态，以便站点不混入另一视图的数据。

### 皮肤系列

19. 作为访客，我希望皮肤系列目录展示系列名称，以便浏览系列列表。
20. 作为访客，我希望皮肤系列详情展示系列名称，以便确认当前系列。
21. 作为访客，我希望皮肤系列详情展示所属皮肤宇宙，以便理解主题与叙事世界的关系。
22. 作为访客，我希望皮肤系列详情列出该系列内全部皮肤资料项，以便从系列发现皮肤。
23. 作为访客，我希望每个系列内皮肤资料项显示名称、缩略图和本地化稀有度，以便直接辨认和比较。
24. 作为访客，我希望有效皮肤阶段作为独立资料项出现在系列集合中，以便阶段不会被隐藏在所属皮肤之下。
25. 作为访客，我希望系列内皮肤按稳定规则排序，以便刷新和切换通道后顺序可预期。
26. 作为访客，我希望系列核心资料成功但皮肤集合失败时仍能使用宇宙导航并单独重试皮肤集合，以便局部失败不清空页面。

### 皮肤宇宙

27. 作为访客，我希望皮肤宇宙目录展示宇宙名称，以便浏览宇宙列表。
28. 作为访客，我希望皮肤宇宙目录展示每个宇宙包含的皮肤系列名称，以便在进入详情前理解范围。
29. 作为访客，我希望皮肤宇宙详情展示宇宙名称和描述，以便理解其叙事设定。
30. 作为访客，我希望皮肤宇宙详情展示所属皮肤系列，以便在宇宙与系列之间导航。
31. 作为访客，我希望宇宙详情按皮肤系列归类展示皮肤，以便理解每款皮肤属于哪个系列。
32. 作为访客，我希望每个宇宙内皮肤资料项显示名称、缩略图和本地化稀有度，以便直接辨认和比较。
33. 作为访客，我希望同一皮肤不会因多个关系路径在同一分组中重复出现，以便集合准确。
34. 作为访客，我希望宇宙核心资料或系列关系成功但皮肤集合失败时仍可使用已加载内容，以便局部失败可恢复。

### 皮肤详情与阶段

35. 作为访客，我希望皮肤详情展示皮肤或阶段名称和本地化稀有度，以便识别当前外观。
36. 作为访客，我希望皮肤详情展示所属英雄、皮肤系列和皮肤宇宙，以便理解并导航其关系。
37. 作为访客，我希望皮肤详情展示来源提供的描述，以便了解该外观资料。
38. 作为访客，我希望查看聚焦原画、未裁剪原画、缩略图、载入图和动态原画，以便浏览来源实际提供的媒体。
39. 作为访客，我希望查看数据源实际提供的历史版本及对应原画，以便比较皮肤视觉变更。
40. 作为访客，我希望只有具有有效正整数 ID 的皮肤阶段形成独立资料目标，以便站点不补造阶段身份。
41. 作为访客，我希望阶段详情优先使用阶段自己的名称、媒体和炫彩，以便看到该阶段的真实资料。
42. 作为访客，我希望阶段缺少描述、稀有度、皮肤系列或皮肤宇宙时只继承同一响应中所属皮肤的对应事实，以便不跨边界混合数据。
43. 作为访客，我希望皮肤阶段 URL 同时保留所属皮肤身份和阶段 ID，以便阶段仍是皮肤子记录而不是伪装成独立实体。
44. 作为访客，我希望无效、缺失或不属于该皮肤的阶段 ID 显示链接无效，以便页面不猜测目标。

### 炫彩与皮肤本体项

45. 作为访客，我希望炫彩数量只统计真正的炫彩，以便数量语义准确。
46. 作为访客，我希望炫彩区域同时展示当前皮肤的皮肤本体项，以便在原始配色与炫彩之间比较。
47. 作为中文访客，我希望皮肤本体项显示“默认配色”，以便理解它代表当前皮肤自身。
48. 作为英文访客，我希望皮肤本体项显示 `Base`，以便理解它代表当前皮肤自身。
49. 作为屏幕阅读器用户，我希望皮肤本体项明确说明它不是炫彩，以便不会与真正炫彩混淆。
50. 作为访客，我希望皮肤本体项不显示炫彩颜色，以便视觉状态符合领域含义。
51. 作为访客，我希望真正的炫彩显示来源提供的名称、图片和颜色，以便辨认不同配色。
52. 作为现有臻彩页面用户，我希望原有颜色组件语义和表现保持不变，以便皮肤资料扩展不影响静态图鉴。

### 第三方入口

53. 作为英文皮肤详情访客，我希望通过 SkinSpotlights 按皮肤名称查找演示视频，以便查看游戏内效果。
54. 作为英文皮肤详情访客，我希望通过 Teemo.GG 查看对应英雄与皮肤的 3D 模型，以便观察模型。
55. 作为简体中文皮肤详情访客，我希望通过布锅锅语音站按英雄 ID 查看语音，以便访问国服参考资料。
56. 作为简体中文皮肤详情访客，我希望通过哔哩哔哩按中文皮肤名称查找演示视频，以便查看本地化内容。
57. 作为简体中文皮肤详情访客，我希望通过布锅锅 3D 模型站按完整皮肤 ID 查看模型，以便定位正确外观。
58. 作为访客，我希望英文和简体中文入口互不混用，以便每种本地化视图沿用对应参考项目的第三方网站。
59. 作为访客，我希望第三方链接正确编码并安全打开，以便名称中的空格或特殊字符不会破坏目标。

### PBE 新增

60. 作为访客，我希望通过独立页面查看 PBE 新增，以便集中发现尚未进入正式服的数据实体。
61. 作为访客，我希望看到 PBE 与正式服的数据通道及来源可验证的版本信息，以便理解比较基线。
62. 作为访客，我希望看到新增实体总数和四类数量，以便快速了解本轮规模。
63. 作为访客，我希望看到新增英雄的名称和头像，以便识别新增英雄。
64. 作为访客，我希望看到新增皮肤的名称、缩略图、本地化稀有度和所属英雄，以便识别新增外观。
65. 作为访客，我希望看到新增皮肤系列的名称，以便识别新增主题系列。
66. 作为访客，我希望看到新增皮肤宇宙的名称及其包含的皮肤系列，以便理解新增叙事关系。
67. 作为访客，我希望 PBE 新增只按实体类型和稳定 ID 判断，以便已有实体的名称、稀有度或媒体变化不会被误报为新增。
68. 作为访客，我希望新皮肤包含的有效阶段作为多个皮肤资料项展示，以便阶段可单独进入详情。
69. 作为访客，我希望现有皮肤新增阶段不被误报为新 CommunityDragon 实体，以便“新增”口径保持一致。
70. 作为访客，我希望每个新增实体链接到同语言 PBE 详情，以便复现比较结果。
71. 作为访客，我希望单个分类为空和全部分类为空都有明确状态，以便区分没有新增与加载失败。
72. 作为访客，我希望任何必要比较数据失败时看到可重试错误，而不是不完整结果，以便不会误判新增数量。

### 本地化、可访问性与维护

73. 作为英文访客，我希望页面只显示 `default` 本地化视图的事实，以便内容不混入简体中文记录。
74. 作为简体中文访客，我希望页面只显示 `zh_cn` 本地化视图的事实，以便内容不混入英文记录。
75. 作为访客，我希望玩家界面使用 `PBE`、中文“正式服”和英文 `Live`，以便看到游戏圈常用名称。
76. 作为键盘用户，我希望目录、详情、媒体、通道切换、重试和第三方入口都可操作，以便不依赖鼠标。
77. 作为移动端用户，我希望新增字段、分组和操作完整可读，以便不会因屏幕较窄丢失关键资料。
78. 作为维护者，我希望所有关系、阶段和差集规则集中在领域投影中，以便页面不会各自实现不同口径。
79. 作为维护者，我希望完整皮肤集合只在获准页面按需加载，以便当前轻量运行时边界不会扩散。
80. 作为维护者，我希望常规测试使用固定夹具且不访问真实 CommunityDragon，以便测试稳定可重复。

## Implementation Decisions

1. 当前 CommunityDragon 运行时资料边界继续作为主要数据 seam。扩展它对页面所需字段、完整皮肤集合和来源版本信息的校验与规范化能力，不创建第二套平行数据客户端。
2. 在运行时资料边界之上建立一个纯领域资料投影层，集中负责页面字段选择、本地化稀有度、皮肤阶段展开、继承、关系索引、PBE 差集、去重和稳定排序；DOM 视图只消费投影结果。
3. 页面公开字段以《英雄联盟资料页面信息规范》为完整清单。当前页面已展示但不在清单中的英雄称号、简介、系列图片/描述等字段不继续作为页面承诺；不得以“源数据存在”为理由自行扩展页面信息。
4. 保留当前目录/详情页面壳、查询参数路由、普通链接、详情 `noindex`、列表 canonical、数据通道切换和语言映射。阶段详情在现有皮肤详情壳中增加阶段 ID 参数，同时保留所属皮肤 ID 与英雄定位提示。
5. 英文页面固定使用 `default`，简体中文页面固定使用 `zh_cn`。任何缺失字段均保持缺失；不得跨本地化视图或跨数据通道补值。
6. CommunityDragon 实体和关系使用稳定数字 ID。名称、描述、slug、数组位置和皮肤 ID 数字格式均不得作为身份或关联依据。
7. 英雄默认外观只通过皮肤记录的 `isBase: true` 识别。`isBase` 不参与炫彩所属皮肤、系列、宇宙或阶段关系判断。
8. 稀有度按本地化视图投影：`default` 使用该视图的全球稀有度事实，`zh_cn` 使用该视图的区域稀有度事实；缺失时不互相替代。显示标签和图标必须来自同一稀有度事实。
9. 只有来源提供有效正整数 ID 的阶段才投影为独立皮肤资料项。阶段名称与媒体优先使用阶段值；不得为缺失名称生成 `Stage N` 等来源不存在的玩家文案。
10. 阶段仍是所属皮肤的子记录。阶段资料目标由英雄 ID、所属皮肤 ID 和阶段 ID 共同定位；不能把阶段 ID 当成顶层皮肤实体 ID。
11. 阶段缺少描述、稀有度、皮肤系列或皮肤宇宙时，只能继承同一数据通道、同一本地化视图、同一所属皮肤响应中的值。阶段自己的炫彩和媒体不从其他阶段继承。
12. 炫彩数量只统计真正的炫彩记录。皮肤本体项是独立展示状态，不属于炫彩、不携带颜色，也不进入数量。
13. 颜色组件增加显式非炫彩状态，只供皮肤资料中的皮肤本体项使用；已有臻彩页面在未传入该状态时保持当前行为。
14. 皮肤系列与皮肤宇宙的完整皮肤集合需要对 ADR-0002 作窄范围修订：只有系列详情、宇宙详情和 PBE 新增页可以显式请求完整皮肤资源。英雄目录/详情、运行时皮肤详情、首页、臻彩详情和博客不得因此加载完整皮肤资源。
15. 系列皮肤集合按系列 ID 直接匹配。宇宙皮肤集合先使用宇宙与系列的 ID 关系确定分组，再以皮肤的系列 ID 归类；同一分组按资料项稳定 ID 去重并排序。
16. 完整皮肤资源属于大体积按需请求，继续使用当前省略凭据、无 Referer、页面内存去重、取消和结构化错误策略；不增加持久缓存、代理、数据库或构建时联网。
17. PBE 新增固定比较同一本地化视图的 `pbe` 与 `latest`。差集键由实体类型和顶层实体 ID 组成；字段变化不构成新增。
18. 新皮肤实体可以展开为所属皮肤本体和有效阶段等多个皮肤资料项。已有皮肤实体新增阶段属于字段/子记录变化，不进入 PBE 新增实体结果。
19. PBE 与正式服版本信息必须来自可校验的 CommunityDragon 元数据；`pbe` 和 `latest` 只能作为数据通道标识，不得伪装成具体版本号。源站未提供版本值时显示明确缺失状态。
20. PBE 新增页任一必要集合失败时不得提交部分差集为完整结果；保留已成功数据仅用于重试，不对访客展示误导性总数。
21. 第三方入口由纯函数根据页面本地化视图和已校验实体字段生成。英文只生成 SkinSpotlights 与 Teemo.GG；简体中文只生成布锅锅语音站、哔哩哔哩和布锅锅 3D 模型站。
22. 第三方链接使用现有安全外链属性并正确编码参数。第三方站点不可用不影响 CommunityDragon 核心资料渲染。
23. PBE 新增采用独立中英文静态页面壳，并作为固定资料入口加入站内导航；它不是实体详情页，不生成逐实体 HTML。
24. 首页、臻彩详情、博客、静态目录 JSON 和既有臻彩 SEO 链路不参与本规格的数据投影或运行时请求。

## Testing Decisions

1. 最高测试 seam 是扩展后的运行时资料边界与领域资料投影组合：输入固定 CommunityDragon 夹具，断言页面可消费的目录、详情、关系集合和 PBE 差集，不测试内部辅助函数调用顺序。
2. 运行时资料边界测试覆盖新增字段 Schema、资产 URL、版本元数据、完整皮肤集合、安全路径、缓存去重、取消、HTTP/网络/JSON/Schema 错误，并继续证明常规皮肤详情不请求完整皮肤资源。
3. 投影测试覆盖严格字段清单、`default` / `zh_cn` 稀有度、缺失值、本地化视图隔离、稳定排序和关系去重。
4. 英雄投影测试覆盖目录名称/头像/定位、英雄详情不渲染 `isBase: true` 的默认外观、全部皮肤名称/正方形 `tilePath` 缩略图/稀有度、发布顺序与稀有度排序，以及英雄详情成功后不显示完成状态文案。
5. 阶段测试采用表驱动夹具，覆盖有效 ID、无效或缺失 ID、来源名称缺失、媒体覆盖、允许继承字段、禁止继承字段、重复阶段 ID 和不属于所属皮肤的阶段参数。
6. 炫彩测试覆盖真正炫彩计数、皮肤本体项仍显示、皮肤本体项无颜色和非炫彩无障碍说明，以及真正炫彩的名称、图片和颜色。
7. 系列与宇宙关系测试覆盖 ID 匹配、按系列分组、阶段展开、去重、稳定排序、空集合和局部失败；同时断言完整皮肤请求只发生在获准页面。
8. PBE 差集测试覆盖四类实体、新增 ID、相同 ID 字段变化、已有皮肤新增阶段、新皮肤阶段展开、分类为空、全部为空、版本信息缺失和任一必要请求失败。
9. 第三方入口测试覆盖两种本地化视图的精确网站集合、英雄 ID、完整皮肤 ID、名称编码、阶段目标，以及两组入口不互相泄漏。
10. 页面控制器和 DOM 测试继续使用可注入运行时与 History Adapter，覆盖加载、成功、非法参数、核心失败、关联失败、重试、取消、旧响应竞争、通道切换、语言切换和浏览器前进后退。
11. DOM 测试按页面信息规范断言用户可见字段，尤其验证不再显示未列入页面契约的额外资料，并避免依赖具体元素构建步骤。
12. 构建产物测试覆盖中英文 PBE 新增页面、canonical、alternate、robots、sitemap、详情 `noindex`，并证明没有新增皮肤目录或逐实体静态页面。
13. 公开产物审计证明完整 CommunityDragon JSON、运行时响应和第三方媒体副本未写入 `public/` 或构建产物。
14. 真实浏览器验收覆盖中英文英雄、系列、宇宙、皮肤、阶段和 PBE 新增路径，包括桌面端、移动端、键盘、通道切换、刷新、返回、失败重试及阻断性控制台错误。
15. 最终验证运行相关 Vitest、类型检查、数据校验和发布构建。若只修改运行时代码而未修改静态目录，数据校验仍作为发布构建链路的一部分执行。
16. 现有运行时领域测试、控制器测试、DOM 测试、URL 状态测试和构建产物测试作为测试先例；不访问真实 CommunityDragon 的常规测试规则保持不变。

## Out of Scope

- 修改首页、臻彩详情、博客、覆盖率文章或其他静态图鉴内容。
- 新增皮肤目录页或公开全量皮肤列表入口。
- 展示英雄称号、简介、背景故事、属性、技能、装备、符文、对局统计或电竞数据。
- 展示皮肤价格或自行推断可获得性。
- 复制参考项目的技术架构、组件组织、页面布局或视觉样式。
- 把阶段提升为 CommunityDragon 实体，或把现有皮肤新增阶段计为 PBE 新实体。
- 展示已有实体在 `pbe` 与 `latest` 之间的字段变化。
- 跨本地化视图或跨数据通道回退缺失字段。
- 将完整皮肤资源扩散为所有运行时页面的默认依赖。
- 新增 CommunityDragon 代理、Worker 数据 API、运行时数据库或持久浏览器缓存。
- 为运行时详情生成可索引逐实体静态 HTML。
- 抓取、代理、缓存或托管第三方网站的视频、语音和 3D 模型。

## Further Notes

- 本规格取代同目录旧版本中“英雄属性、技能、价格、可获得性”等超出已确认信息范围的内容。
- 当前代码已经实现的独立页面壳、运行时错误模型、URL 状态、本地化隔离和普通导航是基线能力，不应在后续工单中重建。
- ADR-0002 已在完整皮肤关联和 PBE 新增实施前修订；当前只允许三个明确入口按需读取完整皮肤资源，其他边界继续有效。
- “英雄默认外观”“炫彩所属皮肤”“皮肤本体项”和“皮肤阶段”必须继续使用项目领域词汇，不恢复含义模糊的“基础皮肤”。
- 当前另有独立工单处理臻彩可选补充数据错误使用 `isBase` 校验炫彩所属皮肤的问题；该缺陷不并入本规格，也不得借机修改臻彩详情内容。
