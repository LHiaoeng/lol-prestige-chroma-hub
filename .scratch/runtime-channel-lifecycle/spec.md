# 统一运行时通道加载生命周期规格

## Problem Statement

LoL Chroma Art 的两个浏览器入口都需要按 `pbe` / `latest` 数据通道加载 CommunityDragon 资料：静态臻彩详情页加载可选的英雄、所属皮肤和炫彩补充资料，运行时资料页加载英雄、皮肤、皮肤系列、皮肤宇宙及其关联资料。

这两个入口分别维护了相似但不完全相同的生命周期规则，包括当前通道、目标通道、`AbortController`、generation、防止旧响应覆盖新内容、加载中状态、失败重试、内容保留、浏览器前进后退和 History API 提交。规则分散后，修复一个入口的取消或失败行为不能自动修复另一个入口，容易产生旧内容被覆盖、URL 提前改变、重试提交错误通道或按钮状态不同步的问题。

对访客而言，通道切换应该是一个一致的网页行为：目标资料加载成功后才切换 URL 和内容；目标请求失败时保留仍然有效的内容；已经取消的请求不能重新写入页面；浏览器前进后退应该恢复对应的通道。当前实现把这些规则分布在多个调用方，维护者难以通过一个测试 seam 证明两条路径具有相同语义。

## Solution

建立一个共享的客户端运行时通道生命周期 module，把“按通道开始一次加载、取消旧加载、忽略旧结果、保留有效内容、提交成功 URL、报告失败并重试”的行为集中到一个 deep implementation 中。

静态臻彩补充页和运行时资料页继续拥有各自的资料查询、页面状态和 DOM 展示，但不再各自实现 generation、取消、成功提交和失败重试规则。两个调用方通过同一个最高层 seam 使用生命周期 module；调用方只提供目标通道、资料加载操作、成功/失败/无效状态的展示适配，以及当前页面需要的 History 行为。

`CommunityDragonRuntime` 继续负责 CommunityDragon 资源读取、缓存、Schema 校验、路径规范化和错误分类；本规格不改变它的资料 interface。生命周期 module 也不负责皮肤阶段投影、关系筛选、PBE 差集或 DOM 结构。

## User Stories

1. 作为访客，我希望首次打开运行时资料时看到当前 URL 所表达的数据通道，以便页面内容不会与分享链接不一致。
2. 作为访客，我希望首次打开静态臻彩详情的可选补充资料时看到当前 URL 所表达的数据通道，以便补充资料与静态正文的来源选择一致。
3. 作为访客，我希望从 `pbe` 切换到 `latest` 时先加载目标资料，再提交新的 URL，以便失败时不会留下虚假的地址。
4. 作为访客，我希望从 `latest` 切换到 `pbe` 时先加载目标资料，再提交新的 URL，以便两个方向拥有相同的行为。
5. 作为访客，我希望通道切换成功后页面内容、当前通道标签和 URL 同时指向目标通道，以便不会看到混合状态。
6. 作为访客，我希望通道请求失败时保留上一次成功的内容，以便短暂的 CommunityDragon 故障不会让页面失去可用资料。
7. 作为访客，我希望失败状态提供只重试当前目标通道的操作，以便重试不会意外回到旧通道或默认通道。
8. 作为访客，我希望重试成功后当前通道标签和 URL 恢复一致，以便失败提示不会残留在成功内容旁边。
9. 作为访客，我希望快速连续切换通道时只显示最后一次有效请求的结果，以便较慢的旧响应不会覆盖较新的选择。
10. 作为访客，我希望离开当前页面或开始新的导航时旧请求被取消，以便页面不会在离开后继续更新已失效的 DOM。
11. 作为访客，我希望浏览器后退恢复先前成功提交的通道，以便通道切换符合普通网页导航习惯。
12. 作为访客，我希望浏览器前进恢复之后成功提交的通道，以便前进和后退拥有对称行为。
13. 作为访客，我希望历史导航加载失败时保留最后一个已提交的有效 URL 和内容，以便浏览器状态不会停在无法展示的目标上。
14. 作为访客，我希望 URL 中显式的 `channel=pbe` 得以保留在内部导航和重试链接中，以便显式来源意图不会被静默删除。
15. 作为访客，我希望缺少 `channel` 时仍按默认 `pbe` 加载，以便旧的合法链接继续可用。
16. 作为访客，我希望非法 channel 被识别为无效链接且不发出 CommunityDragon 请求，以便页面不会猜测资料来源。
17. 作为键盘和屏幕阅读器用户，我希望加载、失败、重试和成功状态能被正确感知，以便不依赖视觉变化判断通道是否完成。
18. 作为键盘用户，我希望通道按钮在请求进行中保持可预测的焦点和可操作状态，以便不会因为旧请求返回而错乱。
19. 作为静态臻彩详情页访客，我希望可选补充资料失败时静态正文和图片仍然可用，以便运行时资料不会阻断核心图鉴内容。
20. 作为运行时资料页访客，我希望核心资料成功后独立的关联资料继续遵守旧结果保护规则，以便补充请求不会覆盖核心详情。
21. 作为维护者，我希望静态臻彩补充页和运行时资料页共享同一套取消与旧结果保护规则，以便修复一次即可减少两处回归风险。
22. 作为维护者，我希望页面调用方只描述资料加载和展示状态，不再复制 generation 与 `AbortController` 协调，以便生命周期规则集中在一个 module。
23. 作为维护者，我希望生命周期 module 能通过一个最高 seam 接受可替换的资料加载操作，以便测试不访问真实 CommunityDragon。
24. 作为维护者，我希望成功提交 URL 的时机由生命周期 module 统一决定，以便所有通道切换路径遵守“成功后提交”的规则。
25. 作为维护者，我希望生命周期 module 保留结构化错误和 `aborted` 语义，以便取消不被误报为用户可见失败。
26. 作为测试维护者，我希望用同一组行为测试覆盖两个调用方，以便静态补充页和运行时资料页不会逐渐产生不同的生命周期语义。
27. 作为测试维护者，我希望测试能够控制请求完成顺序，以便稳定验证旧响应、取消和快速切换场景。
28. 作为站点维护者，我希望本次改造不改变 CommunityDragon 的请求域名、凭据策略、缓存范围和数据通道 token，以便继续遵守现有 ADR。

## Implementation Decisions

- 新增一个共享的客户端运行时通道生命周期 module，作为两个页面入口共同使用的最高 seam。
- 生命周期 module 的 interface 以一次通道加载的外部行为为中心：开始加载、导航到目标通道、销毁当前加载、成功提交、失败重试和无效状态处理。具体的资料类型与 DOM 结构留在调用方。
- 生命周期 module 持有当前请求的 generation 和取消控制器；开始新加载、销毁页面或收到非法状态时，使旧 generation 失效并取消仍可取消的请求。
- 生命周期 module 只允许当前 generation 提交成功结果。旧响应、已取消响应和已经失效的重试回调不得改变内容、通道按钮或 URL。
- 通道切换采用先加载、后提交策略。只有目标资料成功且仍属于当前 generation 时，才更新已提交 URL、当前通道和成功内容。
- 失败时区分取消与真正失败。取消不显示失败提示；网络、HTTP、Schema、实体不存在和其他结构化错误沿用现有错误分类并交给调用方展示。
- 失败重试必须绑定失败时的目标通道和页面状态；重试不能使用后来选择的通道，也不能重复提交已经失效的历史 URL。
- 当调用方已有成功内容时，通道切换与重试失败必须保留该内容；首次加载失败可以使用调用方提供的空内容失败状态。
- History API 的成功提交规则集中在生命周期 module；调用方提供页面所需的 URL 创建方式，但不自行提前 push 或 replace 目标通道。
- 浏览器前进和后退继续作为外部导航事件进入同一生命周期 seam；历史导航失败时恢复最后一个已提交的有效 URL，避免地址栏与内容脱节。
- `channel` 缺省仍解释为 `pbe`，显式 `pbe` 与 `latest` 仍是唯一有效技术 token；本次不改变玩家界面的 `PBE`、中文“正式服”和英文 `Live` 映射。
- 静态臻彩补充页继续把运行时资料视为可失败的辅助资料；生命周期 module 不得让补充资料失败覆盖静态正文。
- 运行时资料页继续支持核心资料与关联资料的独立生命周期；本次共享的是通道加载的取消、提交和旧结果规则，不把所有关联资料合并为一个请求。
- `CommunityDragonRuntime` 继续作为资料读取 adapter，保留现有 `list`、`get`、请求去重、缓存、Schema 校验、资源路径和结构化错误行为。
- 不在生命周期 module 中加入持久缓存、轮询、自动刷新、代理、服务端请求或新的外部数据源。
- 不在本次改造中拆分完整 DOM view，不改变静态页面、运行时页面路由、SEO、sitemap、PBE 差集口径或皮肤资料项投影。
- 实现完成后删除两个调用方中已经被共享 module 取代的重复 generation、取消、成功提交和失败重试协调；不保留两套长期并存的生命周期实现。
- 遵循 ADR-0002：浏览器仍直接读取 CommunityDragon，运行时资料仍是可失败辅助资料，静态图鉴内容不依赖运行时请求完成。

## Testing Decisions

- 测试只验证外部行为：内容提交时机、URL 提交时机、旧结果保护、取消、失败分类、重试目标、历史导航和可访问状态；不绑定内部类名、Promise 缓存容器或具体 DOM 构建步骤。
- 主要测试 seam 是共享的运行时通道生命周期 module，注入可控的资料加载操作、History Adapter 和状态展示 adapter；测试不得访问真实 CommunityDragon。
- 使用一个可控制完成顺序的 fake loader，覆盖首次加载成功、首次加载失败、从 `pbe` 切换到 `latest`、从 `latest` 切换到 `pbe`、快速连续切换和旧响应晚到。
- 覆盖请求被取消后的行为：取消不会触发用户可见失败，取消后的响应不会提交内容、URL、通道标签或重试状态。
- 覆盖成功提交规则：目标请求成功前 URL 不变；目标请求成功后只提交一次目标 URL；重复导航不会产生错误的历史记录。
- 覆盖失败保留规则：已有成功内容时失败不会清空内容；首次失败可以显示失败状态；失败重试只重试失败时选择的目标通道。
- 覆盖结构化错误规则：网络、HTTP、Schema、实体不存在等错误交给调用方显示；`aborted` 不作为普通失败显示。
- 覆盖历史导航规则：后退和前进进入同一个加载 seam；历史导航失败时恢复最后一个已提交 URL；成功后内容与地址保持一致。
- 覆盖非法状态规则：缺失或非法 channel 不发出资料加载操作，并交给调用方显示无效链接状态。
- 为静态臻彩补充页保留行为测试，证明运行时补充失败不会改变静态正文，并且成功通道切换后链接和补充状态一致。
- 为运行时资料页保留行为测试，证明列表、详情和关联资料继续支持核心内容优先、局部失败和独立重试。
- 用同一组共享生命周期契约测试驱动两个调用方的 adapter，避免仅测试其中一条路径而遗漏另一条路径的集成错误。
- 继续运行现有相关 Vitest 测试、类型检查和构建审计；改造不应放宽或删除现有的取消、通道切换、重试和浏览器导航断言。
- 完成自动化验证后，至少进行一次真实浏览器验收：静态臻彩详情与运行时资料页分别执行首次加载、通道切换、失败重试、快速切换、前进和后退，并检查无阻断性控制台异常。

## Out of Scope

- 不重新设计 `CommunityDragonRuntime` 的资源读取 interface、URL 白名单、Schema、缓存键或错误分类。
- 不拆分或重写 `runtime-reference-view` 的列表、详情、PBE、媒体、关系和分页 DOM implementation。
- 不统一皮肤资料项的 identity、阶段展开、去重或排序规则；该方向另行规格化。
- 不统一所有 URL 解析与跨语言路径规则；只保证本次共享生命周期对现有 URL 行为保持兼容。
- 不增加新的运行时页面、静态页面、数据字段、外部数据源、代理、数据库或持久客户端缓存。
- 不改变 `pbe` / `latest` 的技术 token、默认通道、玩家界面文案或本地化视图规则。
- 不改变静态臻彩正文、博客、首页、SEO、sitemap、广告策略或 Cloudflare 部署流程。
- 不将运行时资料变成构建时依赖，也不让静态图鉴内容等待 CommunityDragon 请求完成。
- 不保证 CommunityDragon 源站可用；源站不可用时仍按现有结构化错误和重试行为处理。

## Further Notes

- 现有运行时架构规格已经把页面运行时控制器列为主要交互 seam；本规格是在该 seam 之上提取跨入口共享的生命周期行为，而不是改变原有页面资料边界。
- 这项改造的价值来自两个真实调用方：静态臻彩补充页和运行时资料页。它不是为了抽象一个只有单一实现的假想变化点。
- 共享 module 的 interface 应优先表达用户可观察的状态转移，而不是暴露页面模式、资料实体种类或 DOM slot；这样可以提高 depth、leverage 和 locality。
- 实现时若发现两个调用方的失败保留语义确实不同，应保留统一的取消与 generation 规则，并把差异限制在调用方的状态展示 adapter 中。
- 如果实现需要改变 ADR-0002 中的浏览器直接读取、静态/运行时资料边界或缓存策略，应先另行记录 ADR，不在本规格中隐式扩大范围。
