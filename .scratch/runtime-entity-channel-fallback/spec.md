# 运行时实体详情的跨通道缺失回退

## Problem Statement

访客在 PBE 独有皮肤详情页使用版本切换控件查看正式服时，当前页面会保留 PBE 皮肤的数字 ID，只把数据通道改为 `latest`。该皮肤在目标通道不存在，因而访客无法到达可阅读的正式服资料。英雄、皮肤系列和皮肤宇宙等 CommunityDragon 实体也可能只存在于一个数据通道；今后新增实体类型时，同样可能出现此问题。

数字 ID 是跨数据通道的共享身份，但共享身份不保证每个通道都存在对应实体。通道切换需要区分“目标通道明确没有该实体”与网络、校验或其他加载失败，选择有效的目标页面，同时继续遵守先确认目标资料、后更新页面与 URL 的既有规则。

## Solution

在所有运行时实体详情页共用的版本切换流程中，先查询当前本地化视图下的目标通道。若同一实体存在，就显示目标通道的详情；若明确不存在，就进入该实体预先声明的目标通道回退页面，并说明为何离开详情页。皮肤优先回退到所属英雄详情；该英雄也不存在时进入英雄目录。英雄、皮肤系列和皮肤宇宙分别回退到自身目录。

网络、响应校验等失败不触发缺失回退，仍保留当前已成功加载的资料和 URL，提供重试。新增运行时实体类型必须同时定义其详情路由和缺失回退规则，并经过同一切换流程。

## User Stories

1. 作为访客，我希望 PBE 独有皮肤切到正式服时能看到所属英雄的正式服资料，以便继续浏览已有内容。
2. 作为访客，我希望所属英雄也不在正式服时进入正式服英雄目录，以便不会到达另一个不存在的详情。
3. 作为访客，我希望已有皮肤在两个通道都有资料时仍停留在同一皮肤详情，以便正常比较版本。
4. 作为访客，我希望 PBE 独有英雄切到正式服时进入正式服英雄目录，以便找到可用英雄。
5. 作为访客，我希望仅在一个通道存在的皮肤系列切到另一个通道时进入目标通道的皮肤系列目录，以便继续浏览。
6. 作为访客，我希望仅在一个通道存在的皮肤宇宙切到另一个通道时进入目标通道的皮肤宇宙目录，以便继续浏览。
7. 作为访客，我希望从正式服切到 PBE 时也遵守相同的存在性判断和回退规则，以便两个方向的行为一致。
8. 作为访客，我希望回退后的页面明确说明目标通道缺少原实体，以便理解为何页面发生跳转。
9. 作为英文访客，我希望目标通道及缺失提示使用英文文案，以便理解当前资料来源。
10. 作为中文访客，我希望目标通道及缺失提示使用中文文案，以便理解当前资料来源。
11. 作为访客，我希望回退目标保留当前页面语言，只读取该语言对应的本地化视图，以便不会混用两个视图的资料。
12. 作为访客，我希望切换期间继续看到原有资料，直到目标实体或回退目标确认可用，以便没有短暂的无效详情。
13. 作为访客，我希望网络故障或资料格式错误时仍停留在原详情页并重试，以便故障不会被误判为实体不存在。
14. 作为访客，我希望连续快速切换时只有最后一次有效操作决定页面和 URL，以便过期响应不会带我去错误的页面。
15. 作为访客，我希望回退后使用浏览器后退能返回原详情页，以便符合普通网页导航习惯。
16. 作为访客，我希望回退目标的链接可以刷新、复制和在新标签页打开，以便导航结果稳定。
17. 作为键盘用户，我希望仍能操作版本切换控件并读到缺失提示，以便不依赖鼠标。
18. 作为访客，我希望直接打开一个不存在的详情 URL 时看到明确缺失状态，以便能识别无效链接；该行为不应被误认为我主动切换了通道。
19. 作为维护者，我希望新增运行时实体类型时必须声明其详情路由和缺失回退目标，以便不会默默沿用无效实体 ID。
20. 作为维护者，我希望所有实体共用存在、缺失和请求失败的切换规则，以便修复一次即可覆盖现有和后续实体。

## Implementation Decisions

- 保留现有 Astro 静态页面壳、浏览器运行时 CommunityDragon 读取、`pbe` / `latest` token、数字 ID 身份和 `default` / `zh_cn` 本地化视图隔离。不得从另一通道或另一视图拼补缺失实体。
- 共享版本切换流程以目标通道的实体查询结果为依据。只有明确的实体不存在结果进入回退分支；网络故障、取消、非法响应和其他错误沿用现有失败与重试语义。
- 同一实体存在时，沿用现有详情页加载、取消、迟到响应保护、成功后提交 URL 和 History 行为。目标缺失时，先确认回退目标可用，再以普通跨页面导航进入该目标通道；回退本身也不得提交一个不存在的实体详情 URL。
- 皮肤使用当前详情已知的所属英雄数字 ID 定位回退目标；若目标通道没有该英雄，进入英雄目录。皮肤详情与英雄详情不得为此加载完整皮肤集合。
- 英雄、皮肤系列和皮肤宇宙缺失时，分别进入对应目录。目录 URL 明确表达目标通道；页面语言保持不变。
- 回退原因提供中英文可访问提示。提示不应依赖原页面未提交的瞬时 DOM 状态，刷新回退目标后仍应能理解当前通道和所处页面；具体呈现复用现有页面状态与提示组件。
- 实体类型与回退目标的映射采用穷尽类型检查。新增实体类型未定义路由或回退规则时，类型检查必须失败；不要在共享流程设置静默的默认回退路径。
- 直接访问一个不存在的详情 URL，继续显示明确缺失状态；回退规则仅适用于访客从已加载详情主动切换数据通道。
- 不改变静态臻彩详情的正文、SEO、数据源或通道补充资料行为；不改变 PBE 新增比较页的差集定义。

## Testing Decisions

- 优先使用现有可注入运行时资料服务与 History 的页面控制器测试入口，覆盖从版本切换动作到目标资料、URL、渲染或跨页面导航的外部行为；跨页面导航若需注入，仅在该高层入口增设最小接口。不要分别测试内部条件分支来代替完整行为。
- 用固定夹具覆盖四种现有实体：目标通道存在、目标通道明确不存在、皮肤和所属英雄均不存在、网络或校验失败。断言目标通道、页面语言、最终地址、原 URL 保留或提交，以及重试结果。
- 覆盖两个切换方向、过期响应、快速连续切换、浏览器返回，以及直接打开缺失详情 URL 不触发回退。
- 以现有运行时页面控制器、通道生命周期和 DOM view 的相邻测试为先例；验证缺失提示的中英文文本与可访问呈现，不把测试绑在具体 DOM 内部结构上。
- 代码验证先运行相关 Vitest 测试，再运行类型检查。真实页面验收至少覆盖中英文 PBE 独有皮肤切向正式服、正常存在实体、回退提示、键盘操作、刷新与返回，并观察窄屏布局及控制台错误。

## Out of Scope

- 不新增全量皮肤目录、站点运行时数据库、代理或持久缓存。
- 不展示或合并两个数据通道之间的字段变化；此规则只判断实体是否存在。
- 不改变 PBE 新增列表、静态臻彩图鉴、第三方入口或实体详情的 SEO 收录规则。
- 不为未来尚未定义的实体类型预设具体页面或回退层级；新增时必须显式声明。

## Further Notes

- 本规格细化主动切换时的缺失行为。既有“目标加载失败保留旧内容和 URL”仍适用于故障；既有“目标实体不存在显示明确状态”仍适用于直接打开缺失详情 URL。
- 预期主要测试 seam 是运行时页面控制器及其可注入的服务、History 和必要的跨页面导航适配。该 seam 与既有测试组织一致，能观察用户最终到达的页面，而非只检查一个路由计算函数。

- 相关控制器与生命周期测试 46 项通过；新增 DOM 测试 3 项通过；`git diff --check` 通过。

- 全量 DOM 测试仍有 3 项既有失败，类型检查仍有 7 处既有错误；这些问题不在本规格改动文件中。
