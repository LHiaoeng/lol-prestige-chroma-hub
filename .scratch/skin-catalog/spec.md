# 双语皮肤目录

## Problem Statement

访客目前只能从英雄、皮肤系列或皮肤宇宙逐步找到皮肤资料，无法在一个目录中跨英雄浏览皮肤，按皮肤稀有度筛选，或按英雄名称排序。现有皮肤卡片也没有用户给出的竖版原画和底边居中稀有度宝石的目录展示方式。

## Solution

新增中英文皮肤目录，浏览器按当前数据通道和本地化视图读取 CommunityDragon 的完整皮肤集合，并以复刻 Antdv Next Listy 行为和样式的虚拟列表展示。页面按用户截图组织搜索、按英雄／按系列入口、平铺稀有度筛选、命中数／总数、排序和竖版卡片；新目录卡片可显示来源提供的皮肤边框，底边中点显示稀有度图标。页面沿用本站暗色金色主题和 Astro 静态站架构。

## User Stories

1. 作为中文访客，我希望在中文皮肤目录浏览当前资料版本的皮肤，以便集中查找皮肤。
2. 作为英文访客，我希望在英文皮肤目录浏览对应本地化视图，以便理解皮肤名称和稀有度。
3. 作为访客，我希望从站点导航进入皮肤目录，以便无需先打开英雄详情。
4. 作为访客，我希望从皮肤详情返回本语言皮肤目录，以便继续浏览。
5. 作为访客，我希望切换 PBE 和正式服／Live，以便查看各数据通道实际提供的皮肤。
6. 作为访客，我希望皮肤目录展示非默认皮肤，以便结果不被英雄默认外观占据。
7. 作为访客，我希望有效皮肤阶段各有独立卡片和可打开的详情，以便找到特定阶段。
8. 作为访客，我希望同一皮肤或阶段只出现一次，以便数量和结果不重复。
9. 作为访客，我希望按当前语言的英雄名称升序或降序排列，以便按英雄查找。
10. 作为访客，我希望同一英雄的皮肤顺序稳定，以便切换排序后仍容易定位。
11. 作为访客，我希望在搜索框输入英雄名或皮肤名，以便快速缩小结果。
12. 作为访客，我希望搜索忽略大小写和首尾空格，以便常见输入方式都能找到结果。
13. 作为访客，我希望同时选择多个稀有度，以便比较不同等级的皮肤。
14. 作为访客，我希望“全部”清除稀有度限制，以便恢复完整结果。
15. 作为访客，我希望把“未标注”与其他稀有度一起选中，以便包含来源未给出稀有度的皮肤。
16. 作为访客，我希望筛选只使用当前本地化视图的稀有度事实，以便不混入另一视图的品质判断。
17. 作为访客，我希望看到筛选和搜索命中数及当前版本总数，以便理解结果范围。
18. 作为访客，我希望搜索、筛选和排序共同作用，以便精确查找。
19. 作为访客，我希望复制目录 URL 后恢复搜索、筛选、排序与数据通道，以便分享结果。
20. 作为访客，我希望浏览器前进和后退恢复目录条件，以便按网页导航习惯探索。
21. 作为访客，我希望切换数据通道时保留已选条件，并按目标通道重新计算结果，以便比较。
22. 作为访客，我希望滚动大量皮肤时页面保持流畅，以便在手机上浏览完整目录。
23. 作为访客，我希望在手机宽度足够时每行看到三张竖版卡片，以便得到接近参考截图的密度。
24. 作为极窄屏访客，我希望卡片改为两列，以便文字和触控区域仍可使用。
25. 作为桌面访客，我希望容器宽度增加时卡片列数相应增加，以便充分利用屏幕。
26. 作为访客，我希望卡片显示竖版载入图和来源可用的皮肤边框，以便快速识别皮肤外观。
27. 作为访客，我希望缺少载入图或边框时仍有可识别的图片或占位状态，以便卡片不消失。
28. 作为访客，我希望皮肤名清晰可读，并能打开对应皮肤或阶段详情，以便继续查看资料。
29. 作为访客，我希望有稀有度图标的卡片在底边中点显示宝石并提示其名称，以便识别品质。
30. 作为访客，我希望没有稀有度图标的卡片保留完整底边，以便不出现虚假的品质标记。
31. 作为访客，我希望在目录中打开现有皮肤系列入口，以便按系列继续浏览。
32. 作为访客，我希望资料加载时看到与结果区域相称的占位和状态文字，以便知道页面正在工作。
33. 作为访客，我希望资料为空或筛选无结果时看到明确提示，以便区分没有结果和加载失败。
34. 作为访客，我希望 CommunityDragon 请求失败时看到错误与重试操作，以便恢复浏览。
35. 作为访客，我希望切换版本失败时已加载的结果和 URL 不被错误的新状态覆盖，以便继续使用目录。
36. 作为键盘用户，我希望能操作搜索、筛选、排序、版本切换、虚拟列表和卡片链接，以便不依赖鼠标。
37. 作为使用辅助技术的访客，我希望图标、结果数量和加载状态有可理解的文字，以便获得与视觉用户等价的信息。
38. 作为搜索引擎访客，我希望目录有可索引的中英文页面壳、标题与导航，以便发现这个入口。

## Implementation Decisions

- 延续 Astro 静态站和浏览器运行时资料架构；不引入 Vue 或 Antdv Next 运行时。按官方 Listy 的结构、尺寸、间距、虚拟滚动与交互状态在现有组件体系内复刻，颜色及字体使用本站 Antdv Next 暗色金色 Token；按上游版本核对源码与许可要求。
- 皮肤目录是完整皮肤集合的新按需消费者，不让首页、英雄页、皮肤详情或博客默认请求该大体积资源。此边界由“增加运行时皮肤目录”ADR 修订；数据仍来自当前通道的 CommunityDragon，而非臻彩图鉴 JSON 或构建快照。
- 中英文各有独立列表路由和规范 URL；加入现有英雄联盟导航。皮肤详情的面包屑或返回入口指向当前语言的皮肤目录，皮肤详情本身仍走既有实体请求；跨通道缺失实体的回退规则不变。
- 复用现有运行时资料投影处理皮肤、有效阶段、身份去重和阶段覆盖。排除英雄默认外观；阶段保留所属皮肤身份并打开对应详情。皮肤集合按英雄 ID 与英雄摘要关联本语言名称，用于显示、搜索和排序。
- 本地化视图相互隔离：英文使用来源 `rarity`，中文使用 `regionRarityId`，阶段沿用既有稀有度继承规则；缺失事实为“未标注”，来源明确标记的“未知”不是“未标注”。不从另一视图或通道补值。
- 页面按参考截图安排分段式“按英雄／按系列”入口、搜索、资料版本、平铺稀有度多选、数量、英雄排序与卡片区；“按系列”进入现有系列目录。保持站点页面模板要求的标题、面包屑和共享导航。
- 稀有度选项以当前视图来源提供的类别为准，支持多选；“全部”表示无筛选，“未标注”可与具体类别组合。搜索匹配当前语言的英雄名和皮肤名，忽略大小写及首尾空格。过滤与搜索取交集；默认按英雄名升序，可切换降序，同英雄使用稳定顺序。
- 搜索、稀有度选择、排序和数据通道写入 URL；直接打开链接、刷新、前进和后退恢复状态。对 URL 参数进行明确校验，保持现有通道切换的取消、迟到响应保护、失败保留和成功后提交规则。
- 数量展示命中卡片数和当前数据通道的目录总卡片数；阶段单独计数。排序不改变数量，切换通道后按目标通道重新计算，并保留仍适用的用户选择。
- Listy 在固定高度滚动区域中以虚拟行承载响应式多列卡片。手机宽度足够时三列，极窄屏两列，桌面随版心增加列数；列数改变时维持正确的可见行、滚动与键盘访问。
- 新目录卡片使用竖版载入图，来源有可用边框时显示边框；资源缺失时回退到合适原画或占位。卡片显示皮肤名称；有图标时把当前视图的稀有度宝石置于底边中点，并提供可由悬停和键盘聚焦读取的名称提示。无图标时不留假图标。
- 竖版卡片仅用于新目录，其他页面共享皮肤卡片布局不变。参考图中的“已拥有／日期”、三种视图切换、炫彩页签及“显示未解锁”不进入本页。
- 页面壳允许索引，提供中英文标题、描述、canonical、alternate 和目录语义；运行时皮肤条目不伪装为构建时可抓取内容。列表使用现有加载、空结果、失败、重试和版本切换呈现规则。

## Testing Decisions

- 主要测试 seam 是皮肤目录的浏览器页面行为入口：以固定 CommunityDragon 响应、可注入请求和 History 驱动加载、搜索、筛选、排序、通道切换与滚动，断言访客看到的卡片、数量、链接、状态和 URL。优先沿用现有运行时页面控制器和 DOM view 测试做法，避免为每个内部辅助函数建立重复测试。
- 在同一高层 seam 覆盖中文／英文视图、英雄名称排序、非默认皮肤与阶段计数、稀有度多选和未标注、搜索交集、直接打开分享 URL、前进后退、重试及旧请求迟到。使用小型固定夹具，不在自动测试中请求真实 CommunityDragon。
- 虚拟列表测试验证可见区域只生成必要卡片、滚动后更新可见结果、响应式列数变化不漏项，并检查卡片链接和键盘可达性；测试外部行为而不是内部行号或计算细节。
- 沿用现有运行时资料投影、运行时 URL、页面控制器、SEO 的相邻测试先例。若一个边界无法由主 seam 可靠观察，只为该边界补最小的纯领域或 SEO 测试，不复制实现步骤。
- 验证先运行相关 Vitest 测试和类型检查；发布范围按项目要求运行构建与产物审计。真实页面检查中英文、手机三列与极窄屏两列、桌面宽度、长列表滚动、键盘焦点、加载／空结果／失败／重试及资料版本切换。

## Out of Scope

- 不建立账号、玩家持有状态、解锁日期或个人藏品清单；不把截图中的个人记录冒充本站事实。
- 不新增皮肤系列的第二套分组列表，也不新增三种视图切换或炫彩目录页签。
- 不改变现有英雄、系列、宇宙和 PBE 页的皮肤卡片布局。
- 不把完整皮肤集合写入静态臻彩目录、公开 JSON、运行时数据库或本站代理；不引入新的构建时远程依赖。
- 不生成每款皮肤的静态 SEO 详情或承诺搜索引擎能索引浏览器渲染的每张卡片。

## Further Notes

- 视觉参考是本次讨论中用户提供的手机截图：采用目录信息层级、竖版卡片密度与底边宝石位置；具体控件遵守本站主题和可访问性要求。截图未随规格复制到仓库。
- 当前完整皮肤集合体积明显大于普通列表资源；虚拟化控制 DOM 规模，不能缩小网络响应。加载和失败状态需要对这一限制保持清楚的反馈。
- 首选测试 seam 是目录页面的可观察行为入口，覆盖资料、筛选、URL 与虚拟滚动的组合；只有无法在此稳定观察的边界才增加更低层测试。
