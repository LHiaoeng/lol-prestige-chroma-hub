# 全站主题切换与 Antdv Next GitHub 源码对齐

## Problem Statement

LoL Chroma Art 目前全站固定使用暗色金色主题。访客无法从 Header 选择跟随系统、浅色或暗色。现有 CSS 变量建立在单套暗色输出上，增加主题选择后，静态图鉴内容、运行时资料和共享组件都需要在同一生效主题下呈现。维护者需要能从锁定的 GitHub 源码追溯菜单行为、主题推导和组件状态。

## Solution

在全站 Header 提供「跟随系统」「浅色主题」「暗黑主题」三项选择。保存用户偏好，并在首屏恢复生效主题。沿用 LoL Chroma Art 的品牌金和原画视觉，按锁定版本 Antdv Next 的浅暗算法输出建立两套语义 Token，并让静态和动态渲染共用。用实际页面的 Header 菜单验收完整切换行为，再在代表页核对计算样式。

## User Stories

1. 作为桌面访客，我希望悬停 Header 主题按钮时打开靠右对齐的菜单，以便快速查看主题选项。
2. 作为手机访客，我希望轻触主题按钮就能打开菜单，以便在没有鼠标的情况下切换。
3. 作为键盘用户，我希望能打开菜单、移动焦点、确认选项和按 Escape 关闭，以便独立完成切换。
4. 作为读屏用户，我希望能获知按钮用途、菜单开合和当前选项，以便辨认已保存的偏好。
5. 作为中文访客，我希望主题菜单使用中文名称，以便理解三个选项。
6. 作为英文访客，我希望菜单和可访问名称使用英文，以便理解相同的设置。
7. 作为选择跟随系统的访客，我希望菜单始终标记「跟随系统」，以便辨认目前采用的是系统偏好。
8. 作为选择跟随系统的访客，我希望系统改色后当前页面随之更新，以便与设备外观一致。
9. 作为明确选择浅色或暗色的访客，我希望系统改色时页面保持我的选择，以便保留手动偏好。
10. 作为希望在明亮环境中阅读的访客，我希望能明确选择浅色，以便舒服地浏览页面。
11. 作为习惯本站暗色外观的访客，我希望能明确选择暗色，以便继续使用熟悉的配色。
12. 作为回访者，我希望刷新和重新进入网站时恢复上次选择，以便免于重复设置。
13. 作为跨页浏览者，我希望切换页面和语言时继续使用当前偏好，以便保持阅读连贯。
14. 作为选择与当前外观相同的偏好的访客，我希望选中标记和保存值仍能更新，以便后续按新偏好生效。
15. 作为访客，我希望首屏直接呈现应生效的主题，以便避免看到另一套配色闪过。
16. 作为浏览器存储受限的访客，我希望当前页仍能切换主题，以便继续使用页面。
17. 作为启用了减少动态效果的访客，我希望主题直接切换，以便避免不必要的动画。
18. 作为图鉴访客，我希望卡片、筛选器、弹层和骨架屏使用一致的主题，以便识别内容和交互状态。
19. 作为运行时资料访客，我希望切换后才加载的内容也使用新主题，以便浏览器渲染的结果与页面一致。
20. 作为原画和博客读者，我希望两套主题都能清楚显示封面叠字、正文和焦点，以便继续阅读和操作。
21. 作为维护者，我希望能从固定提交追溯每套 Token 和组件状态的来源，以便核对实现和处理后续升级。
22. 作为维护者，我希望主题选择只依赖本站静态资源和浏览器能力，以便保留现有部署、路由和数据边界。
23. 作为同时打开多个标签页的访客，我希望从一个标签页更改主题后，其他同源标签页也立即采用该偏好，以便跨标签浏览时配色一致。

## Implementation Decisions

- 使用 Antdv Next 固定提交 `839bec66f18a78eeef5c6843b78ea4a54d73b248`。对照官网 Header 主题入口、偏好存储、首屏初始化、系统监听和切换逻辑，再对照组件库算法、语义 Token、Dropdown／Menu 和受影响组件的样式。实施时记录固定源码位置、上游表现、本站实现与可复现验收结果。
- 在共享 Header 复用仅图标的文字按钮和 Dropdown。主题按钮排在语言切换右侧，位于 Header 控件组最右端。桌面与手机保持同一顺序，窄屏沿用现有小号图标按钮并保留主题入口。桌面悬停、右下对齐，沿用已有视口避让和键盘、触屏激活规则。三项按系统、浅色、暗色排序，依次使用 SyncOutlined、SunOutlined、MoonOutlined。对照上游入口图形和菜单项几何。仅当前主题偏好显示右侧 6px 圆点，并公开单选状态。圆点尺寸与位置对齐上游，本站改用生效主题的强调金色，浅色为 `#8A6B38`，暗色为 `#D7B56D`。触发器有双语可访问名称，Escape 恢复触发器焦点，选项确认沿用共享菜单关闭与焦点规则。
- 主题偏好为 `system`、`light` 或 `dark`，生效主题为浅色或暗色。只在跟随系统时响应系统配色变化。重新选择相同方案时仍按用户选择更新偏好及可访问选中状态。
- 默认偏好为 `dark`。首次访问、无保存值或保存值无效时，页面直接以暗色呈现，菜单选中「暗黑主题」，与系统配色无关。这是相对官网默认浅色的项目差异。存储不可用时支持当前页面切换，刷新后使用可解析的偏好或本站默认值。无脚本时以暗色静态样式呈现，页面内容和原有导航可用。
- 首屏先解析偏好及系统色彩，再让页面绘制。根节点的生效主题和浏览器 `color-scheme` 同步，浏览器主题色与当前背景一致。共享页面布局为主题状态的应用入口，主题偏好跨站内页面和语言共用。同一浏览器的同源标签页同步主题偏好，接收页直接更新选中项和生效主题。
- 对照上游在浅色使用 `defaultAlgorithm`、暗色组合 `defaultAlgorithm` 与 `darkAlgorithm` 的输出。鼠标或触屏选中且具有有效指针起点时，支持 View Transition 的浏览器按上游效果从点击点展开圆形过渡。键盘选择、系统改色、跨标签同步、启用减少动态效果和不支持过渡的场景直接生效。过渡失败或快速连续切换时，以最后选择为准并恢复正常交互。
- 离线核对 Seed、Map、Alias 和组件 Token，使用共享 CSS 变量发布两套主题。覆盖页面、容器、浮层、正文层级、边框、填充、阴影、反色前景、状态色与交互色阶。以现有亮金 Chroma Gold `#D7B56D` 为唯一品牌种子，按上游算法派生浅暗色板。两套主题的实色主按钮默认使用亮金与深字 `#141414`，暗色保留本站对派生默认主色的覆盖。浅色表面上的金色文字和焦点使用同一色板的第八阶 `#8A6B38`，暗色金色文字沿用亮金。悬停、按下等色阶按上游语义和实际相邻背景核定，记录具体输出与覆盖理由。保留现有标题层级。目录卡片名称使用主文本色，已有金色强调的详情标题按生效主题使用对应的金色文字。原画、封面和具有固定含义的领域颜色保留原有语义，媒体之上的文字和操作单独核对对比度。
- 对本站实际使用的共享组件，按变体与状态追踪「变化属性 → 上游 Token → 本站变量」。覆盖适用的默认、悬停、键盘焦点、展开、选中、按下、禁用、空、错误及加载状态。保留现有已记录的组件差异，并在两套主题下复核。新增差异须说明原因。
- 新增主题选择后更新全站设计与相邻组件文档，并补充 ADR 对静态暗色基线的修订说明。继续使用 Astro 和静态部署。主题运行时仅使用原生 DOM、浏览器 API 和 CSS 变量。Antdv Next 的 Vue 源码和算法仅作为实现对照与离线核对依据，禁止引入 Vue、Astro Vue 集成或依赖 Vue 的 Antdv Next 组件包。静态图鉴内容、运行时资料、双语路由、可索引性和数据加载边界继续遵循现有契约。

## Testing Decisions

- **主要入口为实际页面的 Header 主题菜单**。同一入口覆盖鼠标、键盘和触屏选择，观察可访问状态、选中标记、页面生效主题及刷新、跨页和切换语言后的结果。用干净存储分别在浅色和暗色系统下验证初次访问均显示暗色并选中「暗黑主题」，再模拟保存值无效、存储不可用、系统改色、同一生效主题下偏好变化、同源标签立即同步、减少动态效果、连续切换和不支持过渡。核对鼠标及触屏的动效起点，以及键盘、系统改色与接收同步时的直接切换。
- 优先扩展现有 Header 和 Dropdown 的验证方式，复用菜单焦点、位置及视口边界的现有测试先例。需要补相邻回归测试时，覆盖用户可观察的状态和结果。内部调用次数、类名和源码字符串不能单独证明交互或视觉对齐。
- 先验收组件再验收页面。以固定版本源码和两套 Token 输出为基准，用计算样式、元素边界与截图核对图标尺寸、间距、位置、颜色、阴影和状态对比。验证首页、臻彩原画图鉴、臻彩详情、运行时皮肤目录或详情、云顶目录、博客列表及文章的双语桌面和手机代表场景。覆盖首屏、弹层、动态结果、骨架屏、原生表单控件和媒体叠层。核对 Header 主题入口在两种宽度下都位于最右端并可用，核对圆点在浅暗主题及菜单悬停背景上的可辨识性，并用目录卡片和已有金色强调的详情标题验收颜色层级。按 WCAG AA 在实际背景复核普通文字至少 4.5:1，识别控件和状态所需的非文字标记至少 3:1，并覆盖可见交互态。 [文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) · [非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- 实施时检查依赖、锁文件和构建产物，确认主题功能未新增 Vue 相关依赖或客户端运行时。运行受影响的测试和仓库规定的发布检查。报告实际查验的页面、场景、刻意保留的差异，以及尚未实测的浏览器行为。

## Out of Scope

- 官网主题菜单的紧凑、欢乐、AI 主题和主题编辑器入口。
- 自定义主题编辑器、多套品牌配色、账户或跨设备同步。
- 组件库迁移、通用组件完整 API 复刻、路由和数据契约重构。

### 上游色板推算

Ant Design 的色彩规范建议以色板第六阶作为品牌主色。以现有 Chroma Gold `#D7B56D` 为唯一种子，用锁定提交依赖的 `@ant-design/colors@8.0.1` 及 Antdv Next 浅暗 Palette／Map 源码离线计算。暗色计算使用默认生成背景 `#141414`。以下为覆盖前的上游输出。 [色彩规范](https://ant.design/docs/spec/colors-cn.md) · [暗黑模式规范](https://ant.design/docs/spec/dark-cn/) · [Token 映射源码](https://github.com/antdv-next/antdv-next/blob/839bec66f18a78eeef5c6843b78ea4a54d73b248/packages/antdv-next/src/theme/themes/shared/genColorMapToken.ts)

| 上游 Token | 浅色 | 暗色 |
| --- | --- | --- |
| `colorPrimary` | `#D7B56D` | `#BA9D60` |
| `colorPrimaryHover` | `#E3CE98` | `#CEBB8B` |
| `colorPrimaryActive` | `#B08F51` | `#937D4E` |
| `colorPrimaryBg` | `#FFFDF0` | `#4F442F` |
| `colorPrimaryBgHover` | `#FFFCF0` | `#6C5C3C` |

- 亮金 `#D7B56D` 在白底上的文字对比度为 1.96:1，在暗色容器 `#141414` 上为 9.40:1。浅色文字取同一色板第八阶 `#8A6B38`，在白底、浅灰 `#F5F5F5` 和选中悬停底上的对比度分别为 4.95:1、4.54:1 和 4.82:1。
- 实色主按钮默认使用亮金填充和 `#141414` 文字，配对为 9.40:1。派生按下填充维持深字时，浅色为 6.05:1，暗色为 4.64:1。若控件识别依赖边界或焦点，按相邻背景复核相应标记的 3:1 对比度。
- 在暗色选中底 `#4F442F` 上亮金文字为 4.87:1，在选中悬停底 `#6C5C3C` 上为 3.31:1。选中悬停遵循本站 Dropdown 的主文本色规则。实施时以实际组件背景复核。

## 实施与验收结果

- Header 已加入系统、浅色、暗色主题菜单；默认偏好为 `dark`。原生 DOM 控制器实现首屏恢复、同源跨标签同步、系统偏好监听、存储失败回退与可选圆形过渡；主题语义 Token 已覆盖站内页面和共享组件。未新增 Vue、Vue 集成或 Antdv Next 组件包。
- 使用当前 Edge 复用的浏览器窗口核验首页与中英文云顶棋盘目录：菜单顺序和右侧位置、浅暗切换、跨页和语言路由、刷新保留选择、同源标签页即时同步。桌面页面截图确认浅暗背景、筛选器、卡片与输入占位文字随主题生效。
- 对比度复查后，将活动占位符、Select 分组标题和广告标签改用 `muted`，避免浅色主题使用 `disabled`／`tertiary` 的低对比度颜色。
- 已通过 34 项主题、Header、Select 与排版定向测试；`pnpm typecheck`、`pnpm build`（2153 页）和 `pnpm audit:build`（2238 个产物）通过。完整 `pnpm test` 有 644 项通过、17 项失败，集中在未改动的博客、响应式布局和站点构建断言；例如站点构建测试要求不存在 `/skins/index.html`，而当前构建实际包含该目录页。单独复跑该断言仍失败，判定为既有测试与当前页面契约不一致。
- 未实测手机视口、操作系统配色事件、无存储环境、键盘完整流程和减少动态效果下的实页行为；对应实现由单元测试和既有 Dropdown 契约覆盖。

## 审查后修复

- 新主题决策使旧过渡失效，迟到的更新回调无法覆盖新偏好。回归测试覆盖连续选择、键盘切换、跨标签同步及系统改色。
- 主题菜单保留可访问的单选状态，选中外观由右侧金点表达。PBE 标记在浅暗主题下均使用适合媒体黑色遮罩的亮金文字和内侧焦点环。
- 撤回主题规格之外的 Select 禁用分组扩展，保留既有单项禁用和分组标签的可读性修正。
- 复用现有 Edge 桌面窗口在中文皮肤目录核验浅暗菜单的选中圆点和原画上的 PBE 标记。连续切换竞态通过控制器行为测试验证。
- 71 项定向测试、类型检查、数据校验及匹配 Adsterra 构建配置的产物审计通过。全量测试 648 项通过、16 项失败，16 项失败均在基线 `f87e84b` 同名复现。
