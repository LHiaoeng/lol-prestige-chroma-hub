# 区分内容类型并显式限定广告范围

LoL Chroma Art 区分图鉴资料与原创文章；广告资格不改变内容类型，图鉴详情不会因投放广告成为原创文章。博客内容仍需经过人工维护，并在适用时标明资料来源；广告范围由共享布局默认开启、特殊页面显式排除和内容就绪条件共同约束。

2026-11-17 修订：当前先使用 Adsterra，保留 AdSense 以便后续继续申请和切换。投放包含中英文首页、博客和臻彩、英雄、皮肤、皮肤系列、皮肤宇宙详情；后续新增页面通过共享布局默认启用，无需新增路由允许名单或开启参数。运行时详情须在主资料成功加载并确有实体后才初始化广告；加载失败或实体不存在的空壳不投放。每页最多一个广告位，位于主内容后、页脚前，首期使用 300×250 Adsterra Banner。

既有 Editorial Policy、About、Privacy、错误页、PBE 新增页及当前其他目录页显式关闭广告；不由这些例外推导出未来新页面默认关闭的规则。详情页既有的索引与 sitemap 规则不因广告变化而调整，`noindex` 本身不代表禁止广告。

新页面通过 `ads={false}` 声明免广告时，共享布局输出 `data-ads-disabled` 标记，产物审计读取该声明，不要求再登记新的免广告路由。既有特殊页面的禁止投放规则仍独立校验。

广告平台由单一构建期开关 `AD_PROVIDER` 选择 `adsterra`、`adsense` 或 `none`，初始为 `adsterra`。只执行被选中平台的广告投放代码，不混投、不自动回退；页面显式关闭优先于平台选择。两种集成及已有申请验证身份可以同时保留，实际投放互斥。切换须重新构建并部署。

本修订取代原有“臻彩详情不投放广告”及可投放路由逐页登记的规则，以减少新增页面漏接广告，同时保留主内容优先和明确例外。详细行为及验收见 [广告接入规格](../../.scratch/adsterra-integration/spec.md)；首期验收仅看 Adsterra 广告正常展示，后台记录及实际到账由用户自行查看，AdSense 实际展示待具备投放条件后另行验证。广告代码已在本地实现，尚未验证真实广告素材展示或部署。
