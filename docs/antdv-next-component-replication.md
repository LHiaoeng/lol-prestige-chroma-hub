# Antdv Next 组件复刻规范

新增、重做或调整以 Antdv Next 为上游的组件时，按本文件执行。任务称“复刻组件”时，默认覆盖该组件的上游公开能力；任务只要求某项能力时，明确支持范围，并核对与它关联的状态。本站继续使用 Astro、原生浏览器 API 和 [DESIGN.md](../DESIGN.md) 定义的暗色金色主题。

## 1. 锁定上游契约

从 [DESIGN.md](../DESIGN.md) 获取锁定的 GitHub 提交。先查该提交下目标组件的实现、样式、Token 和对应示例。涉及子组件、图标或组合时，沿源码查相关依赖。[官网组件总览](https://www.antdv-next.com/components/overview-cn) 用于定位 API 和演示，出现版本差异时以锁定源码为准。

动手前明确支撑这次需求的上游示例、组件组合、变体和尺寸。在组件相邻文档中记录适用项，每项包含固定源码位置、上游表现、本站实现位置与可观察的验收结果。修改已有组件时更新受影响的条目。

| 契约 | 必须核对的内容 |
| --- | --- |
| API 与默认值 | 属性、默认值、尺寸、变体、事件、受控与非受控状态 |
| 结构与语义 | 实际 DOM 层级、图标、ARIA、键盘操作、焦点和弹层行为 |
| 样式 | 几何尺寸、内外边距、定位、颜色、字体、圆角、动效及「上游语义 Token → 本站 Token」映射 |
| 状态 | 默认、悬停、聚焦、展开、选中、清空、禁用、空值、长内容及适用的错误状态 |

完成条件：支持范围内每一项都有固定提交的源码依据、本站实现位置和可观察的预期；不支持的能力在对应组件文档中明确列出，不以同名 API 暗示已经实现。

## 2. 在本站复刻

在 `src/components/` 实现共享契约，静态和动态消费者共用同一套状态、样式与行为。默认保留上游的结构、几何尺寸、状态切换和事件顺序。按 [DESIGN.md](../DESIGN.md) 与 [tokens.css](../src/styles/tokens.css) 映射主题值。上游用主色前景的状态对应本站主色色阶，上游用填充背景的状态对应本站同用途的填充 Token。改变状态影响的属性也属于契约差异，例如在原本只改变背景的状态增加文字变色。出现架构、主题、无障碍或产品差异时，在组件文档记录上游表现、本站表现和原因。

调用方负责内容、上游变体与尺寸选择，以及组件之间的布局。同一变体和尺寸在不同页面应保持一致的内部结构、内边距、图标对齐和状态反馈。发现不一致时，先查共享组件和主题映射。只有差异来自调用方确实需要的布局或用法时，才在调用方处理并记录依据。

完成条件：每项契约都能指向实际代码；复刻范围内不存在未经说明的默认值、行为、DOM 语义或视觉差异。

## 3. 先验收组件，再验收页面

1. **组件验收**。复用一个能稳定复现目标变体和状态的现有页面或示例。缺少对应状态时，使用临时示例。逐项验证第 1 节的对照结果。截图用于检查可见间距、图标轮廓与状态对比，计算样式和元素边界用于核对尺寸、Token、弹层定位与覆盖来源。行为测试覆盖会改变结果的事件和状态，源码字符串断言只作辅助。
2. **页面验收**。组件表现确认后，检查接入页面中的外部间距、对齐、溢出和内容差异。覆盖受影响的中英文、桌面与手机宽度、键盘与触控，并分别检查实际使用的静态首屏和动态渲染入口。全局 CSS、浏览器默认样式或页面私有规则造成差异时，按第 2 节定位责任层。
3. **交付检查**。运行与改动相关的测试和 [AGENTS.md](../AGENTS.md) 要求的检查。在交付中写明核对的页面、状态及刻意保留的差异。

完成条件：相关检查通过；真实页面的结构、行为和计算后样式与上游契约对应；所有刻意差异已写入组件文档，未解决差异在交付时逐项说明。
