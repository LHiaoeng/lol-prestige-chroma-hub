# LoL Chroma Art 视觉规范

## 设计方向与演进

视觉基调是精品数字原画展馆：原画承担主要视觉，暗色界面衬托作品，金色标识建立品牌与操作层级。设计感优先来自构图、排版比例、对齐和空间节奏。

首页突出精选作品与站点身份，目录保持方便比较的浏览密度，详情页突出完整原画与资料，博客保证连续阅读。页面可以有不同密度，但共享品牌、字体角色和交互语言。

日常维护延续已有模式；明确要求设计升级时，可以改进版式、字号比例、留白和图片编排。品牌规则与已验证的功能契约仍适用，现有 CSS 不是不可调整的视觉目标。由 Agent 提出推荐方向并用真实内容验证，无需用户指定美学参数。

相关任务使用 `.agents/skills/frontend-design/SKILL.md`。成熟的新规则维护在本文，页面行为维护在 `docs/frontend-design.md`，避免重复建立设计规范。

## 全站一致性契约

全站风格统一是首要设计原则，优先于单页的新颖和表现力。每个页面都应让用户感到仍在同一个原画展馆中。

- 统一品牌与色彩语义、字体角色与字号层级、间距尺度、同类版心与断点规则、圆角与边框层级，以及动效节奏。
- Header、Footer、按钮、链接、标签、卡片、表单和交互状态使用共享组件或公共样式；同类元素在不同路由和中英文页面保持一致。
- 页面可按用途调整构图、内容密度和图片比例；差异应体现内容与任务，不另起一套配色、字体或控件语言。
- 单页升级在现有系统内演进。全站语言升级需在授权范围内同步更新共享规则及其消费者；暂不能迁移时保留统一基线，先提出迁移方案。
- 验收时将目标页与同类基准页比较；共享规则变更还需检查受影响页面类型的代表页，防止单页优化造成其他页面风格漂移。

## 主题色

- 名称：Chroma Gold
- CSS 变量：`--gold`
- 色值：`#d7b56d`
- 深色文字：`#121019`

Chroma Gold 是项目唯一的主题强调色。按钮、选中状态、重要标签、链接焦点和其他强调元素应优先使用 `var(--gold)`，不要在组件中重复写入十六进制色值。

## 品牌字标

品牌正式拼写为 `LoL Chroma Art`。在 Header、占位图和其他深色背景上的品牌锁定组合中，`LoL CHROMA` 使用 Chroma Gold，`ART` 使用主文字白 `#f4f0e6`。图标与字标应保持紧凑的视觉间距，作为一个整体出现，避免分散成两个独立元素。

小尺寸图标可以只显示徽标，但必须保留 `LoL Chroma Art` 的可访问名称。SEO、正文和结构化数据使用正式大小写，不沿用视觉字标的全大写形式。

占位图中的品牌组合是低对比水印，不是正式 Logo 展示位。它保留标准双色关系，但徽标使用约 `20%` 不透明度、字标使用约 `32%` 不透明度，与深色径向背景融合；不得使用 Header 的完整亮度，以免图片加载失败时抢夺页面内容层级。

`public/adsense-logo.png` 使用完整亮度的横向品牌锁定组合，导出为 PNG 或 JPG，宽高比保持 `5:1`，文件不得超过 `150 KB`。当前标准输出为 `600×120` PNG；`LoL CHROMA` 使用金色，`ART` 使用主文字白。

### 已确定用途

- 筛选区 Apply 按钮背景
- 卡片 NEW 标签背景
- 主要按钮和当前选中状态
- 重要标题、图标及交互焦点

### 使用规则

- 金色实心背景上使用 `#121019` 深色文字。
- 深色背景上可使用 `var(--gold)` 作为文字、边框或图标色。
- 大面积背景不使用主题色，避免降低原画的视觉层级。
- 发光、渐变和动画只作轻量点缀，保持简约的暗色画廊风格。

## 返回顶部

全站使用右下角悬浮的圆形返回顶部按钮。页面滚动超过 `480px` 后显示，主体使用 `var(--gold)`，图标使用 `#121019`。移动端必须适配安全区；用户启用“减少动态效果”时，禁用淡入与平滑滚动。

## Header 控件

语言切换器使用紧凑的金色描边胶囊，视觉高度约为 `32px`。组件外围保留约 `44px` 的透明点击区域，避免为追求紧凑而牺牲移动端可用性。

Header 全站共用一层玻璃：底色固定为 `color-mix(in srgb, var(--bg) 48%, transparent)`，`backdrop-filter` 为 `blur(4px) saturate(165%) brightness(.96)`。底色不随滚动变化，页面一打开就能透过 Header 看到底层图像；滚动收窄状态只额外增加外阴影与底部分隔线，不改透明度。参数要求透出底层图像的清晰轮廓而不是只剩色块，所以模糊半径保持在 5px 以内、亮度不低于 `.95`。Header 内文字统一使用 `0 1px 7px #000000d9` 阴影，保证压在浅色图上时仍可读。不支持 `backdrop-filter` 时回退到 97% 不透明的深色 Header。

## 全端首屏背景

首页和博客列表页共用 `ResponsiveHeroBackdrop` 组件。组件在桌面端加载大图、在 `767px` 及以下加载中图，并统一处理渐变遮罩、轻微漂移、鼠标视差和减少动态效果。

首屏背景从视口顶部开始：背景容器向上延伸 `var(--site-header-height)` 覆盖 Header 之后，高度取 `100svh`，内容再用等量 `padding-top` 补偿，保证正文位置不变。这样 Header 玻璃在页面初始状态就能采样到背景，观感与皮肤详情页的固定背景一致；首页 `.hero-section`、博客列表页 `.blog-hero` 用负 `margin-top` 整体上移，臻彩详情页 `.detail-background` 直接改 `inset` 与高度。改用 `100svh` 而不是 `calc(100svh - var(--site-header-height))`，仍可避免移动端浏览器栏导致的溢出。遮罩渐变使用百分比停靠点，不使用固定 `vh` 位置。博客背景仅覆盖首屏，但标题与文章列表共用内容容器，让首篇文章在首屏内开始展示并自然延续到下方深色内容区；视差交互也只在首屏内响应。

## 英雄详情

`/champions/` 是 CommunityDragon 英雄资料的静态目录壳；无参数时展示 `pbe`/`latest` 通道、启用脚本提示和加载状态，区域由页面语言决定，不在主界面暴露内部 locale 或原始请求地址。英雄详情使用独立的 `/champions/detail/?id={championId}` 页面壳。详情不承担实体 SEO，移动端仍保持清晰的状态、重试和链接触控区域。臻彩详情继续复用 `ChromaCard` 的静态目录布局，CommunityDragon 只作为可失败的炫彩所属皮肤补充。

## 皮肤详情展签

皮肤名称使用主题金色，并允许在剩余宽度内自然换行；字号保持高于背景故事但不恢复为巨幅标题。稀有度宝石与标题字号共用尺寸变量，并对齐标题首行。

皮肤名称只比背景故事高一个文字层级，避免名称再次成为大标题；背景故事占满展签正文宽度，与金色分隔线和后续区块左右对齐。

展签正文块与后续系列、炫彩和阶段区块使用同一内容宽度。稀有度宝石与名称使用同一视觉尺寸并始终保持单行；名称字号低于页面主展墙的视觉权重，超长内容在极窄视口以省略号收束，完整名称仍保留在标题文本与提示中。

皮肤基本信息采用单一“展签正文块”：稀有度宝石与皮肤名称在同一行构成身份标题，细金色分隔线之后直接呈现背景故事；英雄入口、状态关联、炫彩数量和档案编号降为故事后的次级资料行。宝石缺失时不保留空位，长名称允许自然换行；手机端资料行改为单列，名称与宝石仍保持清晰对应。

运行时不提供皮肤目录入口；皮肤详情通过独立的 `/skins/detail/?id={skinId}&champion={championId}` 页面壳在浏览器中加载，核心资料、媒体与关联关系按当前通道渐进展示。无实体静态展墙，详情失败时保留状态和可访问重试反馈。

展签徽章按页面语言选择本地化字段：英文使用 `global/default`，中文使用 `global/zh_cn`；当前本地化字段缺失时保留缺失状态，不读取另一视图补值。稀有度沿用参考项目的 `rarity` 键映射和 CommunityDragon 稀有宝石图标；没有稀有度或图标时整枚徽章不显示。`isLegacy` 只代表 Legacy/典藏内容，不能等同于真正限定皮肤；CommunityDragon 没有稳定的独立限定字段，后续如要增加“限定”徽章必须接入带来源、服区和核验日期的人工清单。

背景覆盖整个视口并延伸到 Header 之后，Header 沿用全站玻璃参数，让原画轮廓透过 Header 可见；不做页面级覆盖。
