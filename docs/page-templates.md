# 页面模板契约

新增或重做页面时，先选页面类型，再按通用骨架组装；修改现有页面布局或响应式时核对对应契约。复用现有 [BaseLayout](../src/layouts/BaseLayout.astro)、[Breadcrumb](../src/components/Breadcrumb.astro) 和组件。视觉值以 [DESIGN.md](../DESIGN.md) 与 [tokens.css](../src/styles/tokens.css) 为准。

## 通用骨架

1. `BaseLayout` 接收本语言的标题、描述、canonical、locale，以及适用的结构化数据；它负责站点 Header、`<main>`、Footer、语言切换和 [返回顶部](../src/components/BackToTop.astro)。Header 将英雄、系列、宇宙和 PBE 新增入口收在“英雄联盟”下拉中，桌面与窄屏共用同一交互。页面不重复放置返回顶部按钮。
2. 有上级的页面在 Header 下、标题前放 `Breadcrumb`。它与页面版心容器作为 `<main>` 的同级内容排列，不放进 `.runtime-page` 等已设版心或横向留白的容器，避免二次缩进；面包屑与后续第一个内容块统一间隔 `--space-3`，内容容器不再增加顶部间距。首项链接到本语言首页，中间项链接到上级，末项是当前页纯文本；文章使用 `article` 变体。首页与无确定上级的 404 页省略面包屑。
3. 页面内容使用唯一的 `h1`，下面依次放简短说明、适用的操作和主体内容；主体内容按 `h2` 分节。动态区域只负责动态结果，加载、空、错误和重试状态在此就地呈现并提供文字反馈，不改变面包屑、标题和页面版心容器的层级；CD 详情页的实体标题及面包屑末项由成功加载的实体名称填充。

## 动态资料展示结构

- **列表页共用排版**：面包屑 → 主题色领域图标与目录名称 `h1` → 共享版本切换、垂直 Divider 和结果数量 → 水平 Divider → 筛选、排序与结果卡片。列表页不显示说明文案；英雄、系列和宇宙目录使用响应式 Masonry，不分页。宇宙卡片用不可展开的 Tree 常显宇宙与所属系列关系。
- **详情页共用排版**：英雄、皮肤、皮肤系列与宇宙详情依次显示面包屑 → 主题色领域图标与实体名称 `h1` → 有内容时显示简介 → 共享版本切换行（有信息时用垂直 Divider 分隔）→ 水平 Divider → 主体内容。英雄 `h1` 显示称号与名称；英雄在版本后显示皮肤总数；皮肤系列在版本后显示所属宇宙与皮肤总数；皮肤在版本后显示所属英雄、系列与宇宙；摘要行和炫彩分节标题都显示炫彩数量（不含基础皮肤）。关联名称按数据就绪分别填充，头部已有的所属关系不在正文重复。主体按资料类型组织：英雄直接展示包含默认皮肤的皮肤列表，皮肤详情的 h1 有稀有度图标时显示该图标并用 Tooltip 显示稀有度名称，否则显示皮肤领域图标；媒体与边框预览使用版心宽度的手动轮播，媒体画面不重复显示标题，底部互斥按钮标明并切换可用内容。有动态原画时自动静音循环播放非聚焦动态原画，并提供聚焦动态原画选项；手机端将媒体选项排成两列，并将下载按钮设为 Block 满宽。其余主体展示阶段与炫彩，默认皮肤没有自身描述时显示英雄简介；系列展示皮肤，宇宙展示筛选与系列皮肤。适用的内容分节使用 `h2`；缺失的简介和摘要字段不留空占位。
- **头部信息与关联入口**：详情页由 [RuntimeDetailSummary](../src/components/RuntimeDetailSummary.astro) 统一组装摘要行并管理其专属样式，版本下拉复用 [RuntimeChannelSwitcher](../src/components/RuntimeChannelSwitcher.astro)。版本切换是操作控件；其后的所属关系与总数是当前实体的摘要信息，按“领域图标＋名称或数量”排列，并用垂直 Divider 分隔；皮肤详情摘要行还显示当前皮肤的炫彩数量（不含基础皮肤）。整行使用比默认正文大一档的 16/24px 字体规格，版本控件与分隔线继承该规格；各信息项之间以及图标与文字之间共用同一横向间距 Token，分隔线自身不叠加边距。加载时只显示一条接近文字高度的短骨架，贴齐摘要首行；数据就绪后整行替换。可跳转的所属关系使用普通行内文字链接，保留悬停与键盘焦点反馈，不套用按钮或芯片外观；无目标的数量使用纯文本。头部已有的关系不在正文重复成节，确需展开说明或展示集合时再设独立章节。
- **共用加载与显示规则**：列表与详情使用同一动态状态流程和共享版本切换组件，骨架按各自真实排版占住标题、操作与主体位置：列表卡片沿用对应目录的列宽与卡片高度，系列卡片包含标题与所属宇宙标签占位；皮肤详情媒体按轮播区域和媒体比例占位，PBE 对比页先占住版本、摘要与分类区域。加载完成后由真实内容替换，并以短暂淡入呈现；减少动态效果时取消淡入和骨架流光。失败或无效资料时移除对应占位；不让骨架与真实内容同时显示。详情页摘要行在版本、所属关系和数量所需数据仍在加载时只显示单条骨架，待这些字段全部就绪后一次性展示，不逐项露出真实内容；空结果或失败也应结束骨架，并在对应位置隐藏无数据字段或提供重试。加载状态提供文字反馈，主数据的错误显示 Alert 与重试；列表无结果显示 Empty。正文关联资料仍独立加载，只在所属区域显示占位、结果或失败重试，不重置已加载的主数据。切换资料版本时沿用同一流程。标题图标、字号、间距和 Divider 均复用共享组件与设计 Token，保持版心和内容顺序一致。
- **特有展示**：宇宙详情在简介后显示版本与领域图标数量，系列标题使用可跳转的主题色图标 `h2`，系列筛选与英雄/稀有度排序位于同级工具栏；皮肤系列详情的皮肤列表使用英雄/稀有度排序，英雄详情只提供发布顺序/稀有度排序。筛选控件在列表上方同级排列，头部数量表示当前版本的总量，不随排序改变；缺少匹配结果时显示空状态。皮肤卡片标题使用稀有度图标与名称，名称单行省略，悬停或键盘聚焦时用 Tooltip 显示完整名称与稀有度。
- **状态决定控件**：加载中以同尺寸骨架占住可用的筛选和排序位置；成功且有可操作的结果时才显示真实控件。主数据为空或失败时移除筛选与排序，直接展示 Empty 或 Alert 与重试；局部关联资料失败时只替换该区域。版本切换、重试和筛选后的空结果分别验收，不能留下已结束的骨架、旧版本数量或与当前结果无关的控件。
- **骨架与结果逐项对齐**：首次加载与切换版本复用同一骨架结构；按真实页面核对标题图标、标题与简介行高、摘要首行、Divider 宽度、筛选栏高度、卡片列宽与内容高度、媒体比例及区块间距。卡片高度由内容决定时，骨架跟随该类型的实际卡片，不用统一的大块占位；缺失字段和空结果不保留无意义高度。检查从骨架到结果的前后画面，而非只检查其中一个状态。
- **领域标识统一**：目录和详情的 `h1`、分组 `h2`、摘要及关联入口复用 [领域图标映射](../src/components/domain-icons.ts) 中相同语义的图标；图标以 `1em` 跟随文字大小并继承主题色，和文字垂直居中。名称、数量与操作各有固定语义位置，不因页面或资料版本重新定义图标、字号或间距。

## 宽度

- 列表、详情和普通页面沿用共享版心：`width: min(var(--content-width), calc(100% - (var(--page-gutter) * 2)))`，水平居中。面包屑已有相同版心，不再叠加横向留白。
- 页面默认内容容器占满共享版心，不额外缩窄，也不超过版心宽度；仅图片、专属网格、图表和浮层等有明确功能或媒体需求的元素局部限宽。
- 长文沿用 [article.css](../src/styles/article.css) 的外层版心；正文、导语、图片和表格默认使用完整版心宽度。关于页和隐私页正文同样沿用各自版心。
- 背景与原画可铺满视口，标题、正文、导航和操作仍与版心对齐。间距用现有 `--space-*`；手机边距由共享样式覆盖。

## 固定背景媒体

- 页面级背景由 [BaseLayout](../src/layouts/BaseLayout.astro) 全局加载 [backgrounds.css](../src/styles/backgrounds.css)。页面直接使用模块类，不重复导入样式，也不自行实现 `position: fixed`、视口尺寸、媒体裁切和层级。
- Header 与 Footer 由 `BaseLayout` 保留在背景之上；页面模板只放背景和页面内容，不隐藏、替换或用全屏层覆盖 Footer。
- 按页面层级选择模块类：首页使用 `page-backdrop page-backdrop--home`，并让页面建立 `isolation: isolate` 的层叠上下文、前景内容设为 `z-index: 1`；其他页面使用 `page-backdrop page-backdrop--behind`，并确保其所在页面层叠上下文隔离。详情页可额外使用 `page-backdrop--detail` 获得详情专用遮罩。背景包裹层使用 `aria-hidden="true"`，不得承载交互或唯一信息。
- 页面结构按此模式组装，背景与正文同属页面模板，但背景固定于视口：

  ```astro
  <BaseLayout title={title} description={description}>
    <div class="page-backdrop page-backdrop--behind" aria-hidden="true">
      <!-- ResponsiveHeroBackdrop 或 picture/img -->
    </div>
    <!-- 面包屑、标题和正文 -->
  </BaseLayout>
  ```

- 需要响应式取图、叠加层和已有图片回退逻辑时，在 `.page-backdrop` 内使用 [ResponsiveHeroBackdrop](../src/components/ResponsiveHeroBackdrop.astro)；详情等静态背景使用 `<picture>` / `<img>`，并给装饰图设置 `alt=""`。背景失效或不可用时，主体内容与阅读顺序保持不变。
- 固定背景不得置于带 `transform`、`filter`、`perspective` 或裁切的祖先下，以免固定定位变成局部定位或被截断；背景层不遮挡交互，Header 和前景内容保持在背景之上。
- 背景按本站断点适配：桌面（≥1024px）使用大图与宽屏遮罩；平板（768–1023px）保留大图清晰度并调整遮罩和动效；手机（≤767px）使用中图、单独调整构图和遮罩。平板与手机均关闭漂移动画，保持正文对比度并减少小屏开销。
- 背景图片以 `object-fit: cover` 填满视口；叠加渐变或遮罩，保证前景文字对比度。图片加载失败时依次尝试已配置的备用图片和占位图；都不可用时保留 `var(--bg)` 等主题纯色底，不显示破图图标。
- CD 详情页统一在共享模板中渲染固定全屏详情背景。英雄详情从该英雄的非基础皮肤中选择稀有度最高、最新的一款；系列和宇宙详情从各自的皮肤集合中选择；皮肤详情使用当前皮肤/阶段。首选非聚焦原画；该原画缺失时使用同一皮肤的聚焦原画，加载失败时再回退另一原画、缩略图和占位图；无可用原画或媒体均失败时保留主题纯色底。CommunityDragon 未提供皮肤发布日期，最新暂按皮肤 ID 倒序判断。背景只作装饰，不改变标题骨架、正文版心、Footer 或信息顺序。
- 背景视频同样只作装饰，静音、内联播放、循环播放并提供静态 `poster`；视频未能加载、播放或自动播放时显示 `poster`/备用图片，静态资源也失败时回退到主题纯色底。共享模块目前只提供视频的固定定位和铺满视口样式，使用视频的页面还须实现上述媒体回退；视频不承载唯一信息，不提供会抢占焦点的控件。
- 尊重 `prefers-reduced-motion`：减少动态效果时停止背景视频与视差/漂移动画，显示静态图片；自动播放受限、节省流量或媒体格式不支持时也采用静态兜底。

## 类型差异

| 类型 | 在通用骨架上补充 |
| --- | --- |
| 首页 | 可用视觉隐藏的 `h1`；主题区块用 `h2`，提供内容入口和主要目录。 |
| 列表 / 搜索 | 结果列表与空/失败状态；有筛选需求时提供筛选、排序和结果数量。内容高度不一时可使用 Masonry；数据量和任务需要分页时才提供分页。 |
| 详情 | 主媒体或关键资料、相关操作、补充资料；处理缺失字段和图片失败。以原画为视觉焦点时可隐藏 `h1`，但可见名称须清晰。 |
| 运行时资料（CD） | 列表与详情的排版、骨架及共用加载状态见上方“动态资料展示结构”；固定全屏背景和媒体回退见“固定背景媒体”。皮肤详情媒体使用 Carousel 与 Radio.Button 控制；媒体选择和图标下载按钮共用紧凑控制行，以垂直 Divider 分隔。本地 RadioButtonGroup 与 Button 均通过 `size` 属性控制 small/middle/large 尺寸，轮播使用 middle（默认 32px），手机端媒体选项为两列，下载按钮使用 Button 的 Block 属性铺满控制区；控件高度仍由组件尺寸控制。下载操作始终对应当前媒体。边框页默认显示合成载入图，并可切换为透明边框图。水平和垂直分割线使用共享 Divider。首次加载无原画时显示主题底色，切换版本期间保留当前背景，待新资料就绪后更新。PBE 对比页使用静态比较说明和独立 `h1`。 |
| 文章 / 长文 | 标题后放导语、日期/来源和分节正文；文章 SEO 与来源要求见 [博客文章规范](../.agents/skills/blog-article/SKILL.md)。 |
| 表单任务 | 带标签的字段、字段错误、提交反馈与主/次操作；复用现有 Input、Select。 |
| 错误页 | 原因、下一步说明和返回或重试入口；404 页设置 `noindex`。 |

## 响应式适配

- 页面先用流式宽度和弹性布局；内容拥挤或阅读受影响时才切换排列，优先复用现有 480/768/1024px 断点。面包屑、标题、正文和操作保持语义顺序。
- 组件先适应容器宽度；同一组件在不同容器内确需切换布局时使用容器查询。独立控件的触控尺寸和文字链接的间距按 [DESIGN.md](../DESIGN.md#layout) 执行；悬停只作增强。
- 首页与列表：窄屏导航、筛选、卡片和适用的分页仍可操作；Masonry 在窄屏减少列数，Tree 启用展开时控件支持触控；折叠后仍能访问全部选项，横向卡片列表的单张内容可读。
- 详情：原画完整，资料与操作可达；预览和菜单避开视口边缘与安全区。长文、表单和错误页：正文可读，宽表在自身区域滚动，字段、反馈和返回入口可达。
- 验收受影响的中英文页面：320 CSS px 无页面级横向溢出，检查断点两侧、宽屏与缩放，以及触控（含鼠标与触控混合设备）、键盘、空/错误状态和减少动效；可用时再核对不同浏览器。

交付前核对所选类型、面包屑与标题顺序、版心和适用状态；验证流程见 [前端视觉统一与治理](frontend-design.md#4-流程与协作)。
