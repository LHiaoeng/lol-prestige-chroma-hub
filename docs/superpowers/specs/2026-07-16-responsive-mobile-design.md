# Chroma Art 全响应式适配设计

## 目标

让整个站点在 320px 小屏手机到宽屏桌面之间形成连续、可用且视觉一致的响应式体验。移动端以原画沉浸感为主，桌面端兼顾浏览效率，不改变现有数据模型、路由、国际化和 SEO 行为。

## 已确认的视觉方向

- 首页手机端采用“原画沉浸”：单列大图、横向筛选入口、折叠导航。
- 详情页手机端采用“全屏海报叠层”：原画占据首屏主体，标题和关键标签叠在底部渐变区域，完整资料在下方展开。
- 桌面目录采用“三列画廊”：宽屏三列、平板两列、手机单列。
- 延续现有深色背景、金色强调、衬线标题和原画主导的品牌语言。

## 响应式架构

以内容表现而不是设备名称划分断点：

- 320–479px：小屏手机。
- 480–767px：大屏手机。
- 768–1023px：平板与窄屏窗口。
- 1024px 及以上：桌面。

全站在 `global.css` 中定义统一的容器边距、内容宽度、触控尺寸、字号缩放和安全区变量。页面组件只补充自身特有布局，避免各页面重复声明互相冲突的断点。

## 页面与组件设计

### 全局导航

桌面保持横向品牌、说明、About 和语言切换。低于 768px 时显示紧凑品牌和菜单按钮，About 与语言切换进入原生 `details` 折叠菜单。所有按钮的可触控区域至少为 44×44px，菜单支持键盘操作，并在页面点击外部时关闭。

### 首页英雄区与画廊

英雄区在手机端减少顶部留白，标题按可用宽度缩放，避免英文长词和中文内容溢出。目录从桌面三列过渡到平板两列、手机单列。手机卡片采用更宽的原画展示区域和更明显的标题层级；hover 位移仅在支持 hover 的设备启用。

### 筛选器

桌面和平板保留完整筛选表单。手机端使用原生 `details` 容器：摘要区域常驻显示“筛选与排序”，完整搜索、选择框和操作按钮在面板内纵向排列。字段允许横向内容安全收缩，操作按钮占满可用宽度。保持现有表单提交、重置和目录脚本接口不变。

### 详情页

桌面继续图文双栏。低于 768px 时，详情主图扩展到视口宽度并使用接近首屏高度的海报布局；标题、类型、英雄和版本等关键内容叠在图片底部渐变层。完整定义列表置于图片后方的独立信息面板，并使用原生 `details` 提供可访问的展开/收起行为。现有外部操作菜单保留在对应字段中，弹出列表在窄屏下限制到视口宽度。

### 其他页面与浮层

- About 与 404 页面缩短移动端留白，控制正文行长与字号。
- 图片预览对话框使用动态视口单位和安全区内边距，关闭按钮维持 44px 触控区域。
- 分页允许换行，按钮达到触控尺寸。
- 面包屑允许横向滚动或截断，不撑破页面。
- 页脚链接与正文在窄屏保持清晰行距。

## 数据流与兼容性

不修改目录 JSON、Astro 静态路由和浏览器目录筛选的数据流。新增交互优先使用原生 HTML 语义（`details`、`summary`、`dialog`），仅为关闭菜单等增强行为使用少量脚本。禁用 JavaScript 时，导航、筛选表单和详情资料仍可访问。

## 错误处理与边界

- 320px 宽度下不得产生页面级横向滚动。
- 中英文长标题、标签和操作菜单必须换行或截断在自身容器内。
- iOS 安全区、动态地址栏和软键盘不应遮挡导航、对话框关闭按钮或表单操作。
- `prefers-reduced-motion` 继续关闭非必要动画。
- 保留并兼容工作区内尚未提交的详情操作菜单相关改动。

## 测试与验收

先增加响应式结构测试，验证移动导航、可折叠筛选、详情海报/资料面板和三列画廊契约；确认测试因缺少结构而失败后再实现。完成后运行全部单元测试、类型检查和生产构建。

视觉验收覆盖 320×568、375×812、430×932、768×1024、1024×768 和 1440×900，检查首页、详情页、About、404 与图片预览。重点验证无横向溢出、44px 触控区域、内容无重叠、筛选可操作、菜单不超出视口以及中英文切换后的布局。

## 非目标

- 不重写目录数据、搜索排序逻辑或国际化系统。
- 不引入新的前端框架或运行时依赖。
- 不重新设计品牌颜色、图标或文案。
- 不改动部署与 Cloudflare 配置。
