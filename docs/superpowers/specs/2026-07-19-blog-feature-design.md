# 博客功能设计

## 目标

为 CHROMA ART 增加与现有深色、金色视觉语言一致的静态博客。Header 与 Footer 均提供博客入口；用户进入博客列表页后可打开首篇中英文图文文章。首版只包含一篇介绍《英雄联盟》的文章，但页面结构应允许后续迁移到 Markdown 内容系统。

## 路由与导航

- `/blog/`：博客列表页。
- `/blog/what-is-league-of-legends/`：首篇文章详情页。
- Header 在语言切换按钮前显示 `Blog / 博客`；Footer 在 About 与 Privacy Policy 之间显示同一入口。
- 博客入口、列表卡片与正文内链接均支持键盘操作、清晰的焦点状态和至少 44px 的移动端触控区域。

## 页面设计

### 博客列表

采用已确认的“大图精选”布局。页面包含博客 Kicker、主标题、简介，以及唯一一篇横向大幅精选文章卡片。卡片展示封面、双语标题、摘要、发布日期和预计阅读时间；整张卡片只有一个明确的文章链接目标。

桌面端以大图和宽幅排版营造杂志感；平板保持横向卡片但收紧间距；手机端改为单列上下结构，避免裁切文字与水平滚动。样式复用全局颜色、边框、字体和间距变量，不引入新的视觉系统。

### 文章详情

文章使用窄版阅读栏和衬线标题，正文穿插宽幅图片、双语图注与来源链接。内容覆盖：

1. 《英雄联盟》的游戏定位；
2. 召唤师峡谷与胜利目标；
3. 五人团队、英雄和常见位置；
4. 对线、资源、团战与团队协作；
5. 持续版本更新、世界观与电竞文化。

中英文均为完整文章，并随站点已有语言切换即时显示对应版本。禁用 JavaScript 时默认英文内容仍完整可读。

## 内容与数据边界

首版正文直接存放在 Astro 文章页面中。列表所需的 slug、标题、摘要、发布日期、阅读时间和封面信息集中到一个小型 TypeScript 常量，避免列表与详情元数据重复。首版不引入 Content Collections、MDX、分类、标签、搜索或分页。

图片只使用 Riot Games 官方公开页面提供的素材与来源链接。实现前核对官方素材 URL、使用条款和可直接展示性；不下载或提交远程图片副本。图片使用懒加载、明确尺寸和站点现有占位图降级机制，并提供中英文替代文本与图注。若无法找到稳定且适合直接引用的官方图片，则改用已有 Riot 素材路径或官方静态资源 URL，不扩大到非官方图源。

## SEO

- 博客列表页提供独立 title、description、Canonical、Open Graph 信息和 `CollectionPage` JSON-LD。
- 文章页提供独立元数据、`BlogPosting` JSON-LD、发布日期、图片、作者/发布者站点信息和面包屑。
- Sitemap 加入博客列表与文章详情两个静态 URL。
- 页面 H1、摘要和结构化数据分别提供清晰的英文搜索意图；中文正文由语言切换展示。

## 响应式与无障碍

支持 320px 手机、常见手机、平板、桌面和宽屏。布局不得产生水平溢出；标题允许安全换行；图片保持合理宽高比；正文行长限制在适合阅读的范围。交互元素具备可见焦点，图片具备有效替代文本，图注明确来源，结构使用 `article`、`header`、`nav`、`figure`、`time` 等语义元素，并遵守 `prefers-reduced-motion`。

## 错误与降级

- 图片加载失败时显示 `/placeholder.svg`，不影响正文阅读。
- 语言脚本失败时保留默认英文版本。
- 博客不依赖运行时 API、数据库或浏览器端数据请求。
- 未知博客路径沿用现有静态 404 页面。

## 测试与文档

- 静态契约测试验证 Header/Footer 博客入口、博客路由、双语内容与语义结构。

- SEO 测试验证博客元数据、结构化数据和 Sitemap URL。
- 图片测试或静态断言验证懒加载、尺寸、替代文本、图注和失败降级属性。
- 更新 README 与 `docs/frontend-design.md`，说明博客路由、首版内容来源和未来维护边界。
