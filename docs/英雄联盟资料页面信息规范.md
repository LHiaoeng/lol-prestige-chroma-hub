# 英雄联盟资料页面信息规范

> 状态：已确认，并已按当前页面实现、静态产物和运行时测试核验。

本文定义 LoL Chroma Art 借鉴国服与直营服 Skin Explorer 时，各英雄联盟资料页面展示哪些信息。本文不决定数据加载架构、路由形式、布局、交互或 SEO 策略。

参考项目：

- [国服 Skin Explorer](https://github.com/BuguoguoLoLCreator/lol-skin-explorer)
- [直营服 Skin Explorer](https://github.com/BennyExtreme00/lol-skin-explorer)

## 1. 范围边界

- 首页、臻彩详情页和博客保持现有信息范围，不因本规范增加、删除或改写内容。
- 资料范围包括英雄目录与详情、皮肤详情、皮肤系列目录与详情、皮肤宇宙目录与详情，以及独立的 PBE 新增页面。
- 不提供皮肤目录页；皮肤从英雄、皮肤系列、皮肤宇宙或 PBE 新增资料进入详情。
- 页面只展示当前本地化视图存在的事实；英文使用 `default`，简体中文使用 `zh_cn`，缺失字段不跨本地化视图或数据通道补值。`default` 和 `zh_cn` 是数据源 token，不作为服务器名称展示。
- 运行时实体详情切换资料通道时，先确认目标通道同一实体是否存在。明确缺失时，皮肤进入目标通道的所属英雄详情；英雄也缺失时进入英雄目录。英雄、皮肤系列、皮肤宇宙分别进入自身目录。目标目录也须成功加载后才跳转；网络或资料格式错误保留原详情和地址并提供重试。回退地址保留语言、明确标记目标通道和缺失原因，刷新后仍显示对应的双语提示；直接打开缺失详情链接继续显示缺失状态。
- CommunityDragon 实体使用数字 ID 识别，不根据名称或 slug 猜测身份；`skins.json` 的皮肤归属按 CommunityDragon 约定从皮肤 ID 前缀解析，并仅用于该集合的英雄关系。

## 2. 页面信息范围

| 页面 | 展示信息 |
| --- | --- |
| 英雄目录 | 英雄名称、英雄头像、英雄定位 |
| 英雄详情 | 英雄名称，以及该英雄去重后的统一皮肤资料项名称、缩略图和稀有度；中英文摘要行“更多”含 League of Legends Wiki 入口，简体中文另含布锅锅语音站和对战数据入口 |
| 皮肤系列目录 | 皮肤系列名称 |
| 皮肤系列详情 | 系列名称、所属皮肤宇宙，以及系列内皮肤的名称、缩略图和稀有度 |
| 皮肤宇宙目录 | 皮肤宇宙名称及其包含的皮肤系列名称 |
| 皮肤宇宙详情 | 皮肤宇宙名称、描述、所属皮肤系列，以及按系列归类的皮肤名称、缩略图和稀有度 |
| 皮肤详情 | 名称、稀有度、描述、所属英雄、皮肤系列、皮肤宇宙、媒体、历史版本原画、炫彩和对应第三方入口 |
| PBE 新增 | 新增实体总数和分类数量，以及新增英雄、皮肤、皮肤系列、皮肤宇宙、召唤师图标、表情、炫彩、皮肤边框、守卫皮肤和终结特效 |

目录和详情中的皮肤资料只包含参考项目实际使用的皮肤字段，不扩展到技能、出装、符文、胜率或职业比赛数据。

英雄详情中的皮肤资料默认按发布顺序展示，并提供按稀有度排序的筛选；皮肤卡片使用来源 `tilePath` 对应的正方形缩略图。
皮肤系列详情的“英雄”排序按英雄名称分组，同一英雄的皮肤按皮肤 ID 与阶段顺序展示；“稀有度”排序按稀有度降序展示。

英雄详情网格统一投影 `skins[]` 顶层皮肤与有效 `questSkinInfo.tiers[]` 阶段；顶层项按皮肤 ID 去重，阶段项按所属皮肤 ID 与阶段 ID 去重，tier ID 与顶层皮肤 ID 冲突时保留 tier 资料。系列与宇宙详情的皮肤列表沿用相同的阶段优先规则，避免同一 ID 出现两张卡片。阶段卡片以阶段 ID 和英雄 ID 进入独立皮肤详情。

## 3. 皮肤详情

皮肤详情中只有目录匹配到的臻彩卡片可切换图片，默认展示臻彩图片，切换后展示该炫彩自己的游戏原图；炫彩分节中基础皮肤卡和所有炫彩卡片图片均可预览，臻彩图片使用大图；臻彩卡片名称跳转到对应详情；其他炫彩保持游戏资料图，只可预览，不提供卡片跳转。

### 3.1 核心资料

- 皮肤名称与稀有度。
- 所属英雄、皮肤系列和皮肤宇宙。
- 皮肤描述。
- 聚焦原画、非聚焦原画、缩略图、载入图和数据源实际提供的动态原画。
- 数据源实际提供的历史版本及对应原画。
- 媒体网格只展示无边框原版素材；载入图边框统一收敛到媒体区块之后独立的「边框」模块。
- 边框模块：存在 `loadScreenVintagePath` 时直接展示官方预烘焙的带边框载入图（`_LE` JPG，无切换器）并提供成品图下载；否则按 `skinAugments.borders` 分层叠加，同层互斥边框以分段按钮切换（默认选中 priority 最高项）。每行右侧下载下拉菜单可单独下载该边框 PNG，或通过 canvas 合成当前全部已选图层并下载合成效果图 JPG。详见《皮肤边框数据源调研》。

### 3.2 多阶段皮肤

- 每个具有有效正整数 ID 的阶段在本站作为独立皮肤展示，拥有自己的名称、原画、动态原画和炫彩；详情只展示当前阶段，不列出其他阶段。CommunityDragon 仍从所属皮肤记录提供阶段数据。
- 阶段自身的名称和媒体优先；阶段缺少描述、稀有度、皮肤系列或皮肤宇宙时，继承所属皮肤在同一数据通道和本地化视图中的对应事实。
- 不跨语言或数据通道继承字段，也不为缺少有效 ID 的阶段补造身份。

### 3.3 炫彩

- 炫彩数量只统计真正的炫彩，不包含皮肤本身。
- 炫彩区域同时显示一个皮肤本体项和全部炫彩；中文可见文案使用“默认配色”，英文使用 `Base`，无障碍说明明确它不是炫彩。
- 皮肤本体项不携带炫彩颜色，不进入炫彩数量。
- 每个炫彩展示数据源提供的名称、图片和颜色；缺失字段保持缺失，不从其他本地化视图补值。
- 现有臻彩页面使用的颜色组件保持原有默认语义；非炫彩状态只服务于皮肤资料中的皮肤本体项。

### 3.4 第三方入口

英文皮肤详情（`default` 本地化视图）沿用直营服参考项目的入口：

- “Watch on SkinSpotlights”：按皮肤名称查找演示视频。
- “View 3D model on KHADA”：按当前皮肤或阶段的完整 ID 查看 3D 模型。
- “Wiki”：按所属英雄别名打开 League of Legends Wiki 英文页面。

简体中文皮肤详情（`zh_cn` 本地化视图）沿用国服参考项目的入口：

- “去语音站收听英雄语音”：通过 `https://voice.buguoguo.cn/#/voice/{英雄ID}` 按英雄 ID 查看所属英雄语音。
- “去哔哩哔哩看皮肤演示”：按中文皮肤名称查找演示视频。
- “去卡达查看3D模型”：按当前皮肤或阶段的完整 ID 链接至布锅锅 3D 模型站。
- “对战数据”：按所属英雄 ID 打开腾讯英雄详情。
- “维基百科”：按所属英雄别名打开 League of Legends Wiki 英文页面。

简体中文英雄详情的摘要行“更多”提供布锅锅语音站、对战数据和 League of Legends Wiki 入口；英文英雄详情也提供 Wiki 入口。中英文皮肤与英雄详情都按 `https://wiki.leagueoflegends.com/en-us/{英雄别名}` 生成 Wiki 链接；“对战数据”按 `https://101.qq.com/#/hero-detail?heroId={英雄ID}` 生成链接；其他第三方入口仍按本地化视图分别提供；首页、臻彩详情页和博客不加入这些入口。

## 4. PBE 新增

PBE 新增页面集中展示同一本地化视图下存在于 `pbe`、但不存在于 `latest` 的实体。页面标题与玩家文案使用“PBE 新增”，内部比较仍使用数据源 token；它不承担已有实体字段变化的展示职责。加载期间各分类先行展示骨架占位，数据到达后按分类填充。

页面展示：

- 新增实体总数，以及英雄、皮肤、皮肤系列、皮肤宇宙、召唤师图标、表情、炫彩、皮肤边框、守卫皮肤和终结特效的分类数量。
- 新增英雄：名称、头像。
- 新增皮肤：名称、缩略图、稀有度、所属英雄。
- 新增皮肤系列：系列名称。
- 新增皮肤宇宙：宇宙名称及其包含的皮肤系列。
- 新增召唤师图标（数据源 `summoner-icons.json`）：标题、图标图。
- 新增表情（数据源 `summoner-emotes.json`）：名称、表情图、关联英雄标签。
- 新增炫彩（比较两通道 `skins.json` 内的炫彩 ID 差集）：名称、图片、颜色圆点，并链接到所属皮肤详情。
- 新增皮肤边框（数据源 `skinborders.json`）：名称、边框图。
- 新增守卫皮肤（数据源 `ward-skins.json`）：名称、守卫图。
- 新增终结特效（数据源 `nexusfinishers.json`）：本地化名称、图标。

已有实体的名称、描述、稀有度或媒体变化属于通道间变化，不计入 PBE 新增；未来如需展示，应另行定义变化范围。

## 5. 实现与验收约束

- 英雄、皮肤系列、皮肤宇宙和 PBE 新增页面生成双语静态壳；英雄、皮肤、系列和宇宙实体详情初始 HTML 使用 `noindex`，运行时实体不生成逐实体静态页面。
- 只有皮肤系列详情、皮肤宇宙详情和 PBE 新增页可以按需读取完整 `skins.json`。英雄目录/详情、运行时皮肤详情、首页、臻彩详情和博客不得把完整皮肤集合作为请求依赖。
- PBE 新增固定比较同一本地化视图中的 `pbe` 与 `latest`。页面先为各分类展示骨架占位，并按分类异步请求与填充；单个分类失败时只在该分类内提示重试，不影响其他分类。分类数量随各自数据到达更新，存在失败分类时总数仅统计已加载分类并明确提示加载不完整。
- 目录壳和 PBE 新增页拥有双语 canonical、alternate 和 sitemap 条目；实体详情拥有 canonical、alternate 和 `noindex`，不进入 sitemap。
- 常规构建在禁止联网时完成；完整 CommunityDragon JSON、运行时响应和第三方媒体只在浏览器运行时使用，不复制到 `public/` 或构建产物。
- 页面验收同时检查英文 `default` 与简体中文 `zh_cn`、缺失状态、普通链接、键盘操作、窄屏布局、通道切换、失败重试、刷新与返回；第三方入口只生成当前本地化视图允许的网站集合。

## 6. 明确不在本次范围内

- 修改首页、臻彩详情页或博客的信息。
- 新增皮肤目录页。
- 展示技能、装备、符文、对局统计或电竞数据。
- 把已有实体的字段变化混入 PBE 新增。
- 为缺失数据猜测默认值、身份或跨区域回退值。
- 决定具体视觉样式、交互方式、路由或数据加载架构。

## 7. 与现有架构决策的关系

本规范记录页面信息目标；运行时边界由 [ADR-0002：将 CommunityDragon 资料移至浏览器运行时](./adr/0002-load-communitydragon-reference-at-browser-runtime.md) 约束。为满足关联皮肤与 PBE 差集，ADR-0002 已作窄范围修订：

- 只有系列详情、宇宙详情和 PBE 新增页按需读取完整 `skins.json`，其他页面继续使用轻量资料边界。
- 浏览器运行时继续使用可取消、可重试、页面内存去重和结构化错误策略，不引入构建时联网、代理、数据库或持久缓存。
